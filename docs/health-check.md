# 健康检查端点说明

## 端点 URL

- URL: `/health`
- 请求方法: `GET`
- 认证要求: 无需认证

## 功能说明

健康检查端点用于确认后端 FastAPI 服务是否正常运行。部署监控、负载均衡器或人工排查时，可以通过该端点快速判断 API 进程是否可响应请求。

该端点不执行业务写入，不返回敏感配置、数据库连接串、凭据或内部异常信息。

## 请求示例

```bash
curl -X GET http://localhost:8000/health
```

## 成功响应

状态码: `200 OK`

响应格式遵循项目统一的 `ApiResponse` 结构:

```json
{
  "data": {
    "status": "ok"
  },
  "message": "服务正常"
}
```

字段说明:

- `data.status`: 服务状态标识，`ok` 表示后端服务正在运行并能正常响应。
- `message`: 中文提示信息，用于前端或调用方展示。

## 状态码含义

| 状态码 | 含义 | 说明 |
| --- | --- | --- |
| `200` | 服务正常 | API 进程可访问，健康检查通过。 |
| `404` | 路径不存在 | 请求路径不是 `/health`，请检查 URL 是否正确。 |
| `405` | 方法不允许 | 使用了非 `GET` 请求方法。 |
| `500` | 服务内部错误 | 后端运行异常。响应体应保持结构化错误格式 `{"detail": "错误描述"}`，不泄露内部堆栈或数据库错误。 |

## 错误响应格式

当请求失败时，接口应返回 FastAPI 统一的结构化错误格式:

```json
{
  "detail": "错误描述"
}
```

调用方只应依赖 HTTP 状态码和 `detail` 字段判断错误原因，不应依赖内部异常文本。
