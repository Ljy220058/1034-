# 中文功能创意示例库

本文档为后续调度器和空闲 worker 提供可复用的中文任务创意模板。所有示例默认在共享工作区 `dir:/root/autodl-tmp/projects/hermes-swarm-lab` 执行，任务描述应直接引用该工作区，避免 worker 写入项目外路径。

使用建议：

1. 调度器从下表选择与当前项目瓶颈匹配的角色模板。
2. 将 `{模块}`、`{页面}`、`{接口}`、`{文档}`、`{风险点}` 等占位符替换为仓库中的真实文件或功能名称。
3. 每张卡只保留一个清晰目标、一个主要负责人和可验证验收标准。
4. 对需要人工审核的代码变更，worker 应先写任务评论，再以 `review-required:` 阻断等待复核。

## 模板清单

### 1. 后端：接口输入校验补强

- 标题模板：`补强 {接口} 的请求参数校验与错误提示`
- 适用负责人：后端 worker
- 执行说明：在 `dir:/root/autodl-tmp/projects/hermes-swarm-lab` 中定位 `{接口}` 对应的 FastAPI 路由、数据模型和测试文件；为缺失的必填字段、类型边界、枚举值或跨字段约束补充校验；保持错误响应结构与现有接口一致；为成功路径和至少两个失败路径补充测试。
- 验收标准：相关接口对非法输入返回明确的 4xx 响应；新增或更新测试覆盖成功与失败路径；不改变未涉及接口的返回结构；测试命令可在工作区内完成并记录结果。

### 2. 后端：数据库查询边界优化

- 标题模板：`优化 {列表接口} 的分页、排序和空结果处理`
- 适用负责人：后端 worker
- 执行说明：在工作区检查 `{列表接口}` 的 repository、路由和测试；明确默认分页大小、最大分页大小、排序字段白名单和空结果返回格式；避免直接拼接未校验排序参数；为第一页、越界页、空表和非法排序字段补充测试。
- 验收标准：列表接口在空数据时返回稳定结构；分页参数有上限；非法排序字段不会进入 SQL；相关测试通过并写明测试命令。

### 3. 后端：任务导入流程幂等化

- 标题模板：`让 {导入流程} 支持重复提交的幂等处理`
- 适用负责人：后端 worker
- 执行说明：在工作区梳理 `{导入流程}` 的入口、唯一键和写库逻辑；定义重复提交时返回已有记录、跳过重复行或更新指定字段的规则；避免同一输入生成多份任务；补充重复提交、部分重复和无效输入的测试。
- 验收标准：同一输入重复执行不会产生重复记录；幂等策略在代码注释或文档中说明；测试覆盖重复提交和部分重复场景。

### 4. 前端：表单提交状态反馈

- 标题模板：`改善 {页面} 表单提交中的 loading、成功和失败反馈`
- 适用负责人：前端 worker
- 执行说明：在工作区定位 `{页面}` 的 HTML、JS 和 API 调用；提交时禁用按钮并显示进行中状态；成功后展示可读提示并按现有页面逻辑刷新数据；失败时展示后端错误信息或兜底提示；避免重复提交产生多次请求。
- 验收标准：用户能区分提交中、成功和失败三种状态；按钮不会在请求未完成时重复触发；前端测试或手工验证步骤记录清楚。

### 5. 前端：空状态与错误状态组件化

- 标题模板：`为 {列表页面} 增加统一空状态和错误状态展示`
- 适用负责人：前端 worker
- 执行说明：在工作区检查 `{列表页面}` 的渲染逻辑；当接口返回空数组时展示下一步行动提示；当接口失败时展示错误说明和重试入口；尽量复用或抽取现有样式与工具函数，避免每个页面重复硬编码。
- 验收标准：空列表不会显示空白页面；接口失败时用户能看到重试方式；新增逻辑不破坏已有数据正常渲染；相关前端测试或验证说明完整。

### 6. 前端：移动端关键路径适配

- 标题模板：`适配 {页面} 在手机宽度下的关键操作布局`
- 适用负责人：前端 worker
- 执行说明：在工作区打开 `{页面}` 对应的静态文件和样式；针对 360px 至 430px 宽度检查导航、表格、按钮和表单；将宽表格改为卡片或可横向滚动区域；保证主要按钮无需横向滚动即可点击。
- 验收标准：手机宽度下无关键内容被遮挡；主要操作按钮可见且可点击；桌面布局不出现明显回退；记录验证视口宽度和页面路径。

### 7. 测试：核心 API 回归用例补齐

- 标题模板：`补齐 {业务流程} 的 API 回归测试`
- 适用负责人：测试 worker
- 执行说明：在工作区阅读 `{业务流程}` 涉及的路由、模型和现有测试；按真实用户顺序组织测试，例如注册、登录、创建活动、报名、签到；优先使用测试数据库和现有 fixture；避免依赖外部网络或真实生产数据。
- 验收标准：新增测试能在本地独立运行；覆盖至少一个成功主路径和两个失败边界；测试命名说明业务场景；不会让已有测试顺序相互依赖。

### 8. 测试：权限矩阵验证

- 标题模板：`为 {资源} 补充 member、leader、admin 权限矩阵测试`
- 适用负责人：测试 worker
- 执行说明：在工作区列出 `{资源}` 的读、写、更新、删除操作；为 member、leader、admin 分别构造 token 或测试用户；验证允许和拒绝的状态码；确保拒绝原因与项目当前错误格式一致。
- 验收标准：权限矩阵覆盖三类角色和主要操作；越权请求不会修改数据；测试结果能明确指出失败角色和操作。

### 9. 文档：用户操作指南补全

- 标题模板：`补全 {功能} 的中文用户操作指南`
- 适用负责人：文档 worker
- 执行说明：在工作区阅读 `{功能}` 的前端入口、API 文档和现有 `docs/user-guide.md`；用面向普通社团成员或管理员的语言说明入口、步骤、常见错误和排查顺序；示例使用脱敏手机号、示例 token 和本地地址。
- 验收标准：新增文档包含功能入口、操作步骤、失败提示解释和至少一个请求或页面示例；语言为中文；路径与当前仓库实际文件一致。

### 10. 文档：开发者接口说明更新

- 标题模板：`更新 {接口组} 的中文 API 说明与示例`
- 适用负责人：文档 worker
- 执行说明：在工作区对照 `{接口组}` 的路由实现、请求模型和测试；更新 `docs/api.md` 中的方法、路径、请求体、返回体、权限要求和常见错误；示例命令使用本地服务地址，不包含真实 token 或真实个人信息。
- 验收标准：文档中的字段名与代码一致；每个接口至少包含一个成功示例和一个常见错误说明；权限要求与测试或代码一致。

### 11. 安全：认证与令牌处理审计

- 标题模板：`审计 {认证流程} 的 token 生成、校验和过期处理`
- 适用负责人：安全 worker
- 执行说明：在工作区检查登录、鉴权依赖、配置读取和测试；确认 token 不使用硬编码弱密钥、过期时间可配置、无效 token 返回统一 401；记录发现的问题、影响范围和建议修复路径；如需修改代码，补充最小回归测试。
- 验收标准：输出中文审计记录或修复说明；明确列出已检查文件；若发现问题，给出可复现步骤；若修改代码，相关认证测试通过。

### 12. 安全：角色边界与越权风险检查

- 标题模板：`检查 {管理功能} 的角色边界和越权写入风险`
- 适用负责人：安全 worker
- 执行说明：在工作区定位 `{管理功能}` 的路由、前端入口和测试；尝试用普通成员访问管理员或团长操作；检查是否仅依赖前端隐藏按钮而缺少后端权限校验；为发现的越权路径补充测试或审计记录。
- 验收标准：每个高权限操作都有后端角色校验；普通成员越权请求返回 403 或项目约定错误；输出文件列出已验证路径和结论。

### 13. 运维：启动配置与健康检查校验

- 标题模板：`校验 {部署方式} 的环境变量、启动命令和健康检查`
- 适用负责人：运维 worker
- 执行说明：在工作区检查 README、部署配置、启动脚本和健康接口；确认必填环境变量有默认值或文档说明；为启动前置条件增加轻量校验脚本或文档；不启动长时间服务，只运行静态检查或短命令验证。
- 验收标准：部署说明列出必填环境变量和默认值；健康检查路径可从文档定位；验证命令短时间完成；不留下后台进程。

### 14. 运维：任务运行时限与重试策略验证

- 标题模板：`验证 {任务类型} 的 max_runtime、重试和阻断策略配置`
- 适用负责人：运维 worker
- 执行说明：在工作区读取 `deploy/`、`scripts/` 和相关文档；确认 `{任务类型}` 的运行时限、最大重试次数、幂等重跑条件和人工阻断条件；用现有验证脚本或新增轻量脚本检查配置文件字段完整性。
- 验收标准：配置示例能被脚本验证；文档说明何时重试、何时阻断；验证命令不依赖外部网络且短时间完成。

### 15. 评审：代码变更预合并检查

- 标题模板：`评审 {变更范围} 的可维护性、测试覆盖和回归风险`
- 适用负责人：评审 worker
- 执行说明：在工作区查看 `git diff`、相关测试和文档；重点检查是否混入无关文件、是否缺少测试、是否改变公共接口、是否存在安全或数据迁移风险；不要直接重写大段代码，优先输出阻断问题和建议。
- 验收标准：评审输出列出通过项、阻断项和建议项；每个阻断项包含文件路径、原因和建议验证方式；若无阻断项，明确说明已检查范围和仍需人工确认的残余风险。

### 16. 评审：文档质量与可执行性检查

- 标题模板：`评审 {文档} 的路径准确性、步骤完整性和示例可执行性`
- 适用负责人：评审 worker
- 执行说明：在工作区逐段检查 `{文档}` 中的命令、路径、端口、接口名和角色说明；对明显过期或无法执行的示例提出修正；确认文档没有要求 worker 写入工作区之外的位置。
- 验收标准：评审记录包含已检查章节、发现问题和建议改法；所有路径均指向当前仓库内文件或明确的本地服务地址；示例不包含真实密钥或个人隐私。

## 调度器落卡示例

下面示例展示如何把模板改写为可直接执行的任务卡：

```text
标题：补齐活动报名流程的 API 回归测试
负责人：测试 worker
工作区：dir:/root/autodl-tmp/projects/hermes-swarm-lab
说明：阅读 backend/routes/activities.py、backend/attendance.py 和现有 tests/test_api.py；为“创建活动 → 成员报名 → 重复报名失败 → 取消报名”补充 pytest 用例，复用测试数据库 fixture，不依赖外部网络。
验收：新增测试能单独运行；重复报名返回冲突状态；取消报名后报名记录消失；在任务评论记录测试命令和结果。
```

```text
标题：审计成员管理接口的角色边界
负责人：安全 worker
工作区：dir:/root/autodl-tmp/projects/hermes-swarm-lab
说明：检查 backend/routes/members.py、backend/routes/auth.py 和相关测试；验证普通成员不能修改其他成员资料或提升角色；如发现越权路径，补充失败用例或输出中文审计文档。
验收：列出已检查接口和角色；普通成员越权写入不会成功；输出路径和测试结果写入任务评论。
```
