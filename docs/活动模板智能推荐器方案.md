# 活动模板智能推荐器功能方案

## 1. 目标与定位

“活动模板智能推荐器”用于活动创建流程，帮助团长和管理员根据活动类型、预计人数、历史参与情况和成员标签快速选择合适模板，并把模板里的默认字段一键带入活动表单。

本功能不依赖第三方 API，不引入 AI 或大模型，不新增数据库表。最小版本采用“规则推荐 + 固定模板库”的方式：后端根据已有活动、报名、签到和成员资料计算输入指标，返回 2～3 张推荐结果卡片；前端在创建活动表单旁展示推荐卡片，用户点击后自动填充活动字段。

预期效果：团长创建活动时，不需要从零填写路线、距离、配速组和描述，能根据活动场景快速套用“新手晨跑”“半马备赛”“周末长距离”等模板，降低发布活动成本，并减少活动信息缺漏。

## 2. 现有能力依据

当前仓库已经具备以下基础能力：

- 活动管理：`backend/routes/activities.py`
  - `GET /api/v1/activities` 返回活动列表。
  - `GET /api/v1/activities/{activity_id}` 返回活动详情。
  - `POST /api/v1/activities` 创建活动，仅管理员和团长可用。
  - `PATCH /api/v1/activities/{activity_id}` 更新活动，仅管理员和团长可用。
- 报名与取消报名：`POST /api/v1/activities/{activity_id}/registrations`、`DELETE /api/v1/activities/{activity_id}/registrations/{member_id}`。
- 签到记录：`backend/routes/checkins.py` 已有活动签到相关接口。
- 数据模型：`Activity` 已包含 `title`、`start_time`、`location`、`route`、`distance_km`、`pace_group`、`description`，这些字段正好可由模板一键带入。
- 成员资料：`Member` 已包含 `running_years`、`pace`、`usual_distance_km`、`training_goal`，可作为推荐标签来源。
- 统计基础：`activity_participation_facts` 视图把活动、报名和签到整理成参与分析数据，可用于计算过往参与率。

## 3. 推荐输入设计

最小版本支持 4 类输入，其中前 3 类为必备输入来源。

### 3.1 活动类型

来源：前端创建活动页面的下拉框，用户手动选择。

建议选项：

- 新手入门
- 日常晨跑
- 间歇训练
- 长距离拉练
- 赛前备战
- 休闲社交

用途：决定候选模板池。例如“新手入门”优先推荐 3～5 公里、较慢配速、描述中带集合说明的模板；“长距离拉练”优先推荐 12 公里以上路线和补给提示。

### 3.2 预计人数

来源：前端创建活动页面的数字输入框，用户手动填写；可为空。

建议分段：

- `small`：1～10 人
- `medium`：11～30 人
- `large`：31 人以上

用途：影响模板的组织建议。例如大规模活动推荐更明确的集合地点、分组配速和签到说明；小规模活动推荐更轻量的描述。

### 3.3 过往参与率

来源：后端基于已有活动、报名和签到计算，不需要用户手动输入。

最小计算方式：

- 在 `activity_participation_facts` 中按活动类型关键词或距离范围匹配近 10 场活动。
- 参与率 = `signed_in_count / registered_count`。
- 若没有历史数据，返回 `null`，前端显示“暂无历史参与数据”。

用途：影响推荐理由。例如同类活动历史参与率高时，推荐理由显示“同类活动历史签到率较高，适合作为本周主活动”；参与率低时，推荐更短距离或更清晰说明的模板。

### 3.4 成员标签

来源：成员资料字段，不新增表。

可按规则从现有字段生成标签：

- `新手较多`：`running_years <= 1` 的成员占比较高。
- `半马备赛`：`training_goal` 包含“半马”“半程”。
- `全马备赛`：`training_goal` 包含“全马”“马拉松”。
- `偏好短距离`：`usual_distance_km <= 5` 的成员占比较高。
- `偏好长距离`：`usual_distance_km >= 10` 的成员占比较高。

用途：辅助排序推荐卡片。例如成员标签为“新手较多”时，即使活动类型选择“日常晨跑”，也优先推荐距离更短、配速更宽松的模板。

## 4. 推荐结果卡片字段

每张推荐卡片必须包含以下字段：

```json
{
  "template_key": "beginner-morning-run",
  "template_name": "新手友好晨跑",
  "scenario": "适合新成员较多、预计 10～20 人的周末晨跑",
  "reason": "成员资料显示短距离偏好较多，且同类活动历史签到率较稳定。",
  "default_fields": {
    "title": "周末新手友好晨跑",
    "location": "人民公园东门",
    "route": "公园环线 5 公里",
    "distance_km": 5,
    "pace_group": "6'30-7'30/km",
    "description": "适合新成员参加，集合后统一热身，按舒适配速完成。"
  },
  "badges": ["新手友好", "短距离", "低门槛"]
}
```

字段说明：

- `template_key`：模板稳定标识，便于前端点击和测试断言。
- `template_name`：用户可见模板名称。
- `scenario`：适用场景，解释该模板适合什么时候用。
- `reason`：推荐理由，必须是中文规则化文案，不使用 AI 生成。
- `default_fields`：一键带入活动创建表单的默认字段。
- `badges`：可选标签，用于前端展示“新手友好”“长距离”“备赛”等提示。

## 5. 内置模板建议

最小版本先内置 5 个模板，写在后端常量或独立模块中，不新增数据库表。

### 5.1 新手友好晨跑

- 适用：新手入门、日常晨跑、预计 10～30 人。
- 默认字段：
  - `title`：周末新手友好晨跑
  - `route`：公园环线 5 公里
  - `distance_km`：5
  - `pace_group`：6'30-7'30/km
  - `description`：适合新成员参加，集合后统一热身，按舒适配速完成。

### 5.2 日常节奏跑

- 适用：日常晨跑、成员有一定跑龄、预计 10～20 人。
- 默认字段：
  - `title`：工作日日常节奏跑
  - `route`：城市绿道 8 公里
  - `distance_km`：8
  - `pace_group`：5'30-6'10/km
  - `description`：适合有稳定跑步习惯的成员，注意按配速组出发。

### 5.3 长距离拉练

- 适用：长距离拉练、偏好长距离、预计 5～20 人。
- 默认字段：
  - `title`：周末长距离拉练
  - `route`：河岸往返 15 公里
  - `distance_km`：15
  - `pace_group`：6'00-6'40/km
  - `description`：建议自备补给，集合后说明折返点和退出路线。

### 5.4 半马备赛训练

- 适用：赛前备战、成员标签包含半马备赛。
- 默认字段：
  - `title`：半马备赛配速训练
  - `route`：操场间歇加放松跑
  - `distance_km`：10
  - `pace_group`：5'00-5'40/km
  - `description`：面向半马备赛成员，包含热身、主训练和放松跑。

### 5.5 休闲社交慢跑

- 适用：休闲社交、新成员融入、预计 20 人以上。
- 默认字段：
  - `title`：跑团休闲社交慢跑
  - `route`：公园环线 3 公里
  - `distance_km`：3
  - `pace_group`：7'00-8'00/km
  - `description`：以交流和熟悉路线为主，跑后可安排合影和自由交流。

## 6. 后端接口设计

### 6.1 新增推荐接口

```http
GET /api/v1/activities/templates/recommendations
```

权限：仅 `admin` 和 `leader` 可访问。

查询参数：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| activity_type | string | 是 | 活动类型，例如 `新手入门`、`长距离拉练` |
| expected_count | integer | 否 | 预计人数，必须大于 0 |
| tag | string | 否 | 前端显式传入的场景标签，例如 `半马备赛` |
| limit | integer | 否 | 返回数量，默认 3，最大 5 |

返回示例：

```json
{
  "data": {
    "inputs": {
      "activity_type": "新手入门",
      "expected_count": 18,
      "expected_count_bucket": "medium",
      "historical_participation_rate": 0.82,
      "matched_tags": ["新手较多", "偏好短距离"]
    },
    "recommendations": [
      {
        "template_key": "beginner-morning-run",
        "template_name": "新手友好晨跑",
        "scenario": "适合新成员较多、预计 10～30 人的周末晨跑",
        "reason": "当前预计人数适中，成员短距离偏好较明显，适合使用低门槛晨跑模板。",
        "default_fields": {
          "title": "周末新手友好晨跑",
          "location": "人民公园东门",
          "route": "公园环线 5 公里",
          "distance_km": 5,
          "pace_group": "6'30-7'30/km",
          "description": "适合新成员参加，集合后统一热身，按舒适配速完成。"
        },
        "badges": ["新手友好", "短距离", "低门槛"]
      }
    ]
  },
  "message": "成功"
}
```

### 6.2 后端最小实现范围

建议新增或修改：

- 新增 `backend/activity_templates.py`
  - 定义内置模板常量。
  - 提供 `recommend_activity_templates(activity_type, expected_count, historical_rate, member_tags, limit)`。
  - 提供 `_score_template()`，按活动类型、人数分段、历史参与率和标签打分。
- 修改 `backend/repository.py`
  - 新增 `get_activity_template_context(activity_type: str)`，返回历史参与率和成员标签。
  - 优先使用现有 `activity_participation_facts`；如果视图不存在或没有数据，优雅返回空上下文。
- 修改 `backend/routes/activities.py`
  - 增加 `GET /templates/recommendations` 路由，注意要放在 `/{activity_id}` 动态路由之前，避免路径被误判为 activity_id。
  - 调用 `admin_or_leader(current_user)` 做权限校验。
  - 参数非法时返回 422。
- 修改 `backend/models.py`
  - 可新增 `ActivityTemplateRecommendationOut` 等模型；如为降低改动，可先返回字典，但建议使用 Pydantic 模型固定结构。
- 新增 `tests/test_activity_template_recommendations.py`
  - 覆盖权限、参数校验、无历史数据、有历史数据、limit 限制、路由顺序等场景。

### 6.3 推荐排序规则

最小版本采用可解释规则打分：

1. 活动类型匹配：完全匹配 +40 分，相关类型 +20 分。
2. 预计人数匹配：落在模板建议区间 +20 分；偏离但可用 +8 分。
3. 成员标签匹配：每命中一个标签 +10 分，最多 +30 分。
4. 历史参与率：同类活动参与率 >= 0.7 时，匹配模板 +10 分；低于 0.5 时，短距离或低门槛模板 +10 分。
5. 稳定兜底：没有历史数据时，不扣分，按活动类型和预计人数排序。

推荐理由由命中的规则拼接，例如：

- “活动类型为新手入门，预计人数适中，适合使用低门槛晨跑模板。”
- “同类活动历史签到率偏低，建议选择距离更短、说明更清晰的模板。”
- “成员资料显示半马备赛目标较多，优先推荐配速训练模板。”

## 7. 前端入口设计

### 7.1 页面位置

最小版本将入口放在活动创建表单附近。若当前前端没有独立活动创建页面，可先在 `frontend/index.html` 新增“创建活动助手”区域，包含推荐输入和推荐卡片。

推荐布局：

- 左侧或上方：活动类型下拉框、预计人数输入框、场景标签输入框。
- 操作按钮：`推荐活动模板`。
- 右侧或下方：推荐结果卡片列表。
- 每张卡片按钮：`一键带入表单`。

### 7.2 交互状态

必须覆盖以下状态：

- 初始态：提示“选择活动类型和预计人数后，可获取推荐模板”。
- 加载态：按钮显示“推荐中…”，卡片区域显示加载提示。
- 成功态：展示 2～3 张推荐卡片，包含模板名称、适用场景、推荐理由和默认字段摘要。
- 空状态：后端返回空列表时显示“暂无匹配模板，可先使用基础活动表单创建”。
- 失败态：接口失败时显示“推荐模板暂时不可用，请稍后重试或手动填写活动信息”。
- 无权限态：403 时显示“只有管理员和团长可以获取活动模板推荐”。

### 7.3 一键带入字段

点击 `一键带入表单` 后，前端将 `default_fields` 写入活动表单：

- `title`
- `location`
- `route`
- `distance_km`
- `pace_group`
- `description`

如果用户已经手动填写字段，建议弹出轻量确认：

- 文案：`当前表单已有内容，是否用模板字段覆盖？`
- 操作：`覆盖`、`取消`

最小版本可只覆盖空字段，避免误删用户输入；验收时以“不会覆盖已有非空字段”为准。

### 7.4 前端 API 方法

在 `frontend/api.js` 或现有请求封装中新增：

```js
getActivityTemplateRecommendations(params, options = {}) {
  const query = new URLSearchParams();
  query.set("activity_type", params.activityType);
  if (params.expectedCount) query.set("expected_count", String(params.expectedCount));
  if (params.tag) query.set("tag", params.tag);
  if (params.limit) query.set("limit", String(params.limit));
  return request(`/activities/templates/recommendations?${query.toString()}`, {
    token: options.token,
  });
}
```

## 8. 空状态与失败态

### 8.1 后端空状态

当没有历史活动、没有成员标签或没有精确匹配模板时，后端仍返回基础推荐，不应返回 500。

推荐返回：

```json
{
  "data": {
    "inputs": {
      "activity_type": "日常晨跑",
      "expected_count": null,
      "expected_count_bucket": "unknown",
      "historical_participation_rate": null,
      "matched_tags": []
    },
    "recommendations": [基础模板列表]
  },
  "message": "成功"
}
```

### 8.2 前端空状态文案

- 初始态：`选择活动类型和预计人数后，可获取推荐模板。`
- 无结果：`暂无匹配模板，可先使用基础活动表单创建。`
- 无历史数据：`暂无历史参与数据，本次推荐基于活动类型和预计人数生成。`

### 8.3 失败态文案

- 网络错误：`推荐模板暂时不可用，请稍后重试或手动填写活动信息。`
- 无权限：`只有管理员和团长可以获取活动模板推荐。`
- 参数错误：`请先选择活动类型，并确认预计人数大于 0。`

## 9. 边界条件

1. `activity_type` 为空：返回 422，前端提示选择活动类型。
2. `expected_count <= 0`：返回 422，前端提示预计人数需大于 0。
3. `limit > 5`：后端按 5 截断或返回 422；建议截断并在测试中固定行为。
4. 没有历史数据：仍返回基础模板，推荐理由说明“基于活动类型和预计人数”。
5. `activity_participation_facts` 不存在：后端捕获数据库异常并降级为空历史上下文。
6. 成员资料为空：`matched_tags` 返回空数组，不影响推荐。
7. 普通成员访问：返回 403。
8. 推荐接口路径必须位于 `/{activity_id}` 路由之前，避免 `/templates/recommendations` 被解析为活动 ID。
9. 一键带入不应覆盖用户已填写的非空字段，除非用户明确确认覆盖。
10. 推荐卡片所有用户可见文案必须为中文。

## 11. 验收标准

1. 管理员或团长访问 `GET /api/v1/activities/templates/recommendations?activity_type=新手入门&expected_count=18` 能获得至少 1 张中文推荐卡片。
2. 普通成员访问推荐接口返回 `403 forbidden`。
3. 未传 `activity_type` 或预计人数非法时返回参数错误，不出现 500。
4. 推荐响应包含 `inputs` 和 `recommendations`，且每张卡片包含 `template_name`、`scenario`、`reason`、`default_fields`。
5. `default_fields` 至少包含 `title`、`location`、`route`、`distance_km`、`pace_group`、`description`。
6. 无历史数据时仍能返回基础推荐，并在文案中说明推荐基于活动类型和预计人数。
7. 有成员标签或历史参与率时，推荐理由能体现对应规则，例如“新手较多”“历史签到率较高”“历史签到率偏低”。
8. 前端活动创建入口能展示推荐输入、加载态、成功态、空状态和失败态。
9. 点击“一键带入表单”后，空字段能被模板默认值填充；已有非空字段不会被静默覆盖。
10. 推荐卡片和错误提示全部为中文。
11. 不新增数据库表，不依赖第三方 API，不使用 AI 或 LLM 服务。
12. 新增后端测试通过，现有活动创建、活动列表、报名、取消报名和签到测试不回退。

## 12. 不纳入本次范围

- 不做真正的机器学习推荐模型。
- 不接入 LLM 或第三方推荐服务。
- 不保存用户选择模板的历史记录。
- 不新增活动模板管理后台。
- 不新增数据库表维护模板。
- 不自动创建活动，只做推荐和字段带入。
- 不做短信、微信、邮件等外部通知。

## 13. 推荐后续拆分任务

如果进入开发，建议拆成两个 30 分钟内可完成的小任务：

1. 后端任务：为活动创建新增模板推荐接口，基于内置模板、预计人数和现有数据返回中文推荐卡片。
2. 前端任务：在活动创建区域增加模板推荐卡片，支持推荐加载、错误提示和一键带入空字段。
