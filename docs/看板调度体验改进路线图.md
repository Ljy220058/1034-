# 看板调度体验改进路线图

## 背景与范围

本文整理下一批可派发的小功能，用于改善共享工作区 `dir:/root/autodl-tmp/projects/hermes-swarm-lab` 的看板调度体验。路线图基于现有文档、测试与最近看板结果整理，重点覆盖空闲 worker 识别、重复任务去重、阻塞恢复提示、任务健康度和创意任务验收。

已参考资料包括：

- `docs/creative-task-worker-guide.md`：空闲 worker 推荐、任务板、去重与阻塞排查说明。
- `docs/创意任务验收冒烟清单.md`：创意任务每次生成两张、中文内容、负责人、固定工作区和非阻塞验收清单。
- `docs/chinese-feature-ideas.md`：中文任务模板与分派口径。
- `docs/kanban-runtime-retry.md`：运行时限、重试与阻断策略。
- `docs/创意任务合规规则评审.md`：创意任务规则缺口与测试建议。
- 最近看板结果：`t_664cac83` 已产出中文功能创意示例库，统一约定工作区为 `dir:/root/autodl-tmp/projects/hermes-swarm-lab`，并要求代码变更进入 `review-required:` 复核。

## 设计原则

1. 每个改进项都应该可以独立派发，避免一张卡同时改后端、前端、测试和文档。
2. 默认工作区固定为 `dir:/root/autodl-tmp/projects/hermes-swarm-lab`，任何示例不得写入项目外路径。
3. 先补只读诊断与稳定提示，再做会改变任务状态的自动化动作。
4. 能用测试验证的规则必须落到测试；只适合人工判断的规则必须写清验收清单。
5. 对会修改业务代码的任务，worker 完成后应在看板评论写入变更文件、测试命令和结果，再用 `review-required:` 阻塞等待复核。

## 优先级排序

### 1. 修正任务板健康度筛选返回 500 的问题

- 优先级：最高。
- 适合负责人：后端 worker。
- 预期改动文件：
  - `backend/task_board_models.py`
  - `backend/routes/workspaces.py`
  - `tests/test_task_health.py`
- 执行说明：现有 `tests/test_task_health.py` 中多条健康度筛选用例被标记为 `xfail`，原因是任务板按 `health_level` 或负责人筛选时 SQL 当前返回 500。先复现最小失败，再修复任务表与健康表的关联查询，保证未传健康等级时返回全部任务，传入健康等级时只返回匹配任务。
- 验收标准：
  - 移除相关 `xfail` 后，`python -m pytest tests/test_task_health.py -q -o 'addopts='` 通过。
  - `/api/v1/workspaces/tasks/board?workspace_path=...&health_level=at_risk` 返回 200。
  - 返回任务中保留原有字段，并额外包含可读的 `health` 信息。
- 风险：查询修复可能改变原任务板字段顺序或统计口径；需要保持旧字段兼容，避免前端和文档示例失效。

### 2. 统一空闲 worker 判定口径

- 优先级：最高。
- 适合负责人：后端 worker。
- 预期改动文件：
  - `backend/worker_recommendations.py`
  - `tests/test_idle_worker_recommendations.py`
  - `docs/creative-task-worker-guide.md`
- 执行说明：当前推荐接口会按 `RUNNING_TASK_STATUSES = {'running', 'doing'}` 排除忙碌 worker，但 `build_worker_board()` 中 `running_assignees` 为空集合，导致 worker 看板可能把忙碌 worker 误判为空闲。应抽取共用函数计算运行中负责人，并让推荐接口和 worker 看板共用同一逻辑。
- 验收标准：
  - 同一 workspace 中存在 `running` 或 `doing` 任务时，对应 assignee 不出现在 `idle_workers`。
  - `build_worker_board()` 与 `build_idle_worker_recommendations()` 对同一数据返回一致的空闲 worker 数量。
  - 文档说明 `active` 且无运行中任务才算空闲。
- 风险：已有测试或演示数据可能依赖宽松空闲判断；修复后推荐数量会下降，需要同步更新示例。

### 3. 为重复任务去重增加可解释诊断输出

- 优先级：高。
- 适合负责人：后端 worker。
- 预期改动文件：
  - `backend/kanban_helper.py`
  - `tests/test_creative_task_creation_flow.py`
  - `scripts/validate-kanban-task-dedupe.sh`
  - `docs/creative-task-worker-guide.md`
- 执行说明：现有 `dedupe_task_payloads()` 只返回可创建任务，调用方无法知道候选任务被标题、负责人、工作区还是来源规则过滤。新增只读诊断函数，例如 `explain_dedup_task_payloads(candidates, existing_tasks)`，返回每个候选项的 `accepted`、`reason`、`title_key`、`assignee_key`、`workspace_path` 和 `creation_source`。
- 验收标准：
  - 重复标题、重复负责人、不同工作区、不同来源四类场景都有测试覆盖。
  - 定时创建脚本可以在没有新任务时输出“本轮跳过：近期已存在同标题或同负责人任务”，不修改已有任务状态。
  - 文档包含误判排查步骤和示例输出。
- 风险：诊断输出包含去重签名，虽然不是秘密，但容易被误解为任务 ID；文档需说明这些只是诊断键。

### 4. 给阻塞任务生成可复制的自恢复提示

- 优先级：高。
- 适合负责人：后端 worker 或文档 worker。
- 预期改动文件：
  - `backend/task_diagnostics.py`
  - `tests/test_task_diagnostics.py`
  - `docs/creative-task-worker-guide.md`
- 执行说明：现有诊断器已能为 `blocked`、`triage` 和普通任务输出中文建议，并包含缺少上下文、测试失败、权限问题、依赖未完成等自恢复指南。下一步应让接口或文档输出更适合直接粘贴到看板评论的短提示，并确保不会自动解除阻塞。
- 验收标准：
  - 每条阻塞诊断都包含：问题摘要、建议负责人、缺失信息、下一步动作、可复制入口或命令。
  - 诊断函数保持 `non_mutating: true`，测试验证不会修改任务状态。
  - 文档给出从 `blocked` 到继续排障的人工操作顺序。
- 风险：提示过长会淹没真正错误；需要保留一行摘要和展开明细两种形态。

### 5. 建立任务健康度自动分级规则

- 优先级：高。
- 适合负责人：后端 worker。
- 预期改动文件：
  - `backend/worker_board.py`
  - `backend/task_diagnostics.py`
  - `tests/test_task_health.py`
  - `docs/kanban-runtime-retry.md`
- 执行说明：在现有 `task_health` 表基础上，定义从状态、阻塞次数、重试次数、最近失败原因和最近验收时间推导健康等级的规则。例如：无失败为 `healthy`，一次阻塞或一次重试为 `needs_attention`，多次失败或达到重试上限为 `at_risk`，等待人工输入为 `blocked`。
- 验收标准：
  - 给定不同 `blocked_count`、`retry_count`、`last_failure_reason` 时，健康等级推导稳定可预测。
  - 任务板可以按健康等级筛选，并在响应中解释分级原因。
  - 文档说明健康等级只用于排序和提醒，不应单独作为归档依据。
- 风险：自动分级可能误伤长任务或人工验收任务；需要允许 worker 或人工覆盖健康等级，并保留最后一次自动判断原因。

### 6. 创意任务创建入口统一合规校验

- 优先级：中高。
- 适合负责人：后端 worker。
- 预期改动文件：
  - `backend/kanban_helper.py`
  - `backend/task_import.py`
  - `backend/models.py`
  - `backend/routes/tasks.py`
  - `tests/test_creative_task_creation_flow.py`
  - `tests/test_task_imports.py`
- 执行说明：评审文档指出固定辅助函数、批量创建和导入入口的规则不一致。应抽取统一的创意任务校验函数，覆盖“正好两张、标题中文、描述中文、负责人非空、工作区固定、不能以 blocked 创建”等规则，并让不同入口复用。
- 验收标准：
  - 少于两张、多于两张、英文标题、英文描述、缺负责人、blocked 状态、项目外工作区都返回清晰中文错误。
  - `create_task_payloads()` 默认产物仍然正好两张，且工作区为 `dir:/root/autodl-tmp/projects/hermes-swarm-lab`。
  - 相关测试不再依赖旧的英文标题断言。
- 风险：如果把通用任务入口也强行套用创意任务规则，会影响非创意业务任务；需要通过 `creation_source`、标签或专用入口限定适用范围。

### 7. 补齐创意任务验收结果结构

- 优先级：中高。
- 适合负责人：测试 worker 或文档 worker。
- 预期改动文件：
  - `docs/创意任务验收冒烟清单.md`
  - `docs/creative-task-worker-guide.md`
  - `tests/test_creative_task_creation_flow.py`
- 执行说明：现有验收清单关注创建阶段，但对完成后的产物结构要求较弱。应明确创意任务完成时 `metadata` 或评论中至少包含：摘要、产物路径、验收结论、验证命令或人工验收记录、是否需要复核。
- 验收标准：
  - 文档给出一份标准 `metadata` 示例，不包含真实 token 或个人信息。
  - 测试或静态校验确认默认创意任务模板要求 worker 写入产物路径和验收结论。
  - 对需要人工审核的代码变更，明确要求用 `review-required:` 阻塞。
- 风险：创意任务可能只产出文本而非文件；验收结构需允许“直接写在评论中”的产物形式。

### 8. 增加调度前的任务板快照摘要

- 优先级：中。
- 适合负责人：后端 worker。
- 预期改动文件：
  - `backend/task_board_models.py`
  - `backend/worker_recommendations.py`
  - `tests/test_idle_worker_recommendations.py`
  - `docs/creative-task-worker-guide.md`
- 执行说明：在推荐分配前返回一段简短摘要，说明当前 workspace 中 todo、ready、running、blocked、done 数量，空闲 worker 数量，可执行任务数量，以及因无 worker、无任务或能力不匹配而无法推荐的数量。
- 验收标准：
  - 推荐接口响应包含 `summary` 和 `allocation_blockers`，字段为中文文档说明过的稳定名称。
  - 当 `recommendation_count` 为 0 时，响应能区分“没有空闲 worker”“没有可执行任务”“能力标签不匹配”。
  - 文档给出三类空推荐的排查顺序。
- 风险：如果摘要只基于分页数据，可能误导调度器；需要区分 `filtered_count` 与 workspace 总数。

### 9. 建立重复失败任务的重新拆分提示

- 优先级：中。
- 适合负责人：运维 worker 或后端 worker。
- 预期改动文件：
  - `docs/kanban-runtime-retry.md`
  - `backend/task_diagnostics.py`
  - `tests/test_task_diagnostics.py`
- 执行说明：当任务达到最大重试次数或多次以同一错误失败时，不应继续自动重试，而应输出“拆小任务”的建议。建议包括：保留原任务为诊断记录、创建更小的子任务、明确新负责人、说明上次失败命令和失败文件。
- 验收标准：
  - 诊断输出中对 `retry_count >= max_retries` 的任务给出拆分建议。
  - 文档包含“何时重试、何时阻断、何时拆分”的三分法。
  - 不自动创建子任务，只提供可复制的任务标题和正文草稿，避免误派发。
- 风险：自动生成的拆分建议可能过度细碎；需要保留人工确认或调度器二次筛选。

### 10. 为看板调度体验增加一键冒烟验证脚本

- 优先级：中。
- 适合负责人：测试 worker。
- 预期改动文件：
  - `scripts/validate-kanban-dispatch-experience.sh`
  - `tests/test_idle_worker_recommendations.py`
  - `tests/test_task_health.py`
  - `tests/test_task_diagnostics.py`
  - `tests/test_creative_task_creation_flow.py`
  - `docs/创意任务验收冒烟清单.md`
- 执行说明：新增一个短时间运行的冒烟脚本，只执行调度体验相关测试，不启动外部服务、不访问真实看板、不修改已有任务状态。脚本应覆盖空闲 worker 推荐、去重、阻塞诊断、健康度和创意任务创建合规。
- 验收标准：
  - 在工作区内运行 `bash scripts/validate-kanban-dispatch-experience.sh`，输出清晰的中文通过或失败摘要。
  - 脚本内部使用 `python -m pytest ... -q -o 'addopts='`，避免继承全局并发参数导致调试困难。
  - 失败时提示对应测试文件和建议负责人。
- 风险：如果脚本纳入仍处于 `xfail` 的健康度测试，会造成冒烟结果不稳定；应先完成第 1 项或在脚本中明确标注待修复范围。

## 建议派发顺序

1. 先派发第 1、2、3 项，解决健康筛选、空闲 worker 误判和去重不可解释三个会直接影响调度准确性的问题。
2. 再派发第 4、5 项，把阻塞恢复和健康度从人工经验固化为稳定诊断输出。
3. 随后派发第 6、7 项，收紧创意任务从创建到验收的合规闭环。
4. 最后派发第 8、9、10 项，补齐摘要、拆分提示和一键冒烟，降低后续维护成本。
