# 活动复盘摘要前端入口方案

## 一、目标定位
在“活动详情页”中新增一个可直接落地的“复盘摘要”入口区块，帮助用户在查看活动列表、活动详情、出勤签到之后，快速看到后端生成的活动复盘结论，并能一键定位到完整复盘内容。

本方案仅处理前端页面与交互，不修改业务接口实现，不触碰数据库与后端生成逻辑。

## 二、入口形态设计
建议在活动详情页的右侧信息区或详情主内容顶部新增一个“复盘摘要”卡片，卡片内部保持最小可落地结构：

1. 标题区：展示“复盘摘要”标题、摘要更新时间、摘要状态标签。
2. 核心摘要区：展示后端返回的摘要正文，限制在 3 到 5 行可读范围内，超出后折叠。
3. 关键结论区：用 3 到 4 个信息胶囊展示关键指标，例如参与人数、签到率、缺勤人数、异常数量。
4. 操作区：提供“展开完整复盘”“复制摘要”“刷新摘要”三个入口。
5. 状态区：加载中、空态、错误态、权限不足态统一在同一位置展示，避免布局跳动。

建议默认将“展开完整复盘”作为主按钮，放在摘要正文下方靠右位置；“刷新摘要”和“复制摘要”作为次按钮并排显示。

## 三、与现有页面的摆放关系
基于现有活动列表 / 活动详情 / 签到页面，推荐如下放置方式：

1. 活动列表页：在每个活动卡片右下角增加一个小型“复盘摘要”入口，点击后进入活动详情页的复盘锚点。
2. 活动详情页：在详情主体顶部、签到区之前插入“复盘摘要”主卡片，作为进入后最先看到的总结区域。
3. 签到页或出勤页：在出勤列表上方放置一个轻量版摘要条，仅显示一句摘要和一个“查看完整复盘”按钮。

其中，最小可落地版本只需要完成活动详情页中的主卡片与列表页的小入口即可。

## 四、后端接口配合方式
前端建议约定独立的复盘摘要接口，避免和已有活动详情、签到接口耦合。推荐返回结构如下：

```json
{
  "activity_id": 123,
  "summary_status": "ready",
  "updated_at": "2026-06-06T14:30:00+08:00",
  "permission": "member",
  "summary": "本次活动签到率较高，但中途有少量迟到与未到场情况。整体执行顺畅，建议下次提前 10 分钟开始点名。",
  "highlights": [
    { "label": "参与人数", "value": 28 },
    { "label": "签到率", "value": "92%" },
    { "label": "缺勤", "value": 2 },
    { "label": "异常", "value": 1 }
  ],
  "sections": [
    {
      "title": "执行情况",
      "items": ["签到流程顺畅", "迟到人数较少"]
    }
  ],
  "full_report_url": "/activities/123/summary"
}
```

前端渲染规则：

1. `summary_status=loading` 时显示骨架屏或 spinner。
2. `summary_status=empty` 时显示“暂无数据”，提示当前活动尚未生成复盘摘要。
3. `summary_status=error` 时显示错误文案和“重试”按钮。
4. `permission=forbidden` 时显示权限提示，不展示正文内容。
5. `summary` 为空但 `highlights` 有数据时，优先展示指标，再显示“暂无摘要正文”。
6. `sections` 存在时，以折叠列表展示，默认只展开第一组。
7. `updated_at` 必须以“更新时间”标签形式展示，并使用本地化时间格式化。

## 五、具体交互规则
建议定义以下交互：

1. 点击“展开完整复盘”后，滚动到页面中的复盘全文区域，或跳转到独立的完整复盘页面。
2. 点击“复制摘要”后，只复制 `summary` 与关键指标的纯文本，不包含 HTML。
3. 点击“刷新摘要”时，仅重新请求摘要接口，避免刷新整页活动详情。
4. 对于权限不足用户，卡片保留标题与提示，不显示敏感内容，也不显示复制按钮。
5. 摘要正文默认只显示 5 行，超出后出现“展开更多 / 收起”切换。

## 六、最小页面结构建议
活动详情页建议新增如下语义结构：

```html
<section class="activity-summary" aria-labelledby="activity-summary-title">
  <header class="activity-summary__header">
    <div>
      <h2 id="activity-summary-title">复盘摘要</h2>
      <p>来自后端的活动复盘结论与关键指标</p>
    </div>
    <span class="status-chip">已生成</span>
  </header>

  <article class="activity-summary__body">
    <p class="activity-summary__text">摘要正文……</p>
    <dl class="activity-summary__metrics">

  </footer>
</section>
```

## 七、实现步骤
1. 在活动详情页模板中插入“复盘摘要”卡片容器，优先放在详情标题下方或签到模块前。
2. 在前端新增一个独立的摘要渲染模块，只负责请求、状态切换和内容渲染，不混入活动详情主逻辑。
3. 定义加载、空、错误、权限不足四种状态的统一组件样式，确保桌面与手机一致可读。
4. 接入摘要接口后，按 `activity_id` 拉取摘要数据，并在页面首次进入时自动加载。
5. 为“展开完整复盘”“复制摘要”“刷新摘要”补齐按钮态与键盘可访问性。
6. 在 375px、768px、1280px 三个宽度分别检查摘要卡片的折行、按钮换行和卡片间距，确保没有横向滚动。
7. 若后端返回字段缺失，优先渲染已存在字段，并将缺失内容降级为“暂无数据”。
8. 若复盘摘要接口不存在或格式明显不符合约定，单独提一个 backend-dev 任务补接口，不在前端临时硬拼。

## 八、文案建议
- 标题：复盘摘要
- 副标题：来自后端的活动结论与关键指标
- 加载中：正在获取复盘摘要…
- 空态：暂无数据，当前活动尚未生成复盘摘要
- 错误态：加载失败，请稍后重试
- 权限不足：当前角色暂无查看复盘摘要权限
- 主按钮：展开完整复盘
- 次按钮：复制摘要、刷新摘要

## 九、验收标准
1. 活动详情页能直接看到“复盘摘要”入口，不需要额外跳转找入口。
2. 加载、空态、错误态、权限不足态均有清晰展示。
3. 在 375px 宽度下不出现横向滚动，按钮会自动换行。
4. 摘要正文、关键指标、按钮位置在桌面端与移动端都能清楚识别。
5. 复盘摘要接口字段定义清楚，可直接和后端对齐实施。
6. 方案文档已写入 docs/活动复盘摘要前端入口方案.md。

## 十、备注
如果后续需要把“完整复盘”拆成独立页面，建议保留当前摘要卡片作为引导入口，并复用同一套状态组件与接口字段。
