# 跑团成员活跃度分层模型

## 1. 目标与使用场景

本模型用于把跑团成员按近期参与行为分层，服务三个业务场景：

1. 首页推荐：决定成员优先看到新手友好活动、常规训练、进阶训练、带跑任务或召回活动。
2. 运营周报：统计各分层人数变化、稳定活跃基本盘、沉默/流失风险成员清单。
3. 活动召回提醒：识别潜在流失、已沉默成员，触发低门槛活动或关怀提醒。

设计原则：

- 指标结果落在 `member_activity_segments`，作为按窗口计算的快照事实表。
- 分层展示与运营动作落在 `member_activity_segment_rules`，避免把中文标签、颜色、动作建议硬编码在应用层。
- 原始事实仍来自现有 3NF 表：`members`、`activities`、`registrations`、`attendances`。
- 不反写到 `members`，避免成员主表被周期性统计字段污染。

## 2. 实体关系（脑内 ERD）

- `members` 1:N `registrations`
- `activities` 1:N `registrations`
- `members` 1:N `attendances`
- `activities` 1:N `attendances`
- `members` 1:N `member_activity_segments`
- `member_activity_segment_rules` 1:N `member_activity_segments`

`member_activity_segments.segment_code` 显式外键引用 `member_activity_segment_rules.segment_code`，保证所有分层结果都有可展示元数据。

## 3. 指标字段定义

表：`member_activity_segments`

| 字段 | 类型 | 含义 | 计算来源 |
|---|---|---|---|
| `member_id` | INTEGER | 成员 ID | `members.id` |
| `segment_code` | TEXT | 分层代码 | 计算规则输出，引用规则表 |
| `scoring_version` | TEXT | 算法版本 | 默认 `member-activity-v1` |
| `metric_start_date` | TEXT | 统计窗口开始日期 | 例如近 30 天窗口开始 |
| `metric_end_date` | TEXT | 统计窗口结束日期 | 通常为计算日 |
| `running_distance_7d_km` | REAL | 近 7 天跑量 | 已签到活动的 `activities.distance_km` 汇总 |
| `running_distance_30d_km` | REAL | 近 30 天跑量 | 已签到活动的 `activities.distance_km` 汇总 |
| `registration_count_30d` | INTEGER | 近 30 天报名次数 | `registrations.status='registered'` 且活动时间在窗口内 |
| `checkin_count_30d` | INTEGER | 近 30 天签到次数 | `attendances.status='signed_in'` 且活动时间在窗口内 |
| `activity_completion_rate` | REAL | 活动完成率 | `checkin_count_30d / registration_count_30d`，无报名时为 0 |
| `consecutive_absence_count` | INTEGER | 连续缺席次数 | 按活动时间倒序统计最近连续报名未签到/缺席次数 |
| `last_active_at` | TEXT | 最近一次活跃时间 | 最近一次签到时间优先，否则最近一次报名时间 |
| `computed_at` | TEXT | 本快照计算时间 | 计算任务写入时间 |

## 4. 分层规则 v1

规则按优先级从高到低匹配，命中即停止。优先级设计是为了避免“核心带跑者同时也是稳定活跃”等重复分类。

### 4.1 核心带跑者 `core_pacer`

条件满足任一：

- `members.role IN ('leader', 'admin')`
- 或近 30 天 `checkin_count_30d >= 8` 且 `running_distance_30d_km >= 80` 且 `activity_completion_rate >= 0.8`

展示与运营：

- 中文标签：核心带跑者
- 颜色建议：`#8B5CF6` 紫色
- 首页推荐：优先推荐带队、配速、进阶训练任务
- 运营周报：突出贡献，可列为核心志愿者/领队池
- 召回提醒：通常不需要召回，更多是荣誉和赋能

### 4.2 已沉默 `silent`

条件满足任一：

- `last_active_at IS NULL` 且入团超过 30 天
- 或最近活跃距今 `>= 30` 天
- 或近 30 天 `registration_count_30d = 0` 且 `checkin_count_30d = 0` 且入团超过 30 天

展示与运营：

- 中文标签：已沉默
- 颜色建议：`#94A3B8` 灰色
- 首页推荐：减少高强度活动推荐，推荐轻量恢复跑或社交活动
- 运营周报：统计沉默人数、沉默率、新增沉默名单
- 召回提醒：发送低门槛活动、福利、问卷或一对一关怀

### 4.3 潜在流失 `at_risk`

条件满足任一：

- 连续缺席 `consecutive_absence_count >= 2`
- 或最近活跃距今 14-29 天
- 或近 30 天有报名但 `activity_completion_rate < 0.5`

展示与运营：

- 中文标签：潜在流失
- 颜色建议：`#F59E0B` 橙色
- 首页推荐：推荐低门槛、近距离、熟人多的活动
- 运营周报：列入重点关怀名单
- 召回提醒：活动前提醒、活动后问候，了解缺席原因

### 4.4 新成员 `new_member`

条件：

- 入团天数 `<= 30`
- 且未命中核心带跑者/潜在流失/已沉默
- 且近 30 天 `checkin_count_30d < 3`

展示与运营：

- 中文标签：新成员
- 颜色建议：`#38BDF8` 天蓝色
- 首页推荐：推荐新手友好活动、新人答疑、基础配速组
- 运营周报：关注首月转化和首次签到
- 召回提醒：欢迎消息、报名后路线/装备提醒

### 4.5 稳定活跃 `stable_active`

条件：

- 近 30 天 `checkin_count_30d >= 3`
- 且 `activity_completion_rate >= 0.6`
- 且 `consecutive_absence_count < 2`
- 且未命中核心带跑者

展示与运营：

- 中文标签：稳定活跃
- 颜色建议：`#22C55E` 绿色
- 首页推荐：推荐常规训练、周期挑战、进阶活动
- 运营周报：作为健康活跃基本盘
- 召回提醒：轻触达即可，避免过度打扰

## 6. 计算伪代码

```text
function classify_member(member, metrics, today):
    days_since_join = days_between(date(member.created_at), today)
    days_since_active = null
    if metrics.last_active_at is not null:
        days_since_active = days_between(date(metrics.last_active_at), today)

    completion_rate = 0
    if metrics.registration_count_30d > 0:
        completion_rate = metrics.checkin_count_30d / metrics.registration_count_30d

    if member.role in ('leader', 'admin'):
        return 'core_pacer'

    if metrics.checkin_count_30d >= 8
       and metrics.running_distance_30d_km >= 80
       and completion_rate >= 0.8:
        return 'core_pacer'

    if metrics.last_active_at is null and days_since_join > 30:
        return 'silent'

    if days_since_active is not null and days_since_active >= 30:
        return 'silent'

    if days_since_join > 30
       and metrics.registration_count_30d == 0
       and metrics.checkin_count_30d == 0:
        return 'silent'

    if metrics.consecutive_absence_count >= 2:
        return 'at_risk'

    if days_since_active is not null and 14 <= days_since_active <= 29:
        return 'at_risk'

    if metrics.registration_count_30d > 0 and completion_rate < 0.5:
        return 'at_risk'

    if days_since_join <= 30 and metrics.checkin_count_30d < 3:
        return 'new_member'

    if metrics.checkin_count_30d >= 3
       and completion_rate >= 0.6
       and metrics.consecutive_absence_count < 2:
        return 'stable_active'

    return 'at_risk'
```

## 8. 查询与索引覆盖

高频查询模式：

1. 按成员查最新活跃分层：`member_id + computed_at DESC`
   - 覆盖索引：`idx_member_activity_segments_member_computed`
2. 首页推荐按分层取成员：`segment_code + computed_at DESC`
   - 覆盖索引：`idx_member_activity_segments_segment_computed`
3. 运营周报按统计窗口聚合：`metric_start_date + metric_end_date`
   - 覆盖索引：`idx_member_activity_segments_window`
4. 召回提醒按最近活跃时间筛选：`last_active_at`
   - 覆盖索引：`idx_member_activity_segments_last_active`
5. 前端读取启用规则并按展示顺序排序：`is_active + display_order`
   - 覆盖索引：`idx_member_activity_segment_rules_active_order`
