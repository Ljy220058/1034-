# 代码审查报告
## 严重（必须修）
- [backend/routes/workspaces.py:53-61] `_normalize_workspace_path` 只检查 `is_relative_to(PROJECT_ROOT)` / `Path.cwd()`，但没有约束到项目内白名单根目录；配合 `workspace_path` 查询参数可把任意绝对路径（例如 `/tmp` 下的敏感目录）传入后续读取逻辑，形成越权读路径面 → 建议：只允许预定义的 workspace 根目录列表，或把路径解析限制在单一项目根目录下，并在解析后校验 canonical path 前缀。
- [backend/routes/tasks.py:175-177] `batch_create_task_items` 直接把用户提交的 `workspace_path` 归一化后，只允许等于硬编码的项目根路径；这会把同一部署下的其他合法工作区全部拒绝，而且和 `read_workspace_*` 的路径策略不一致，容易造成创建/读取权限模型分裂 → 建议：统一使用同一套 workspace 解析与授权规则，不要硬编码单一路径，改为共享的 allowlist/前缀校验函数。
- [backend/routes/tasks.py:156-185] `batch_create_task_items` 接收 `raw_payload: dict[str, Any]` 并逐项落库，但没有任何认证依赖，任意未登录用户都可以批量创建任务项 → 建议：补上 `current_user: CurrentUser = Depends(get_current_user)` 并像单条创建接口一样做 `admin_or_leader` 授权检查。

## 中等（应该修）
- [backend/app.py:51-58] `HTTPException` 处理器把非字典 `detail` 统一改成 `{'detail': ...}`，但 `RequestValidationError` 返回的是另一套 `{'detail': exc.errors(), error...}` 结构，客户端需要兼容两种错误格式；前端/调用方很容易漏处理，导致错误提示丢失或解析失败 → 建议：统一所有错误响应结构，至少保证 `error.code/message/details` 在所有 4xx/5xx 响应中一致。
- [backend/app.py:61-66] 全局异常处理器把 500 的响应固定为中文 `{'detail': '服务器内部错误'}`，但完全丢弃了可观测性相关的错误码与 trace 上下文；接口可用性问题会难以定位，且和前面的 `_error_payload` 设计不一致 → 建议：在对外保持通用文案的同时，保留结构化错误码（例如 `internal_error`）并把具体异常写入日志而不是响应体。
- [backend/routes/workspaces.py:91-94] `workspace` 选择器在 `workspace_path is None` 时只要不是 `'current'` 或 `workspace:` 就直接 422，但 `workspace_path` 参数本身默认允许空字符串以外的任意文本；这种双通道解析逻辑重复且容易产生前后端参数不一致，导致同一路径有时通过、有时失败 → 建议：把 selector 规范抽成单一函数，只允许一种输入格式，前端和后端共用同一套规则。

## 建议（可以修）
- [backend/routes/tasks.py:123-146] `create_task_item` 仍然使用 `raw_payload: dict[str, Any]`，虽然最终经过 `TaskItemCreate.model_validate`，但路由层没有明确的请求模型，OpenAPI 文档与实际验证不一致 → 建议：把入参改成 `TaskItemCreate`，让 FastAPI 自动生成 schema 和 422 错误。
- [backend/routes/workspaces.py:144-151] `read_workspace_task_items` 先 `build_worker_board(..., refresh=False)` 再切片/过滤，`status` 过滤是在切片之后做的，会导致返回数量少于 `limit` 且排序受原始列表顺序影响 → 建议：先过滤再截断，或者把过滤逻辑下推到 `list_workspace_tasks`。
- [backend/routes/workspaces.py:199-222] `read_workspace_worker_summary` 使用当前工作目录作为唯一 workspace，忽略了 `workspace_path` / `workspace` 的请求上下文，和同文件其他端点的行为不一致 → 建议：补充参数或改名明确语义，避免调用方误以为能查指定 workspace。
- [backend/routes/tasks.py:203-226] `import_task_items` 将 `ValueError` 直接回传给客户端，若 `batch_import_task_metadata` 抛出的是内部实现细节字符串，可能泄露校验逻辑/路径信息 → 建议：把内部异常映射成固定的业务错误文案，并在服务端日志里保留原始异常。
