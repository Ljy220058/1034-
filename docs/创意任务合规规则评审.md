## 审查范围
- 代码变更范围：`git diff` 覆盖 `backend/app.py`、`backend/routes/tasks.py`、`backend/routes/task_imports.py`、`backend/task_import.py`、`backend/kanban_helper.py`、`backend/task_board_models.py`、`backend/routes/workspaces.py`、相关测试与中文文档。

## 已覆盖规则
- 正好两张：`backend/kanban_helper.py:30-58` 的固定辅助函数当前返回 2 个 `KanbanTaskSpec`；`tests/test_creative_task_creation_flow.py:36-43` 覆盖了 `len(payloads) == 2`。
- 标题中文：`backend/kanban_helper.py:39`、`backend/kanban_helper.py:49` 当前固定标题为中文；`tests/test_creative_task_creation_flow.py:56-65` 只检查“包含至少一个中文字符”。
- 描述中文：`backend/kanban_helper.py:41-55` 当前固定描述为中文；`tests/test_creative_task_creation_flow.py:56-65` 同样只检查“包含至少一个中文字符”。
- 负责人存在：`backend/kanban_helper.py:40`、`backend/kanban_helper.py:50` 当前固定为 `backend-dev`；`tests/test_creative_task_creation_flow.py:68-75` 只覆盖生成结果里负责人字段非空。
- 工作区正确：`backend/kanban_helper.py:18-20` 拒绝相对路径；`tests/test_creative_task_creation_flow.py:46-53` 覆盖固定工作区为 `dir:/root/autodl-tmp/projects/hermes-swarm-lab`。
- 非阻塞：未看到对“创意任务不得以 blocked 状态创建”的强制校验；当前只是在默认辅助函数里未显式设置 blocked。

## 未覆盖规则
- API 批量导入和单条创建没有强制“正好两张”。
- API 创建/导入路径没有强制标题、描述必须是中文。
- 负责人只校验非空或长度，不校验该负责人是否存在于 worker/看板配置中。
- 工作区校验在不同入口不一致：固定辅助函数只检查绝对路径，导入逻辑可接受任意绝对路径，创建路由还没有接收并传递 workspace_path。
- 非阻塞规则没有集中约束：模型和导入状态都允许 `blocked`。
- 测试里存在与中文标题要求相冲突的旧断言，可能让后续修复被错误测试阻止。

# 代码审查报告
## 严重（必须修）
- [backend/routes/tasks.py:78-85] 批量创建任务时没有传入 `workspace_path`，会落到 `backend/repository.py:645` 的 `HERMES_KANBAN_WORKSPACE` 或 `os.getcwd()` 默认值；API 调用者即使在 payload 中带了工作区也不会被使用，无法保证创意任务写入指定 `dir:/root/autodl-tmp/projects/hermes-swarm-lab`。→ 建议：给 `TaskItemCreate` 增加 `workspace_path: str = Field(...)` 或在批量 payload 顶层要求 `workspace_path`，路由调用时显式传入：`upsert_workspace_task_item(workspace_path=validated_workspace, task_key=..., ...)`，并复用 `validate_workspace_access_path()` 校验。
- [backend/routes/tasks.py:68-76] 批量创建只检查 `items` 是非空列表，没有校验“正好两张”；当前 1 张、3 张或更多都会进入创建流程，违反“正好两张”的合规要求。→ 建议：在 `_create_batch_items()` 中增加 `if len(raw_items) != 2: raise HTTPException(422, detail='创意任务必须正好两张')`，并补充 `test_创意任务批量创建_少于两张_返回中文错误`、`test_创意任务批量创建_多于两张_返回中文错误`。
- [backend/task_import.py:101-103] 导入逻辑只校验 `workspace_path` 是字符串，`backend/task_import.py:135` 随后会 `resolve()` 任意路径；没有拒绝项目外绝对路径、隐藏目录、`..` 或非目标工作区，可能把创意任务元数据标记到错误工作区。→ 建议：把 `_normalize_workspace_path()` 改为调用统一的工作区校验函数，只允许 `/root/autodl-tmp/projects/hermes-swarm-lab` 或经配置白名单的工作区；补充 `test_创意任务导入_工作区不是项目目录_返回中文错误`。

## 中等（应该修）
- [backend/models.py:163-169] `TaskItemCreate` 只约束长度，不要求标题/描述包含中文，也不要求负责人非空；通过 `/api/v1/tasks/items` 可以创建英文标题、英文描述、`assignee=None` 的任务，绕过固定辅助函数里的中文/负责人约束。→ 建议：为创意任务入口增加专用模型或 Pydantic 校验器，例如 `contains_cjk(title)`、`contains_cjk(description)`、`assignee.strip()`，错误信息使用中文；补充 `test_创意任务创建_英文标题_返回中文错误`、`test_创意任务创建_英文描述_返回中文错误`、`test_创意任务创建_缺少负责人_返回中文错误`。
- [backend/kanban_helper.py:23-56] `KanbanTaskSpec.as_kanban_args()` 当前只校验负责人非空和工作区绝对路径，没有校验标题为空、描述为空、标题/描述是否中文；`tests/test_creative_task_creation_flow.py:89-115` 只覆盖负责人为空/None/空白，缺少英文标题、英文描述、空标题和空描述的负向用例。→ 建议：在 `as_kanban_args()` 中增加 `title/body` 的非空和中文字符检查，例如 `if not _contains_cjk(self.title): raise ValueError('标题必须包含中文')`；补充 `test_创意任务创建_英文标题_返回清晰中文错误`、`test_创意任务创建_英文描述_返回清晰中文错误`。
- [backend/task_import.py:92-100] 导入入口允许状态为 `blocked`，且只校验负责人是非空字符串，没有校验负责人是否存在于 `task_queue_workers` 或允许的 worker 列表；因此可导入一张“已阻塞”或分配给不存在负责人的创意任务。→ 建议：对创意任务导入增加 `if status == 'blocked': raise ValueError('creative task must not be blocked')`，并查询 worker 表或配置白名单校验 assignee；补充 `test_创意任务导入_blocked状态_返回中文错误`、`test_创意任务导入_不存在负责人_返回中文错误`。
- [backend/routes/task_imports.py:51-70] `/api/v1/tasks/items/import` 只调用 `batch_import_task_metadata()` 并返回结果，没有写入 `workspace_task_items` 或 `workspace_tasks`；文档声称“创建中文创意任务”，但接口实际上只是内存归一化，调用成功后任务板/推荐接口看不到这些任务。→ 建议：导入成功后调用持久化函数，并用同一个事务保存两张任务；补充 `test_创意任务导入_成功后任务板可查询到两张任务`。

## 建议（可以修）
- [backend/task_board_models.py:351-356] `build_task_board_snapshot()` 的统计只基于当前分页和筛选后的 `tasks` 计算，不能反映整个工作区的任务总量；合规报告如果用它判断“是否正好两张”，会被 `limit` 或 `status/assignee/health_level` 过滤误导。→ 建议：增加不受分页影响的 `COUNT(*)` 查询，或在响应中区分 `filtered_count` 与 `total_count`；补充 `test_任务板统计_分页不影响总数`。
- [backend/kanban_helper.py:7] 目标工作区硬编码在模块常量中，测试和文档也复制同一路径；后续部署路径变化时容易出现“代码改了、测试/文档没改”的漂移。→ 建议：把默认工作区集中到配置或环境变量，并在测试中从同一常量读取；补充 `test_创意任务默认工作区_来自统一配置`。
- [backend/routes/tasks.py:50-53] `_normalize_batch_item()` 捕获所有异常并统一返回 `第N项任务数据校验失败`，调用方无法区分标题非中文、负责人缺失、状态 blocked、工作区错误等合规失败原因。→ 建议：对新增合规规则返回明确中文错误，例如 `第1项标题必须为中文`、`第2项负责人不存在`；补充 `test_创意任务批量创建_错误信息包含项序号和字段名`。

## 容易误判的边界条件
- “包含中文字符”不等于“标题/描述中文”：`中文 title with English details` 当前会通过 `tests/test_creative_task_creation_flow.py:31-34` 的检查，但实际可读性不满足全中文要求。
- `assignee='  \t  '` 与 `assignee=None` 是不同入口的边界：固定辅助函数当前都未拒绝，Pydantic 模型也允许 `None`，导入逻辑只拒绝空白字符串。
- `workspace_path` 的 `Path.resolve()` 会把不存在路径也标准化；如果不结合工作区白名单/存在性校验，错误路径会看似“合法”。
- “非阻塞”需要同时检查状态字段和健康字段：`status='todo'` 但 `health_level='blocked'` 也会让任务不可执行。
- 任务板接口的统计受 `limit`、`status`、`assignee` 影响，不能直接作为“正好两张”的全局验收依据。
