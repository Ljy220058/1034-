# 活动复盘卡片验收门禁清单

## 一、适用范围

本文档用于验收“训练完成智能复盘卡片”和训练复盘指标数据契约的后续实现，帮助前端、后端与测试 worker 在开始开发前统一质量标准。

本门禁只检查已经交付的实现或联调样例是否满足约定，不替代产品评审、代码风格审查或长期训练计划设计。检查依据包括：训练完成智能复盘卡片功能规格、训练完成智能复盘卡片数据契约、训练计划日历导出联调样例、成员成长徽章体系方案、活动复盘摘要自动生成方案、跑团活动运营周报摘要器。

## 二、门禁总原则

1. 数据字段必须可追溯，不能凭空生成没有来源的训练指标。
2. 中文文案必须面向成员本人，避免责备、恐吓或医疗判断。
3. 普通成员只能查看自己的复盘卡片，不能通过参数读取他人训练复盘。
4. 异常训练、未完成训练和空数据都必须有可解释展示，不能静默隐藏。
5. 移动端展示必须保证核心信息可读，不能只在桌面端成立。
6. 回归测试必须覆盖正常完成、异常训练、未完成训练、空状态和权限边界。

## 三、验收检查项

### 1. 数据字段完整性

通过标准：后端返回的复盘对象必须包含契约约定的关键字段：契约版本、训练标识、成员标识、计划目标、实际距离、训练用时、平均配速、完成率、完成状态、异常标签、建议文案、数据质量、生成时间。字段缺失时必须按契约给出降级值或拒绝生成，不能返回结构不完整的半成品。

失败示例：接口只返回“本次距离”和“完成度”，缺少成员标识、数据质量、异常标签和生成时间；前端仍然展示为完整复盘卡片。

建议验证方式：使用接口测试或样例 JSON 校验，断言所有必填字段存在；运行训练复盘样例校验脚本；人工抽查接口响应中空值字段是否符合降级策略。

适合跟进的 worker：backend-dev、test-engineer。

### 2. 计划目标与完成率口径一致

通过标准：完成率必须来自“实际距离 / 目标距离”的固定口径；目标距离来源必须明确标记为活动、训练模板、成员资料或兜底来源。目标距离缺失或为 0 时，完成率必须显示为暂不可用，不能显示 100%。

失败示例：成员已报名但没有有效跑步记录，接口因为有签到记录直接把完成率返回为 100%；或者目标距离为空时仍计算出完成率。

建议验证方式：构造目标距离为 10 公里、实际距离为 7 公里的样例，断言完成状态为部分完成；构造目标距离缺失样例，断言完成率为空且前端出现“完成率暂不可用”提示。

适合跟进的 worker：backend-dev、test-engineer。

### 3. 中文文案准确且克制

通过标准：卡片标题、核心指标、个人亮点、异常提醒、下次训练建议、空状态提示必须为中文，语气应鼓励、解释和提示，不得出现英文占位、技术异常堆栈或责备成员的措辞。

失败示例：前端展示“completion_rate is null”“user did not check in”；未签到提示写成“你没有完成训练”，没有给出“请确认是否缺席或现场漏签”的缓和说明。

建议验证方式：检查正常完成、配速异常、未完成训练和空状态四组截图或接口响应；搜索页面和测试快照中是否存在未翻译英文占位；人工核对异常文案是否符合成员视角。

适合跟进的 worker：frontend-dev、test-engineer、content-reviewer。

### 4. 隐私提示与权限隔离

通过标准：普通成员只能查看自己的训练复盘；接口不得接受任意 member_id 让普通成员读取他人数据；卡片不得展示手机号、密码哈希、原始定位轨迹、坐标点或他人个人复盘明细。涉及 GPS 时只展示“是否通过校验”或数据质量说明。

失败示例：普通成员把接口路径中的 member_id 改成其他成员 ID 后可以看到对方复盘；接口返回原始 GPS 坐标数组；前端卡片显示其他成员姓名和训练详情。

建议验证方式：增加权限测试，使用普通成员身份访问自己的活动复盘应成功，访问他人成员复盘应返回拒绝；安全 grep 响应样例和前端渲染，确认没有手机号、密码哈希和坐标数组。

适合跟进的 worker：backend-dev、security-reviewer、test-engineer。

### 5. 异常训练识别与降级展示

通过标准：缺失时间、异常配速、重复轨迹、超长距离、空 GPS 点、GPS 缺失、距离缺失、用时缺失等异常必须转成中文异常标签或数据质量提示；无异常时 anomaly_tags 必须为“无异常”，不能返回空数组造成前端歧义。

失败示例：跑步数据缺少 duration_seconds，接口仍然计算平均配速；异常标签返回空数组，前端误以为无异常；配速明显偏快但没有提醒恢复。

建议验证方式：构造缺失用时、空 GPS、异常配速、重复轨迹等样例；断言对应标签、数据质量 degraded 标记和降级原因都存在；检查前端异常区域是否展示黄色或中性提示而非恐吓式红色警告。

适合跟进的 worker：backend-dev、frontend-dev、test-engineer。

### 6. 未完成训练场景

通过标准：成员已报名但未签到，或签到后没有有效跑步记录时，卡片必须明确展示未完成或无法判断，并给出友好的下次训练建议。不能把报名行为、签到行为和实际训练完成混为同一个状态。

失败示例：成员报名后未到场，前端仍显示“完成本次计划”；未签到场景直接隐藏卡片，导致成员和管理员都不知道原因。

建议验证方式：准备“已报名未签到”“已签到但无跑步记录”“实际距离低于目标距离”三组测试数据；分别断言 completion_status、完成度文案、异常提醒和建议文案。

适合跟进的 worker：backend-dev、frontend-dev、test-engineer。

### 7. 移动端展示可读性

通过标准：移动端首屏应优先展示活动名、日期、本次距离、配速变化、完成度；个人亮点、异常提醒和下次训练建议在窄屏下不被截断，不依赖横向滚动才能读完。空状态和异常提示在手机宽度下仍清晰可见。

失败示例：复盘卡片在手机宽度下三列指标挤压重叠；长中文建议被截断且没有换行；异常提醒只靠颜色区分，没有文字说明。

建议验证方式：用移动端视口或截图测试检查 375 像素宽度展示；人工核对长文案换行；为异常提示增加文本断言，避免只依赖颜色。

适合跟进的 worker：frontend-dev、test-engineer。

### 8. 空状态可解释

通过标准：当活动距离、签到状态、运动用时或导入数据不足时，卡片不能崩溃，也不能伪造完整复盘；应展示“暂无足够数据生成完整复盘”一类中文说明，并提示需要补齐哪些数据。

失败示例：接口返回空对象导致前端白屏；前端显示“NaN 公里”“undefined 秒/公里”；数据不足时仍给出具体训练建议。

建议验证方式：构造活动存在但距离为空、成员无常用配速、没有跑步导入数据、生成时间缺失等样例；断言前端出现空状态文案且控制台无错误。

适合跟进的 worker：frontend-dev、backend-dev、test-engineer。

### 9. 回归测试覆盖范围

通过标准：自动化测试至少覆盖正常完成、配速异常、训练未完成、目标缺失、GPS 缺失、权限拒绝、移动端空状态或快照检查。测试应能在本仓库标准命令下运行，并且不能以永久跳过代替真实验收。

失败示例：只添加正常完成测试，没有异常和权限测试；测试文件全部标记为跳过；测试断言只检查 HTTP 状态码，不检查中文文案和关键字段。

建议验证方式：运行 pytest；查看新增或相关测试文件，确认断言包含字段结构、中文文案、异常标签和权限边界；检查跳过测试是否有明确临时原因和后续任务。

适合跟进的 worker：test-engineer、backend-dev、frontend-dev。

### 10. 与徽章、活动复盘和运营周报边界清晰

通过标准：训练复盘卡片面向成员个人单次训练；成员成长徽章面向长期荣誉；活动复盘摘要和运营周报面向管理员聚合视角。实现中不得把管理员周报字段、他人复盘明细或长期徽章状态塞进个人训练卡片。

失败示例：个人复盘卡片展示全活动缺席名单；把徽章等级作为训练完成状态；把运营周报中的活跃成员排行榜展示给普通成员。

建议验证方式：检查接口返回结构和前端页面，确认个人卡片只包含当前成员与当前训练相关字段；管理员聚合信息必须放在独立入口并有权限控制。

适合跟进的 worker：backend-dev、frontend-dev、product-reviewer。

### 11. 数据来源和日志安全

通过标准：复盘指标只能来自成员、活动、报名、签到、跑步数据导入或明确的训练模板字段；日志和错误响应不得输出密码、密钥、完整请求体中的敏感信息或原始定位轨迹。

失败示例：后端为了调试把完整导入文件内容、GPS 坐标或用户认证信息写入日志；错误响应直接返回数据库异常和堆栈。

建议验证方式：安全 grep 检查代码和样例中是否出现硬编码 password、api_key、token；运行异常场景测试，确认错误响应为结构化中文或安全英文 detail，不泄露内部堆栈。

适合跟进的 worker：security-reviewer、backend-dev、test-engineer。

### 12. 可复制的 kanban 验收摘要

通过标准：交付任务完成时必须在 kanban 评论中提供可复制摘要，说明制品路径、测试命令、通过数量、已知降级和需要后续 worker 处理的事项。摘要应足够短，方便 QA Gate 复核。

失败示例：任务只写“完成了”，没有制品路径、测试结果和风险说明；QA 无法判断是否真的满足数据契约。

建议验证方式：检查任务完成评论或 handoff metadata，确认包含制品路径、测试命令、测试结果、风险点和后续负责人。

适合跟进的 worker：所有实现 worker、quality-gate。

## 四、推荐回归测试矩阵

| 场景 | 关键断言 | 主要负责人 |
|---|---|---|
| 正常完成训练 | 完成率正确、无异常、建议文案为中文 | backend-dev、test-engineer |
| 配速异常 | 异常标签存在、恢复建议存在、不做医疗判断 | backend-dev、frontend-dev、test-engineer |
| 训练未完成 | 状态不是 completed，文案提示缺席或漏签确认 | backend-dev、frontend-dev |
| 目标距离缺失 | completion_rate 为空，展示“完成率暂不可用” | backend-dev、frontend-dev |
| GPS 缺失 | 数据质量 degraded，展示 GPS 缺失提示但不展示坐标 | backend-dev、security-reviewer |
| 普通成员越权 | 访问他人复盘被拒绝 | backend-dev、security-reviewer、test-engineer |
| 移动端窄屏 | 核心指标不重叠，长中文可换行 | frontend-dev、test-engineer |
| 空状态 | 不出现 NaN、undefined 或白屏 | frontend-dev、test-engineer |

## 五、可复制到 kanban 评论的门禁摘要

```text
活动复盘卡片 QA 门禁摘要：
1. 数据契约：必须返回契约版本、训练标识、成员标识、计划目标、实际距离、用时、配速、完成率、完成状态、异常标签、建议文案、数据质量和生成时间。
2. 中文文案：正常完成、异常训练、未完成训练、空状态均需中文展示，不得出现 undefined、NaN、英文占位或责备式提示。
3. 隐私权限：普通成员只能看自己的复盘；不得返回手机号、密码哈希、原始 GPS 坐标或他人复盘明细。
4. 异常与空态：GPS 缺失、用时缺失、距离缺失、异常配速、重复轨迹、未完成训练必须有中文标签或降级原因。
5. 移动端：375 像素宽度下核心指标、异常提醒和下次建议必须可读，不依赖横向滚动。
6. 回归测试：至少覆盖正常完成、配速异常、训练未完成、目标缺失、GPS 缺失、权限拒绝和空状态。
7. 边界清晰：个人训练复盘不得混入徽章排行、管理员周报或全活动缺席名单。
8. 交付说明：完成任务时必须附制品路径、测试命令、测试结果和后续风险点。
```

## 六、QA Gate 判定口径

全部检查项满足时，QA Gate 可判定通过。若任一关键项失败，应创建具体修复任务并指派给对应 worker：数据结构或权限问题指派 backend-dev；展示、移动端或中文文案问题指派 frontend-dev；覆盖不足或断言缺失指派 test-engineer；敏感信息或越权问题指派 security-reviewer。
