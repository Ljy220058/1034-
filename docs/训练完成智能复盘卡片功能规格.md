# 训练完成智能复盘卡片功能规格

日期：2026-06-06
状态：产品创意规格
适用对象：1034 跑团管理系统成员端、活动详情页、训练计划后续实现

## 一、创意概述

在成员完成一次跑团活动或训练后，系统在活动详情页和个人记录入口展示一张“训练完成智能复盘卡片”。卡片用现有成员、活动、报名、签到、跑步数据导入和训练模板字段，汇总本次距离、配速变化、完成度、个人亮点、异常提醒和下次训练建议，帮助成员快速理解这次训练表现。

本功能不依赖第三方服务，不引入大模型或外部智能接口。所谓“智能”仅指后端基于固定规则、已有字段和异常预检结果生成可解释的中文提示。

## 二、用户价值

1. 成员不需要在活动、签到、导入记录和统计页面之间来回切换，就能看到单次训练结果。
2. 团长可以用统一口径解释“已报名、已签到、已完成训练”的差异，减少争议。
3. 测试和后续开发可以基于明确字段、样例数据和隐私边界拆分任务。

## 三、MVP 范围

### 3.1 展示位置

MVP 只建议新增两个入口：

1. 成员端活动详情页：当成员已报名或已签到时，在活动基础信息下方展示个人复盘卡片。
2. 个人训练记录列表：最近一次活动或训练后展示卡片摘要，点击后进入活动详情页查看完整内容。

### 3.2 卡片字段

卡片必须展示以下中文字段：

| 字段 | 展示文案 | 说明 |
|---|---|---|
| 本次距离 | 本次距离：10.24 公里 | 来自跑步数据导入、GPS 轨迹摘要或活动距离兜底 |
| 配速变化 | 配速变化：比目标慢 6 秒/公里 | 对比目标配速或成员常用配速；无法比较时显示“暂无可比目标” |
| 完成度 | 完成度：102% | 实际距离 / 目标距离；目标缺失时显示“暂不可用” |
| 个人亮点 | 个人亮点：稳定完成计划距离 | 使用规则模板生成，不做夸张评价 |
| 异常提醒 | 异常提醒：无异常 | 来自异常预检标签和数据质量降级结果 |
| 下次训练建议 | 下次训练建议：保持当前配速并注意拉伸 | 使用固定中文模板，避免医疗判断 |

### 3.3 状态规则

| 状态 | 判定口径 | 前端展示重点 |
|---|---|---|
| 正常完成 | 完成率大于等于 100%，且无阻断异常 | 绿色或中性色完成标识、个人亮点、保持建议 |
| 部分完成 | 完成率大于 0 且小于 100% | 展示完成百分比和温和建议，不责备成员 |
| 未完成 | 已报名但未签到，或签到后无有效跑步记录 | 展示“暂未记录到有效训练”，提示确认缺席、漏签或补录 |
| 无法判断 | 目标距离或实际距离缺失 | 展示空状态和需要补齐的数据，不伪造完成率 |
| 配速异常 | 异常预检命中“异常配速”或配速明显偏离目标 | 展示异常提醒和恢复建议，不做医疗结论 |

### 3.4 MVP 不新增内容

1. 不新增第三方运动平台 OAuth 授权。
2. 不新增 LLM、AI 文案生成或外部推荐服务。
3. 不展示原始 GPS 坐标、完整轨迹点或其他成员的复盘明细。
4. 不新增徽章、排行、运营周报或训练计划自动排程功能。
5. 不强制新增数据库表；MVP 可先由后端按请求实时计算 DTO。

## 四、非目标

1. 不把复盘卡片做成管理员全员成绩榜。
2. 不替代现有数据统计页面，统计页仍负责聚合跑量和活动参与趋势。
3. 不做医疗、伤病、疲劳恢复诊断。
4. 不承诺预测下一次成绩，只给基于当前训练结果的保守建议。
5. 不处理跨平台导入授权流程，只消费已有跑步数据导入预览或后续落库结果。

## 五、前端展示草图文字说明

### 5.1 正常卡片结构

```text
┌──────────────────────────────┐
│ 训练复盘｜周三 10 公里节奏跑        │
│ 2026-06-06 18:30｜奥体公园         │
├──────────────────────────────┤
│ 本次距离        配速变化       完成度 │
│ 10.24 公里     慢 6 秒/公里    102%  │
├──────────────────────────────┤
│ 个人亮点                         │
│ 稳定完成计划距离，后半程配速波动较小。 │
│                                │
│ 异常提醒                         │
│ 无异常。                          │
│                                │
│ 下次训练建议                       │
│ 下次可继续保持 6 分 05 秒左右配速， │
│ 训练后注意拉伸和补水。              │
└──────────────────────────────┘
```

### 5.2 移动端展示要求

1. 375 像素宽度下优先展示活动名、本次距离、配速变化、完成度。
2. 三个核心指标可以纵向堆叠，不能靠横向滚动阅读。
3. 长中文建议必须自动换行，不截断为省略号。
4. 异常提醒必须有文字，不只依赖颜色。

### 5.3 空状态展示

```text
暂无足够数据生成完整复盘
需要补齐：目标距离、实际距离或训练用时。
如果你已经完成训练，可以联系团长确认是否漏签或补录跑步数据。
```

## 六、后端数据来源

| 展示字段 | 优先数据来源 | 兜底来源 | 缺失处理 |
|---|---|---|---|
| 活动名称与时间 | activities.title、activities.start_time | 跑步导入记录标题和时间 | 缺失时不生成完整卡片 |
| 本次距离 | 跑步数据导入 distance_km 或 GPS 摘要 | activities.distance_km | 都缺失时显示“暂不可用” |
| 目标距离 | activities.distance_km | 训练模板距离、members.usual_distance_km | 缺失时 completion_rate 为 null |
| 训练用时 | 跑步数据导入 duration_seconds | 手工补录用时 | 缺失时 average_pace 为 null |
| 平均配速 | duration_seconds / actual_distance_km | 导入文件 pace | 缺失时显示“配速暂不可用” |
| 配速变化 | 平均配速对比活动 pace_group 或成员 pace | 训练模板目标配速 | 无目标时显示“暂无可比目标” |
| 完成度 | actual_distance_km / target_distance_km | 无 | 无目标或实际距离时为 null |
| 异常提醒 | running_data_anomaly_precheck 标签 | data_quality 降级原因 | 无异常时返回“无异常” |
| 下次训练建议 | 后端规则模板 | 默认保守文案 | 不返回空字符串 |

建议后端返回对象继续沿用 `training_review_card.v1` 数据契约，前端负责把英文枚举转成中文状态，不直接展示技术字段名。

## 七、中文文案规则

### 7.1 个人亮点规则

1. 完成率大于等于 100% 且无异常：
   “稳定完成计划距离，本次训练节奏较完整。”
2. 完成率在 80% 到 99%：
   “已完成大部分计划距离，训练记录有效。”
3. 配速比目标快且无异常：
   “本次配速有提升，请继续关注体感和恢复。”
4. GPS 缺失但距离有效：
   “本次距离已记录，但缺少轨迹用于路线复盘。”
5. 未完成训练：
   “暂未记录到完整训练结果，可确认是否缺席、漏签或需要补录。”

### 7.2 异常提醒规则

1. 无异常：展示“无异常”。
2. 异常配速：展示“配速明显偏离目标，请结合现场情况确认是否为记录误差。”
3. 缺失时间：展示“缺少训练用时，暂无法计算平均配速。”
4. GPS 缺失：展示“缺少 GPS 轨迹，卡片不会展示路线细节。”
5. 重复轨迹：展示“可能存在重复记录，请确认是否重复导入。”
6. 未完成训练：展示“暂未记录到有效完成数据。”

### 7.3 下次训练建议规则

1. 正常完成：建议保持当前训练强度，不增加过大负荷。
2. 配速异常：建议先确认数据准确性，再根据体感恢复。
3. 未完成：建议从较短距离或分段目标恢复，不责备成员。
4. 目标缺失：建议补齐活动目标距离或成员常用配速。
5. 数据不完整：建议补录距离、用时或签到信息。

所有建议必须是训练管理建议，不包含诊断、治疗、用药等医疗内容。

## 九、隐私注意点

1. 普通成员只能查看自己的复盘卡片，不能通过修改 member_id 查看他人复盘。
2. 卡片不展示手机号、密码哈希、原始 GPS 坐标、完整轨迹点和其他成员个人表现。
3. GPS 相关信息只展示“可用、缺失、为空、无需、未知”等质量状态。
4. 后端日志不得输出完整导入文件、原始轨迹、认证信息或包含敏感字段的完整请求体。
5. 管理员如需查看聚合复盘，应另建管理员视角页面，不能复用成员个人卡片接口泄露个人明细。

## 十、可拆分后续任务建议

1. frontend-dev：为活动详情页添加训练复盘卡片静态组件，支持正常、异常、未完成和空状态四类样例。
2. backend-dev：新增只读复盘 DTO 生成函数，按 `training_review_card.v1` 契约从成员、活动、签到和导入数据计算字段。
3. test-engineer：补充复盘卡片契约与中文文案回归测试，覆盖正常完成、配速异常、训练未完成、目标缺失和 GPS 缺失。

## 十一、验收标准

1. 页面字段均为中文，不出现 `undefined`、`NaN`、英文占位或技术堆栈。
2. 正常完成、配速异常、训练未完成三类核心样例均可展示。
3. 无目标距离、无实际距离或无用时时，完成度和配速必须降级为“暂不可用”。
4. 普通成员不能读取他人复盘，接口不返回原始 GPS 坐标。
5. 移动端 375 像素宽度下核心指标、异常提醒和下次建议可读。
6. MVP 不新增第三方 API、不接入大模型、不强制新增数据库表。
