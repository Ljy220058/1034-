# 深圳技术大学风格活动瀑布流界面规范清单

## 概述
本清单用于约束“深技大风格活动瀑布流”的前端实现，确保页面在颜色、卡片、按钮、状态和活动信息层级上保持一致。

适用文件：

- `/root/autodl-tmp/projects/hermes-swarm-lab/frontend/index.html`
- `/root/autodl-tmp/projects/hermes-swarm-lab/frontend/activity-waterfall.js`
- `/root/autodl-tmp/projects/hermes-swarm-lab/index.html`
- `/root/autodl-tmp/projects/hermes-swarm-lab/statistics.html`

前端开发时优先以 `frontend/index.html` 和 `frontend/activity-waterfall.js` 为准。
该页面已包含深色背景、科技蓝、活力绿、活动卡片、筛选栏、加载态、空状态和错误态。

## 快速开始

在项目根目录打开活动瀑布流页面：

```bash
cd /root/autodl-tmp/projects/hermes-swarm-lab
python3 -m http.server 8080
```

然后在浏览器访问：

```text
http://127.0.0.1:8080/frontend/index.html
```

如果本地没有 `python3`，可直接用浏览器打开：

```text
/root/autodl-tmp/projects/hermes-swarm-lab/frontend/index.html
```

当前规范来自现有前端文件，不是另起一套新设计。
已核对的实现包括：

|------|------------|------------|

## 色彩规范

### 主色

主色用于品牌标识、主按钮、焦点态、选中态和高亮信息。

| 变量 | 色值 | 用途 |
|------|------|------|
| `--brand` | `#38bdf8` | 科技蓝，用于主按钮、链接高亮、加载圆环 |
| `--brand-2` | `#22c55e` | 活力绿，用于渐变按钮、校园运动感辅助色 |
| `--brand-ink` | `#bdeaff` | 深色背景上的蓝色文字 |
| `--green-ink` | `#baf7d0` | 深色背景上的绿色文字 |

使用示例：

```css
.btn-primary,
.activity-action--primary {
  background: linear-gradient(135deg, var(--brand), var(--brand-2));
  color: var(--ink);
}
```

### 辅助色

辅助色用于提示、危险、成功和弱信息。

| 变量 | 色值 | 用途 |
|------|------|------|
| `--accent` | `#f59e0b` | 提醒、待处理、运营提示 |
| `--danger` | `#fb7185` | 网络错误、危险状态 |
| `--success` | `#8ff0bb` | 成功反馈、已点赞状态 |
| `--muted` | `#9fb2ca` | 描述文字、次级信息 |
| `--line` | `rgba(148, 163, 184, 0.18)` | 默认边框 |
| `--line-strong` | `rgba(148, 163, 184, 0.28)` | 强边框、虚线空状态 |

### 背景色

页面必须保持深色科技风，不建议改成浅色主题。

| 变量 | 色值 | 用途 |
|------|------|------|
| `--bg` | `#08111d` | 页面主背景 |
| `--bg-2` | `#0b1728` | 页面渐变背景底色 |
| `--card-bg` | `rgba(15, 23, 42, 0.92)` | 卡片上层背景 |
| `--card-bg-soft` | `rgba(15, 23, 42, 0.76)` | 卡片下层渐变背景 |
| `--topbar-bg` | `rgba(8, 17, 29, 0.78)` | 粘性顶部栏背景 |

## 圆角与阴影规范

### 圆角

圆角用于降低界面硬度，让活动卡片更接近校园社交内容流。

| 变量 | 值 | 用途 |
|------|----|------|
| `--radius-sm` | `14px` | 小按钮、输入框、品牌标识 |
| `--radius` | `20px` | 活动卡片、工具栏、状态面板 |
| `--radius-lg` | `28px` | 胶囊标签、导航按钮、头像 |

落地规则：

- 活动卡片统一使用 `20px` 圆角。
- 按钮和输入框统一使用 `14px` 圆角。
- 类型标签、活动标签和导航项使用胶囊形圆角。

### 阴影

阴影用于区分卡片层级，不用于制造强烈浮雕效果。

| 变量 | 值 | 用途 |
|------|----|------|
| `--shadow` | `0 20px 55px rgba(2, 6, 23, 0.42)` | 顶层卡片、品牌标识 |
| `--shadow-soft` | `0 14px 36px rgba(2, 6, 23, 0.22)` | 活动瀑布流卡片 |

交互规则：

- 普通卡片默认使用 `--shadow-soft`。
- 鼠标悬停时卡片上移 `-3px`。
- 鼠标悬停时边框改为 `--chip-active-border`。
- 禁止使用过亮白色阴影，因为会破坏深色背景层次。

## 瀑布流卡片信息层级

活动卡片必须按“封面 → 类型和指标 → 标题 → 推荐理由 → 成员 → 标签 → 操作”的顺序展示。

| 层级 | 元素 | 来源字段 | 说明 |
|------|------|----------|------|
| 1 | 封面标签 | `coverLabel` 或 `cover_label` | 例如“夜跑 · 深技大” |
| 2 | 封面标题 | `title` 或 `name` | 活动名称，卡片中最重要的信息 |
| 3 | 类型徽标 | `type` 或 `category` | campus、speed、social 映射为中文 |
| 4 | 距离 | `distanceKm` 或 `distance_km` | 显示为 `8.4K` 这类短文本 |
| 5 | 配速 | `pace` 或 `avg_pace` | 例如 `5'18"/km` |
| 6 | 推荐理由 | `reasoning` 或 `reason` | 解释为什么推荐该活动 |
| 7 | 成员信息 | `runner`、`nickname` 或 `host` | 展示头像首字和昵称 |
| 8 | 标签 | `tags` 或 `labels` | 例如“夜跑”“操场”“新手友好” |
| 9 | 操作按钮 | `data-card-action` | 创建任务、查看理由 |

卡片结构示例：

```html
<article class="activity-card">
  <header class="activity-card__cover">
    <div class="activity-card__cover-text">
      <span>夜跑 · 深技大</span>
      <strong>校园夜跑接力</strong>
    </div>
  </header>
  <div class="activity-card__body">
    <div class="activity-card__meta">
      <span class="activity-badge activity-badge--blue">校园感</span>
      <span class="activity-badge">8.4K</span>
      <span class="activity-badge">5'18"/km</span>
    </div>
  </div>
</article>
```

## 按钮状态规范

按钮必须覆盖默认、悬停、按下、聚焦和禁用状态。

| 状态 | 样式要求 | 当前实现 |
|------|----------|----------|
| 默认 | 高度不低于 `46px`，文字加粗 | `.btn`、`.filter-chip`、`.activity-action` |
| 悬停 | 上移 `-1px`，边框或背景变化 | `:hover` |
| 按下 | 回到原位，避免跳动 | `:active` |
| 聚焦 | 显示可见焦点，不移除轮廓反馈 | `:focus-visible` |
| 禁用 | 透明度 `0.5`，鼠标为不可点击 | `:disabled` |

主按钮用于提交、创建任务、重试。
次按钮用于刷新、查看理由、筛选辅助操作。

```css
.btn:disabled,
.filter-chip:disabled,
.activity-action:disabled {
  opacity: 0.5;
  cursor: not-allowed;
  transform: none;
  box-shadow: none;
}
```

## 状态规范

### 空状态

空状态用于“接口正常但没有数据”或“筛选后没有结果”。

文案必须说明原因和下一步动作：

```text
当前筛选条件下没有活动卡片，试试切换类型或清空关键词。
```

样式要求：

- 使用 `activity-state` 或 `panel-empty` 容器。
- 边框可用虚线，但文字不能只写“空”。
- 必须提供可执行建议，例如切换类型、清空关键词、刷新页面。

### 加载态

加载态用于等待 `/api/v1/activities` 返回。

当前实现包括：

- 顶部状态栏显示 `加载中`。
- 活动列表显示 3 张 `skeleton-card`。
- 刷新、搜索、排序和筛选按钮临时禁用。

可验收文案：

```text
正在读取活动列表。
```

### 错误态

错误态用于接口请求失败。

当前实现会切换成本地示例数据，同时显示中文错误提示。

可验收文案：

```text
网络错误，已切换为本地示例数据。
```

错误态必须包含重试入口：

```html
<button class="btn btn-primary" type="button" data-retry>重试</button>
```

## 响应式规范

页面使用 CSS column 实现 masonry（瀑布流）布局。
masonry 是一种多列内容流布局，卡片高度可以不同，但阅读方向保持从上到下。

| 屏幕宽度 | 列数 | 当前规则 |
|----------|------|----------|
| 大于 `1024px` | 3 列 | `.masonry { column-count: 3; }` |
| 小于等于 `1024px` | 2 列 | media query 调整为 2 列 |
| 小于等于 `560px` | 1 列 | 手机端单列展示 |

移动端要求：

- 不允许出现横向滚动。
- 筛选按钮和操作按钮在窄屏下可以占满一行。
- 活动封面高度在手机端使用 `--cover-mobile: 190px`。

## 数据字段兼容规范

`activity-waterfall.js` 已做字段兼容，前端新增接口对接时不要只支持单一字段名。

| 页面字段 | 兼容字段 | 默认值 |
|----------|----------|--------|
| 活动标题 | `title`、`name` | `未命名活动` |
| 类型 | `type`、`category` | `social` |
| 封面标签 | `coverLabel`、`cover_label` | `精选活动` |
| 距离 | `distanceKm`、`distance_km`、`distance` | `0` |
| 配速 | `pace`、`avg_pace` | `--` |
| 成员 | `runner`、`nickname`、`host` | `匿名成员` |
| 推荐理由 | `reasoning`、`reason`、`suggestion` | 默认推荐原因文案 |
| 点赞数 | `likes`、`like_count` | `0` |
| 评论数 | `comments`、`comment_count` | `0` |
| 标签 | `tags`、`labels` | 空数组 |

## 组件验收标准

### 活动卡片

一句话说明：活动卡片用于在瀑布流中展示单个活动的封面、指标、成员和操作入口。

验收标准：

1. 卡片根节点使用 `.activity-card`。
2. 卡片必须包含封面区 `.activity-card__cover`。
3. 卡片必须展示活动标题、类型、距离、配速、推荐理由和成员昵称。
4. 类型为 `campus` 时使用蓝色徽标。
5. 类型为 `speed` 时使用绿色徽标。
6. 标签数组为空时，标签区域允许为空，但不能渲染 `undefined`。
7. 鼠标悬停时卡片上移，且边框变为蓝色高亮。
8. 手机端卡片宽度必须为容器宽度，不允许横向滚动。

### 导入入口

一句话说明：导入入口用于把推荐活动带入任务创建流程。

当前页面中对应按钮是：

```html
<button class="activity-action activity-action--primary" data-card-action="create">创建任务</button>
```

验收标准：

1. 主操作按钮文案为“创建任务”或“导入活动”。
2. 按钮使用 `.activity-action--primary`。
3. 点击后必须携带 `title`、`type`、`reason` 三个参数。
4. 当前实现跳转到 `/tasks/create`。
5. 加载态下按钮必须禁用，避免重复触发。
6. 如果后续改为弹窗导入，仍需保留活动标题和推荐理由。

### 状态徽标

一句话说明：状态徽标用于让用户快速识别活动类型、距离、配速和任务状态。

验收标准：

1. 徽标基础类名使用 `.activity-badge`。
2. campus 类型使用 `.activity-badge--blue`。
3. speed 类型使用 `.activity-badge--green`。
4. social 类型使用默认灰色徽标。
5. 徽标文案必须是中文，例如“校园感”“速度训练”“社交约跑”。
6. 徽标高度和内边距必须保持一致，不能因为文字长短跳动。

### 筛选工具栏

一句话说明：筛选工具栏用于按关键词、类型和排序方式缩小活动范围。

验收标准：

1. 搜索框支持活动标题、成员、推荐理由和标签。
2. 类型筛选包含“全部”“校园感”“速度训练”“社交约跑”。
3. 当前选中的筛选按钮必须有 `.is-active`。
4. 当前选中的筛选按钮必须设置 `aria-pressed="true"`。
5. 排序至少支持互动热度、距离和配速。
6. 筛选结果为空时必须展示中文空状态。

### 加载与错误面板

一句话说明：加载与错误面板用于向用户解释当前数据读取状态。

验收标准：

1. 加载时展示 `spinner` 和 3 张 `skeleton-card`。
2. 加载时禁用刷新、搜索、排序和筛选控件。
3. 接口失败时显示“网络错误”。
4. 接口失败时显示“已切换为本地示例数据”。
5. 错误态必须提供“重试”按钮。
6. 空状态、加载态、错误态都不能只显示图标，必须有中文解释。

## 前端引用方式

frontend-dev 可以直接按以下顺序引用本规范：

1. 先打开 `frontend/index.html`，确认 CSS 变量和页面结构。
2. 再打开 `frontend/activity-waterfall.js`，确认字段兼容和状态逻辑。
3. 新增组件时复用 `--brand`、`--brand-2`、`--radius`、`--shadow-soft`。
4. 不要在新组件中重新定义另一套主色、圆角和阴影。
5. 如需拆分样式文件，可先把 `frontend/index.html` 中的 `<style>` 移入独立 CSS 文件。

## 注意事项

- 不要把主色改为纯蓝或纯绿，当前视觉依赖蓝绿渐变表达科技和运动感。
- 不要删除错误态的本地示例数据兜底，否则接口不可用时页面会变成空白。
- 不要只用颜色表达状态，必须同时保留中文文案。
- 不要让瀑布流卡片固定同一高度，否则会失去 masonry 布局的信息密度。
- 不要在手机端保留多列瀑布流，560px 以下必须单列。
- 不要在文案中出现未解释的英文缩写。
