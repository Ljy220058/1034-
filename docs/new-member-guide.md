# 新人上手操作手册

欢迎来到 1034 跑团管理系统前端仓库。本文面向新成员，帮助你快速理解项目、搭建本地环境、找到核心目录，并安全地加入新功能与完成基础验证。

## 1. 项目简介

这是一个以跑团管理为目标的前端项目，界面采用纯静态页面与原生 HTML/CSS/JS 实现，通过 `fetch` 调用后端 API（统一前缀通常为 `/api/v1/`）。项目强调：

- 中文界面，信息清晰，适合运营与管理场景
- 暗色主题 + 大留白 + 轻微动效
- 适配桌面与手机，尤其要保证 375px 宽度下不横向滚动
- 尽量复用现有样式变量与组件状态，不推倒重来

如果你是第一次进入仓库，优先阅读前端入口页和现有文档，理解当前视觉语言、公共变量和 API 约定，再开始动手。

## 2. 本地环境搭建

项目以静态前端为主，通常不需要框架构建工具。建议按下面步骤准备：

1. 进入仓库根目录。
2. 打开前端目录，查看入口文件与脚本结构。
3. 若需要预览页面，使用本地静态服务器，例如：
   - `python3 -m http.server 8080`
4. 在浏览器访问本地地址，检查页面加载、交互状态和响应式表现。

注意事项：

- 不要假设项目使用 npm、Vite、React 或 Vue；当前任务以原生三件套为准。
- 若终端环境缺少某个命令，先确认可用工具，再决定是否通过别的方式验证。
- 只在当前工作区内修改文件，不要随意改动其他路径。

## 3. 目录结构说明

仓库中常见的前端相关位置如下：

- `frontend/index.html`：前端入口页，通常包含全局 CSS 变量、页面骨架与主要挂载区域。
- `frontend/*.js`：页面逻辑、API 封装、通用工具。
- `frontend/*.css` 或内联样式：组件视觉与布局规则。
- `frontend/docs/`：前端文档目录，适合存放规范、说明和协作文档。
- `docs/`：项目级文档目录，适合新增新人手册、流程说明、使用指南等。

理解目录时，建议优先找：

- 全局变量定义位置
- 现有组件的挂载点
- API 请求封装位置
- 已存在的空态、加载态、错误态样式

## 4. 如何添加新功能

新功能建议遵循“渐进扩展”原则：在现有结构上新增模块，不要整体重写。

推荐流程：

1. 先阅读入口页，确认页面现有组件与 CSS 变量。
2. 找到最接近的新功能区域，在其附近追加新的 section 或 article。
3. 使用语义化标签组织内容：`header`、`main`、`section`、`article`、`nav`、`button`、`ul` 等。
4. 组件样式按功能分组，统一引用 `:root` 中的变量。
5. 状态齐全：加载中、空态、错误态、禁用态、悬停态、激活态都要覆盖。
6. 新增 API 接口时，优先复用已有 `fetch` 封装与工具方法。
7. 如发现后端返回格式与页面预期不一致，不要在前端“硬猜”；应创建后端跟进任务。

开发小建议：

- 一个文件尽量只负责一件事。
- 函数名使用动词开头，如 `renderXxx`、`fetchXxx`、`handleXxx`。
- 移动端布局优先保证可读与不溢出，再追求复杂排版。

## 5. 如何运行测试

前端任务通常以静态预览和人工检查为主。如果仓库里有测试，也要先确认测试运行方式与当前环境是否匹配。

基础验证建议：

- 用本地静态服务器打开页面，确认入口可访问。
- 在 375px、768px、1280px 三档宽度下检查布局。
- 逐个点击按钮，确认 hover / active / disabled / loading 状态。
- 检查空列表是否显示“暂无数据”。
- 断开后端或模拟错误，确认错误提示与重试按钮可见。
- 搜索源码中是否出现不应新增的固定颜色值。

如果仓库存在自动化测试脚本，请先看清运行约定，再决定是否执行，避免在错误环境里浪费时间。

## 6. 协作建议

- 先看 `docs/` 中已有内容，补充而不是重复。
- 如果发现 API、数据结构或后端行为存在问题，记录清楚并发起对应协作任务。
- 完成后记得在任务看板里写清楚修改文件、验证方式和潜在限制，方便后续成员接手。

开始前先确认这几件事：

- [ ] 已阅读前端入口页与现有样式变量
- [ ] 已确认页面的核心模块与数据来源
- [ ] 已了解本地预览方式
- [ ] 已确认需要新增的功能区域
- [ ] 已准备好响应式与状态态检查

如果你是第一次接手这个仓库，建议从一个小功能或文档补充开始，先熟悉项目风格，再逐步接入更复杂的交互。
