# 跑团活动照片精选墙功能规格

日期：2026-06-06
状态：产品创意规格
适用对象：1034 跑团管理系统活动详情页、运营周报、管理员审核入口

## 一、背景与目标

1034 跑团管理系统已经具备成员管理、活动管理、公告发布、报名、签到、活动瀑布流、数据统计页面，以及围绕活动复盘、校园挑战赛排行榜、运营周报的规格文档。现有活动瀑布流侧重“活动发现与报名”，运营周报侧重“本周数据汇总”，挑战赛排行榜侧重“周期性成绩激励”，复盘卡片侧重“单个成员训练结果解释”。

“跑团活动照片精选墙”用于补齐活动后的校园氛围展示：管理员从活动相关照片中挑选少量已授权、已审核的图片，展示在活动详情页和运营周报中，让成员回顾现场氛围，同时避免未经授权的人像、敏感地点或不合规内容被公开。

核心目标：

1. 让成员在活动结束后看到精选照片，增强参与记忆和校园社群归属感。
2. 让团长在周报里复用活动照片，提高运营内容的可读性。
3. 让管理员通过明确的审核状态控制哪些照片可见，降低隐私和内容风险。
4. 首版只做轻量 MVP，不引入第三方图片服务、不做 AI 识别、不替代排行榜、热力地图或复盘卡片。

## 二、与已有功能的边界

| 已有或规划模块 | 本功能避让方式 |
|---|---|
| 活动瀑布流 | 瀑布流展示活动卡片和报名入口；照片精选墙只在活动详情或周报中展示活动后照片，不改变活动推荐规则。 |
| 运营周报 | 周报负责数据摘要；照片精选墙提供可被周报引用的封面图和精选图列表。 |
| 成员隐私授权 | 本规格只定义照片展示授权边界；不新增第三方 OAuth，不保存外部账号密码。 |
| 校园挑战赛排行榜 | 排行榜展示跑量、签到和排名；照片墙只展示活动现场氛围，不参与排名计算。 |
| 热力地图 | 热力地图展示路线或区域热度；照片墙不展示 GPS 轨迹和精确拍摄坐标。 |
| 复盘卡片 | 复盘卡片解释个人训练结果；照片墙不评价个人表现，不展示其他成员的训练明细。 |

## 三、MVP 范围

### 3.1 照片上传入口

MVP 建议提供两个轻量入口：

1. 活动详情页管理员入口：活动结束后，管理员在活动详情页点击“上传精选照片”，上传本活动相关照片。
2. 管理后台活动列表入口：管理员在活动行操作区点击“管理照片”，进入该活动的照片审核与排序页面。

首版不建议开放普通成员自由上传到公开墙。如果需要成员投稿，可以先让成员将照片交给团长线下筛选，再由管理员上传，避免短期内引入复杂举报、撤回和批量审核流程。

### 3.2 精选规则

管理员每个活动最多精选 9 张照片，建议默认展示 3 张，点击“查看更多”展开到 9 张。

精选规则：

1. 照片必须关联一个已存在活动 `activity_id`。
2. 照片必须处于 `approved` 审核状态才可对成员可见。
3. 每个活动最多有 1 张封面图 `is_cover = true`。
4. 排序优先级为 `is_cover`、`sort_order`、`created_at`。
5. 照片说明文案不超过 60 个中文字符，避免变成活动复盘长文。
6. 可见性为 `public` 的照片可进入公开活动详情；可见性为 `members_only` 的照片只对登录成员展示；`admins_only` 仅用于待确认或敏感照片内部查看。

### 3.3 封面图

封面图用于两个位置：

1. 活动详情页照片墙首图。
2. 运营周报中活动亮点卡片的配图。

封面图要求：

- 必须来自已审核通过照片。
- 优先选择没有清晰单人正脸、能体现校园跑团氛围的合照、操场、补给点或起终点照片。
- 不展示原始文件名，前端只展示照片说明、上传时间和审核状态。
- 封面图缺失时，前端显示深技大风格渐变占位卡，不显示破图。

### 3.4 活动关联

每张照片必须关联活动。活动基础字段复用现有 `activities`：

| 字段 | 来源 | 用途 |
|---|---|---|
| `activity_id` | `activities.id` | 照片所属活动 |
| `activity_title` | `activities.title` | 前端标题和管理员审核上下文 |
| `activity_start_time` | `activities.start_time` | 判断活动是否已结束、周报归属周期 |
| `location` | `activities.location` | 展示校园地点概览，不展示拍摄精确坐标 |
| `route` | `activities.route` | 管理员判断照片是否与活动相关 |

MVP 不要求照片与具体签到记录、成员个人训练记录强绑定，避免过早扩大隐私范围。

### 3.5 成员可见性

建议可见性枚举：

| 可见性 | 展示范围 | 适用场景 |
|---|---|---|
| `public` | 未登录访客和登录成员可见 | 无明显人像或已取得公开展示授权的校园氛围图 |
| `members_only` | 仅登录成员可见 | 有成员合影但不适合公开传播 |
| `admins_only` | 仅管理员可见 | 待确认授权、敏感地点、需二次审核照片 |

前端必须根据当前用户身份过滤照片：普通成员不能看到 `admins_only`，未登录用户不能看到 `members_only`。

### 3.6 管理员审核状态

建议审核状态枚举：

| 状态 | 中文展示 | 说明 |
|---|---|---|
| `pending` | 待审核 | 上传后默认状态，不进入成员端照片墙 |
| `approved` | 已通过 | 可以按可见性展示 |
| `rejected` | 已拒绝 | 不展示，管理员可查看拒绝原因 |
| `hidden` | 已隐藏 | 曾经通过但因撤回授权或内容问题下线 |

审核原因字段 `review_note` 用于记录“人像未授权”“地点敏感”“与活动无关”“重复照片”等中文原因，不对普通成员展示。

## 四、前端展示字段

### 4.1 活动详情页照片墙

| 字段 | 类型 | 必填 | 示例 | 说明 |
|---|---|---:|---|---|
| `photo_id` | number/string | 是 | `18` | 照片唯一标识 |
| `activity_id` | number/string | 是 | `6` | 关联活动 |
| `image_url` | string | 是 | `/uploads/activity-photos/6/start-line.jpg` | 前端可访问图片地址 |
| `thumbnail_url` | string | 否 | `/uploads/activity-photos/6/thumb-start-line.jpg` | 缩略图，缺失时用 `image_url` |
| `caption` | string | 否 | `起跑前的操场合影` | 60 字内中文说明 |
| `visibility` | string | 是 | `members_only` | `public`、`members_only`、`admins_only` |
| `review_status` | string | 是 | `approved` | 只有通过状态进入成员端 |
| `is_cover` | boolean | 是 | `true` | 是否封面图 |
| `sort_order` | number | 是 | `1` | 手动排序 |
| `uploaded_by_name` | string | 否 | `陈团长` | 管理端展示，成员端可隐藏 |
| `created_at` | string | 是 | `2026-06-06T21:10:00+08:00` | 上传时间 |

### 4.2 活动详情页展示结构

```text
┌──────────────────────────────┐
│ 活动照片精选｜校园夜跑接力        │
│ 已精选 6 张 · 仅展示已授权照片      │
├──────────────────────────────┤
│ [封面大图：起跑前的操场合影]       │
│ 起跑前的操场合影 · 仅成员可见       │
├───────────┬───────────┬──────────┤
│ 补给点照片 │ 终点合影  │ 夜跑路线牌 │
└───────────┴───────────┴──────────┘
```

移动端要求：

1. 375 像素宽度下，封面图单列展示，其余照片两列网格。
2. 每张照片必须有文字状态或可见性提示，不能只靠颜色区分。
3. 图片加载失败时展示“照片暂不可用”，不能影响活动详情页其他信息。
4. `members_only` 在未登录状态下展示登录引导，不展示缩略图。

### 4.3 运营周报展示字段

周报只引用每个活动的封面图和最多 3 张精选图：

| 字段 | 来源 | 周报用途 |
|---|---|---|
| `cover_photo_url` | 当前活动 `is_cover = true` 且 `approved` | 活动亮点封面 |
| `photo_count` | 当前活动已通过照片数 | “本场精选 6 张照片” |
| `caption_summary` | 前 3 张照片说明 | 周报照片说明列表 |
| `visibility_note` | 可见性聚合 | 提醒“含成员可见照片，公开周报请勿外传” |

## 五、后端最小数据来源

### 5.1 推荐数据结构

MVP 需要新增一张轻量照片表，因为现有 `activities` 只有活动基础字段，无法稳定保存多张照片、审核状态和排序。

建议表名：`activity_photos`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `id` | integer | 是 | 主键 |
| `activity_id` | integer | 是 | 关联 `activities.id`，活动删除时级联或限制删除由后端决定 |
| `image_url` | text | 是 | 图片访问路径，不保存本机绝对路径给前端 |
| `thumbnail_url` | text | 否 | 缩略图路径 |
| `caption` | text | 否 | 中文说明，建议 60 字内 |
| `visibility` | text | 是 | `public`、`members_only`、`admins_only` |
| `review_status` | text | 是 | `pending`、`approved`、`rejected`、`hidden` |
| `review_note` | text | 否 | 管理员审核备注 |
| `is_cover` | integer/boolean | 是 | 每个活动最多一张封面 |
| `sort_order` | integer | 是 | 同活动内排序 |
| `uploaded_by_member_id` | integer | 否 | 上传管理员或团长 ID |
| `created_at` | text/datetime | 是 | 上传时间 |
| `updated_at` | text/datetime | 是 | 更新时间 |

### 5.2 推荐 API

首版 API 只需要覆盖展示、上传、审核和排序：

```http
GET /api/v1/activities/{activity_id}/photos
POST /api/v1/activities/{activity_id}/photos
PATCH /api/v1/activities/{activity_id}/photos/{photo_id}/review
PATCH /api/v1/activities/{activity_id}/photos/reorder
```

权限建议：

- `GET`：按登录态和照片可见性过滤。
- `POST`：仅 `leader`、`admin` 可上传，上传后默认 `pending`。
- `review`：仅 `admin` 可通过、拒绝或隐藏照片。
- `reorder`：仅 `leader`、`admin` 可排序；如果把某张图设为封面，后端要自动取消同活动其他封面。

### 5.3 不直接复用的字段

不建议把照片 URL 塞进 `activities.description` 或 `cover_url` 扩展字段里，因为这会造成：

1. 多张照片难排序。
2. 无法记录审核状态。
3. 无法区分公开、成员可见、管理员可见。
4. 周报引用时无法判断是否已授权。

## 六、隐私与内容审核注意点

1. 默认不公开：上传后默认 `pending + admins_only`，通过审核后才允许切换到 `public` 或 `members_only`。
2. 人像授权：含清晰成员正脸的照片默认建议 `members_only`；未确认授权时保持 `admins_only` 或拒绝。
3. 手机号和个人信息：照片说明不得包含手机号、身份证号、宿舍号等个人敏感信息。
4. 精确位置：不保存拍摄 GPS 坐标，不展示宿舍楼具体房间、门禁、车牌等敏感细节。
5. 撤回机制：成员要求撤回本人照片时，管理员可将照片状态改为 `hidden`，周报后续不再引用。
6. 审核留痕：拒绝或隐藏照片必须填写中文 `review_note`，方便后续解释。
7. 文件安全：后端只允许图片 MIME 类型和安全扩展名；前端不信任原始文件名。
8. 未成年人或访客：如活动涉及非跑团成员，默认不公开正脸照片。

## 七、不做范围

MVP 明确不做以下内容：

1. 不做第三方相册、微信、校园云盘或对象存储 API 对接。
2. 不做 AI 自动识别人脸、打码、选图或生成说明文案。
3. 不做普通成员自由投稿的公开流和举报系统。
4. 不展示原始 GPS 坐标、EXIF 信息或完整拍摄设备信息。
5. 不把照片点赞数、评论数纳入排行榜或成员徽章。
6. 不做复杂图片编辑、滤镜、裁剪、批量压缩后台任务。
7. 不替代活动复盘卡片、热力地图或运营周报。

## 十、验收标准

1. 活动详情页能展示已审核通过且当前用户有权限查看的精选照片。
2. 每个活动最多一张封面图，封面缺失时有深技大风格占位。
3. 管理员能看到待审核、已通过、已拒绝、已隐藏四类状态。
4. 普通成员看不到 `admins_only` 照片，未登录用户看不到 `members_only` 照片。
5. 运营周报只引用已通过照片，并能提示可见性边界。
6. 拒绝或隐藏照片时必须有中文审核原因。
