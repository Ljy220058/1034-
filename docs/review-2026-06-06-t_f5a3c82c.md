# 代码审查报告

## 严重（必须修）
- [backend/routes/tasks.py:156] `/api/v1/tasks/items/batch` 没有 `Depends(get_current_user)`，也没有调用 `admin_or_leader`，任何未认证请求都可以批量写入 `workspace_tasks`。这会绕过单条创建接口的鉴权，造成未授权任务注入/覆盖。→ 建议：把签名改为 `def batch_create_task_items(raw_payload: dict[str, Any], current_user: CurrentUser = Depends(get_current_user)) -> ApiResponse:`，函数开头执行 `admin_or_leader(current_user)`；补充未登录返回 401、普通 member 返回 403 的测试。
- [backend/routes/creative_card_router.py:143] `/api/v1/creative-cards/batch-route` 注册为公开接口，函数签名没有任何 `current_user = Depends(get_current_user)` 或角色校验。攻击者可未登录批量提交任务描述，探测 worker 分配规则、生成稳定指纹并消耗服务资源。→ 建议：增加 `current_user: CurrentUser = Depends(get_current_user)` 并调用 `admin_or_leader(current_user)`；若只允许登录用户预检，也至少调用 `get_current_user` 并限制 batch 大小/频率。

## 中等（应该修）
- [backend/models.py:154] `TaskItemCreate.assignee` 被定义为可选，导致 `/api/v1/tasks/items` 在请求完全省略 `assignee` 时仍会持久化 `assignee=None`；这不符合“负责人必须合规”的任务卡规则，也会生成无人处理的创意任务。→ 建议：改为 `assignee: str = Field(min_length=1, max_length=120)`，保留 `normalize_assignee` 清理空白；补充“缺少 assignee 字段返回 422 且中文错误”的测试。
- [backend/routes/workspaces.py:53] `/api/v1/workspaces/tasks` 只校验登录，没有调用 `admin_or_leader`，普通 member 可以读取任意 `workspace_path` 的任务列表。工作区任务里包含 assignee、状态、描述等调度信息，属于越权读取。→ 建议：在第 73 行替换 `_ = current_user` 为 `admin_or_leader(current_user)`，并从 `.common` 导入 `admin_or_leader`；普通成员访问应返回 403。
- [backend/routes/workspaces.py:109] `/api/v1/workspaces/tasks/items` 同样只要求登录用户，普通 member 可读取指定工作区最近任务、负责人和元数据。→ 建议：函数开头调用 `admin_or_leader(current_user)`；补充 member 角色访问该端点返回 403 的测试。
- [backend/routes/workspaces.py:138] `/api/v1/workspaces/workers/board` 只要求登录用户，普通 member 可枚举 `idle_workers`、`busy_workers`、健康状态和任务看板，泄露内部调度状态。→ 建议：函数开头调用 `admin_or_leader(current_user)`；如果需要给 member 展示摘要，另建只返回聚合数量的低权限端点。
- [backend/routes/workspaces.py:206] `/api/v1/workspaces/workers/recommendations` 只要求登录用户，普通 member 可读取 worker 推荐、任务标题、状态和推荐负责人。→ 建议：同样调用 `admin_or_leader(current_user)`；不要向非管理角色暴露推荐 assignee。
- [backend/routes/tasks.py:355] `/api/v1/tasks/workspace-scoped-creation-helper` 从原先返回 `create_task_payloads()` 变成固定返回 `{'count': 0, 'tasks': []}`，且没有鉴权依赖。调用方会以为没有可创建任务，导致“快速复核新建任务”的入口失效；同时公开空接口也会扩大攻击面。→ 建议：恢复 `current_user: CurrentUser = Depends(get_current_user)` + `admin_or_leader(current_user)`，返回 `{'count': len(tasks), 'tasks': tasks}`；若废弃该端点，应删除路由并更新前端/测试，而不是返回空数据。

## 建议（可以修）
- [backend/routes/tasks.py:82] `_validation_detail` 对非自定义 Pydantic 错误直接返回 `message`，例如缺少字段时会返回英文 `Field required`，不符合“输出内容全中文”的合规要求。→ 建议：按 `error['type']` 映射中文文案，例如 `missing -> '字段不能为空'`、`string_too_short -> '字段长度不合法'`，最后 fallback 到 `'任务参数不合法'`。
- [backend/routes/creative_tasks.py:24] `_normalize_workspace_path` 只做 `resolve()`，没有复用 `workspace_validation.validate_workspace_access_path`；`/creative-task-generator` 可以接受任意绝对路径作为工作区上下文，和 `task_import.py` 的项目根目录限制不一致。→ 建议：统一调用 `validate_workspace_access_path(workspace_path)`，只允许 `/root/autodl-tmp/projects/hermes-swarm-lab`；错误返回 `{'detail': '工作区路径不合法'}`。
- [backend/routes/creative_tasks.py:129] `_generate_task_cards` 假设 `_candidate_profiles` 一定返回非空列表，然后用 `profiles[(index - 1) % len(profiles)]`。当前常量列表非空所以暂不触发，但后续配置化为空会直接 `ZeroDivisionError` 并返回 500。→ 建议：增加兜底 `if not profiles: raise HTTPException(422, detail='没有可用负责人')` 或默认 `backend-dev`。

## 不需要修但值得注意
- [backend/routes/tasks.py:51] `_serialize_worker` 把原来的 `eval(worker['capabilities'])` 改成 `json.loads` 是必要的安全方向；后续应确保数据库中的历史非 JSON capabilities 不会导致前端看不到能力标签。
- [backend/repository.py:340] `list_workspace_task_items` 的 SQL 使用参数化查询，当前没有发现 SQL 注入点；继续保持不要把 `status_filter` 或 `limit` 拼接进 SQL 字符串。
