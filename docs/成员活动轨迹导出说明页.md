# 成员活动轨迹导出说明页

## 概述

成员活动轨迹导出用于按成员查看报名、签到、反馈和组织活动记录。
它帮助管理员复盘成员参与过程，识别活跃成员和流失风险。

本文档只说明页面文案、字段和导出内容设计。
本文档不修改业务代码，也不假设当前系统已经提供独立导出接口。

## 适用角色

| 角色 | 是否可使用 | 说明 |
|---|---|---|
| 管理员 | 是 | 可以查看成员列表、活动记录、报名记录和签到记录，适合做完整导出。 |
| 团长 | 是 | 可以查看成员列表、活动记录、报名记录和签到记录，适合做活动运营复盘。 |
| 普通成员 | 否 | 普通成员只能查看自己的资料和自己的报名、签到动作，不应导出他人轨迹。 |

## 数据来源

当前项目已有成员、活动、报名和签到数据结构。
反馈数据在现有代码中没有独立表和接口。
因此本页把反馈作为后续功能的可选字段处理。

| 数据类型 | 现有来源 | 可复用字段 | 说明 |
|---|---|---|---|
| 成员 | `members` 表、`backend/models.py` | `id`、`name`、`phone`、`role`、`running_years`、`pace`、`usual_distance_km`、`training_goal`、`created_at`、`updated_at` | 用于识别成员身份、跑步经验、配速和训练目标。 |
| 活动 | `activities` 表、`backend/activity_registration_risk.py` | `id`、`title`、`start_time`、`location`、`route`、`distance_km`、`pace_group`、`description`、`max_participants`、`created_at`、`updated_at` | 用于展示成员参与过、报名过或组织过的活动。 |
| 报名 | `registrations` 表 | `id`、`activity_id`、`member_id`、`status`、`created_at` | 用于判断成员是否报名、是否取消报名。 |
| 签到 | `attendances` 表、`backend/models.py` | `id`、`activity_id`、`member_id`、`status`、`signed_in_at`、`gps_checked`、`created_at`、`updated_at` | 用于判断成员是否实际到场和是否完成定位校验。 |
| 反馈 | 当前未实现独立表 | 建议字段：`feedback_id`、`rating`、`content`、`sentiment_tags`、`created_at` | 用于活动结束后的体验复盘；当前导出中应显示“暂无反馈数据”。 |
| 组织活动 | 活动表和成员角色组合 | `activity_id`、`title`、`start_time`、`role` | 当前活动表没有创建人字段，因此只能按成员角色和人工筛选标注组织记录。 |

## 页面入口设计

### 入口位置

建议把导出入口放在管理员或团长可见的成员详情页。

推荐入口文案：

```text
成员详情页 → 活动轨迹 → 导出轨迹
```

如果后续增加活动详情页，也可以提供按活动反查成员轨迹的入口：

```text
活动详情页 → 参与成员 → 查看成员轨迹
```

### 入口按钮文案

| 场景 | 按钮文案 | 说明 |
|---|---|---|
| 成员详情页有数据 | 导出活动轨迹 | 默认导出当前成员在筛选条件内的轨迹。 |
| 成员详情页无活动记录 | 导出空轨迹 | 允许导出空结果，便于管理员留档。 |
| 批量成员列表 | 批量导出轨迹 | 后续功能，可一次导出多个成员。 |
| 权限不足 | 无法导出 | 普通成员不展示导出按钮。 |

## 快速开始

管理员可以按以下步骤完成一次导出。

1. 打开“成员管理”。
2. 搜索目标成员姓名或手机号。
3. 进入成员详情页。
4. 点击“活动轨迹”。
5. 设置时间范围和记录类型。
6. 点击“导出活动轨迹”。
7. 下载文件后检查导出摘要和明细记录。

示例操作路径：

```text
成员管理 → 李敏 → 活动轨迹 → 时间范围：最近 90 天 → 记录类型：报名、签到、反馈、组织活动 → 导出活动轨迹
```

## 筛选条件

筛选条件用于控制导出范围。
它可以避免一次导出过多数据，也减少不必要的个人信息暴露。

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `member_id` | integer | 是 | 成员 ID，来自 `members.id`。 |
| `start_date` | date | 否 | 导出开始日期，建议默认最近 90 天。 |
| `end_date` | date | 否 | 导出结束日期，建议默认今天。 |
| `record_types` | array | 否 | 记录类型，可选 `registration`、`checkin`、`feedback`、`organized_activity`。 |
| `activity_status` | string | 否 | 活动时间状态，可选“全部”“已结束”“未开始”。 |
| `registration_status` | string | 否 | 报名状态，可选 `registered`、`cancelled`。 |
| `checkin_status` | string | 否 | 签到状态，可选 `signed_in`、`absent`、`未签到`。 |
| `include_phone` | boolean | 否 | 是否导出手机号，默认关闭。 |
| `include_feedback_content` | boolean | 否 | 是否导出反馈正文，默认关闭。 |
| `format` | string | 否 | 导出格式，建议首版支持 CSV（Comma-Separated Values，逗号分隔值）或 Excel。 |

## 字段说明

### 成员摘要字段

成员摘要展示在导出文件顶部，用于说明本次导出属于哪个成员。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 成员 ID | integer | 是 | 对应 `members.id`。 |
| 姓名 | string | 是 | 对应 `members.name`。 |
| 手机号 | string | 否 | 对应 `members.phone`，默认脱敏为 `138****0000`。 |
| 角色 | string | 是 | 对应 `members.role`，可取 `admin`、`leader`、`member`。 |
| 跑龄 | integer | 是 | 对应 `members.running_years`，单位为年。 |
| 常用配速 | string | 否 | 对应 `members.pace`，例如 `5'30/km`。 |
| 常跑距离 | number | 否 | 对应 `members.usual_distance_km`，单位为公里。 |
| 训练目标 | string | 否 | 对应 `members.training_goal`。 |
| 入会时间 | datetime | 是 | 对应 `members.created_at`。 |

### 活动轨迹明细字段

活动轨迹明细按时间倒序展示。
每行表示成员与一次活动之间的一条轨迹记录。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 记录类型 | string | 是 | 可取“报名”“取消报名”“签到”“缺席”“反馈”“组织活动”。 |
| 活动 ID | integer | 是 | 对应 `activities.id`。 |
| 活动标题 | string | 是 | 对应 `activities.title`。 |
| 活动开始时间 | datetime | 是 | 对应 `activities.start_time`。 |
| 集合地点 | string | 是 | 对应 `activities.location`。 |
| 路线 | string | 否 | 对应 `activities.route`。 |
| 距离 | number | 否 | 对应 `activities.distance_km`，单位为公里。 |
| 配速组 | string | 否 | 对应 `activities.pace_group`。 |
| 活动说明 | string | 否 | 对应 `activities.description`。 |
| 名额上限 | integer | 否 | 对应 `activities.max_participants`。 |
| 报名状态 | string | 否 | 对应 `registrations.status`，可取 `registered` 或 `cancelled`。 |
| 报名时间 | datetime | 否 | 对应 `registrations.created_at`。 |
| 签到状态 | string | 否 | 对应 `attendances.status`，可取 `signed_in` 或 `absent`。 |
| 签到时间 | datetime | 否 | 对应 `attendances.signed_in_at`。 |
| GPS 校验 | boolean | 否 | 对应 `attendances.gps_checked`，表示是否完成定位校验。 |
| 反馈评分 | integer | 否 | 后续反馈功能字段，建议范围 1 到 5。 |
| 反馈标签 | array | 否 | 后续反馈功能字段，例如“路线满意”“组织混乱”。 |
| 反馈摘要 | string | 否 | 默认只导出摘要，不直接导出完整反馈正文。 |
| 组织身份 | string | 否 | 当前活动表没有创建人字段，需要由管理员人工标注或后续增加字段。 |

## 空状态文案

空状态文案用于告诉管理员为什么没有可导出记录。
同时说明下一步可以做什么。

| 场景 | 页面文案 | 建议操作 |
|---|---|---|
| 成员不存在 | 未找到该成员，请确认成员 ID 或搜索条件。 | 返回成员列表重新搜索。 |
| 成员无报名记录 | 该成员在当前时间范围内没有报名记录。 | 放宽时间范围或查看全部活动。 |
| 成员无签到记录 | 该成员在当前时间范围内没有签到记录。 | 检查是否只筛选了“已签到”。 |
| 暂无反馈数据 | 当前系统尚未记录活动反馈。 | 导出时保留反馈列，并填充“暂无反馈数据”。 |
| 无组织活动记录 | 当前系统没有该成员的组织活动记录。 | 如需统计组织贡献，后续应增加活动创建人或协助者字段。 |

## 失败态文案

失败态文案要说明失败原因和可执行的恢复动作。

| 场景 | 失败文案 | 处理建议 |
|---|---|---|
| 权限不足 | 当前账号没有导出成员活动轨迹的权限。 | 使用管理员或团长账号登录。 |
| 筛选范围过大 | 时间范围过大，请缩小到 1 年以内后重试。 | 缩短 `start_date` 到 `end_date` 的跨度。 |
| 成员 ID 无效 | 成员 ID 格式不正确，请重新选择成员。 | 从成员列表进入导出，不手动输入 ID。 |
| 导出文件生成失败 | 导出文件生成失败，请稍后重试。 | 保留筛选条件，刷新页面后再次导出。 |
| 反馈数据不可用 | 反馈模块暂未启用，本次导出不包含反馈正文。 | 继续导出报名和签到记录。 |
| 手机号未授权导出 | 当前导出未包含手机号，因为未开启敏感字段授权。 | 如确需导出手机号，由管理员开启 `include_phone`。 |

## 隐私提示

成员活动轨迹包含身份、手机号、训练目标、报名行为和签到时间。
这些内容属于运营敏感数据。

建议在导出前展示以下提示：

```text
本次导出将包含成员活动参与记录。请仅用于跑团运营、活动复盘和成员服务，不要转发到无关群聊或公开平台。
```

建议导出文件内也包含隐私说明：

```text
隐私说明：本文件仅供 1034 跑团管理员和团长进行活动运营分析。文件中可能包含成员手机号、训练目标、报名记录和签到记录，请勿公开传播。
```

### 敏感字段处理规则

| 字段 | 默认处理 | 原因 |
|---|---|---|
| 手机号 | 脱敏展示 | 手机号可直接识别个人身份。 |
| 反馈正文 | 默认不导出全文 | 反馈可能包含身体状态、情绪或私人安排。 |
| 签到时间 | 可导出 | 用于核对参与记录，但不应公开传播。 |
| GPS 校验 | 只导出是否校验 | 当前字段只表示布尔值，不导出具体位置。 |
| 训练目标 | 可导出 | 用于活动推荐和复盘，但仍应限制访问范围。 |

## 运营解读建议

管理员阅读导出文件时，可以按以下顺序判断成员状态。

1. 先看最近 90 天报名次数，判断成员是否有参与意愿。
2. 再看签到次数，判断报名是否转化为实际到场。
3. 如果报名多但签到少，优先查看取消报名和缺席记录。
4. 如果反馈中多次出现“太快”“太远”“集合点不清楚”，先标记为体验风险。
   这说明活动安排可能与成员能力或信息理解不匹配。
5. 如果成员长期没有报名和签到，可以加入召回名单，但不要频繁打扰。
6. 如果成员多次协助组织活动，可以标记为骨干成员候选人。

## 常见问题

### 1. 为什么反馈列显示“暂无反馈数据”？

当前代码中没有独立的活动反馈表、反馈接口或反馈页面。
导出设计保留反馈字段，是为了后续反馈模块上线后保持文件结构稳定。

### 2. 为什么组织活动记录需要人工标注？

当前活动表没有创建人、负责人或协助者字段。
系统只能确认活动本身存在。
它不能从现有字段自动判断某个成员是否组织了活动。

### 3. 普通成员能不能导出自己的轨迹？

首版建议不开放普通成员导出功能。
普通成员可以在个人页面查看自己的资料、报名和签到。
导出能力应先限制给管理员和团长。

### 4. 为什么手机号默认脱敏？

手机号属于可识别个人身份的信息。
默认脱敏可以降低文件外传后的隐私风险。
同时它仍保留管理员核对成员身份的能力。

### 5. 报名后取消还会出现在导出里吗？

会。
取消报名是成员活动轨迹的一部分。
它可以帮助管理员判断活动时间、地点或强度是否影响参与意愿。

### 6. 没有签到记录是否等于缺席？

不一定。
现有签到表支持 `signed_in` 和 `absent` 两种状态。
没有签到记录也可能是活动尚未开始、现场漏签或数据未录入。
导出中应区分“absent”和“未签到”。

### 7. GPS 校验为“否”是否表示签到无效？

不一定。
`gps_checked` 只表示是否完成定位校验。
是否接受这次签到，需要结合活动规则和管理员判断。

### 8. 为什么建议默认导出最近 90 天？

最近 90 天能覆盖成员近期活动习惯，又不会让文件过大。
管理员需要查看长期变化时，可以手动扩大时间范围。

## 注意事项

- 本页是说明页，不声明已有导出 API。
- 反馈字段属于预留字段，当前系统没有独立反馈数据源。
- 组织活动记录当前无法完全自动生成，原因是活动表没有创建人或协助者字段。
- 导出文件应记录导出时间、导出人和筛选条件，方便后续追溯。
- 默认不要导出未脱敏手机号和完整反馈正文。
- 如果后续新增导出接口，需要再补充 URL、请求方法、参数、返回示例和错误码。
