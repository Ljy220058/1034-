# 跑步数据导入失败原因排查手册

## 概述

本文用于排查 1034 跑团管理系统中
跑步数据导入失败的原因。

读者包括运营、后端开发、前端开发和测试同学。

排查顺序是：
先判断失败类型，
再用接口、日志和测试定位根因。

本文已对以下接口做过 curl 验证：

- `GET /api/v1/running-data-imports/precheck`
- `POST /api/v1/running-data-imports/start`
- `POST /api/v1/running-data-imports/wizard`
- `POST /api/v1/running-data-imports/anomaly-precheck`

验证时本机 `8000` 端口已被占用，
实际使用 `19347` 端口启动服务。
文档命令使用 `BASE_URL` 变量，
复制时只需要改成自己的端口。

## 快速开始

### 1. 启动接口服务

```bash
cd /root/autodl-tmp/projects/hermes-swarm-lab
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

### 2. 设置请求地址

```bash
export BASE_URL='http://127.0.0.1:8000'
```

如果 8000 端口已被占用，
换一个空闲端口后同步修改 `BASE_URL`。

### 3. 注册测试用户并设置令牌

JWT（JSON Web Token，身份令牌）在本项目中
通过 `Authorization: Bearer <token>` 请求头传递。

```bash
PHONE="1399$(date +%S%N | cut -c1-7)"
REGISTER_RESPONSE=$(curl -s -X POST "$BASE_URL/api/v1/auth/register" \
  -H 'Content-Type: application/json' \
  -d "{\"name\":\"Docs Import Runner\",\"phone\":\"$PHONE\",\"password\":\"secret123\",\"role\":\"member\"}")
ACCESS_TOKEN=$(printf '%s\n' "$REGISTER_RESPONSE" \
  | sed -n 's/.*"access_token":"\([^"]*\)".*/\1/p')
export AUTH_HEADER="Authorization: Bearer $ACCESS_TOKEN"
```

注意：如果数据库已有用户，
不要注册 `admin` 或 `leader`。
代码会拒绝普通注册入口提权。

### 4. 跑一遍导入相关测试


## 失败类型总览

| 失败类型 | 常见触发条件 | 用户提示文案建议 | 开发排查入口 |
|---|---|---|---|
| 鉴权失败 | 未登录、Bearer token（Bearer 令牌）缺失、未确认授权 | 请先登录并确认导入授权范围后再继续 | `get_current_user`、`start_running_data_import` |
| 文件格式错误 | CSV 无表头、JSON 无法解析 | 文件内容格式错误，请检查 CSV/JSON 后重试 | `_parse_csv`、`_parse_json` |
| 字段缺失 | 缺少活动名称、开始时间、距离或时长 | 导入数据缺少必填字段，请补齐后重试 | `REQUIRED_FIELDS`、`FIELD_ALIASES` |
| 重复导入 | 活动名称和开始时间精确到分钟后已存在 | 活动已存在，请确认是否跳过重复记录 | `_existing_activity_keys`、`duplicate_count` |
| 异常配速 | 用时除以距离后小于 150 秒/公里或大于 900 秒/公里 | 配速超出常见范围，请核对距离和用时 | `precheck_running_data_anomalies` |

## 1. 鉴权失败

### 概述

鉴权失败表示请求没有通过登录校验，
或用户还没有确认导入授权范围。

代码入口：

- `backend/routes/common.py` 的 `get_current_user`
- `backend/routes/running_data_imports.py` 的 `running_data_import_precheck`
- `backend/routes/running_data_imports.py` 的 `start_running_data_import`

### 快速开始

未登录调用预检接口，
应返回 401。

```bash
curl -i "$BASE_URL/api/v1/running-data-imports/precheck?source=garmin"
```

已登录后调用预检接口。

```bash
curl -s "$BASE_URL/api/v1/running-data-imports/precheck?source=garmin" \
  -H "$AUTH_HEADER"
```

用户确认授权后调用启动接口。

```bash
curl -s -X POST "$BASE_URL/api/v1/running-data-imports/start" \
  -H "$AUTH_HEADER" \
  -H 'Content-Type: application/json' \
  -d '{"source":"manual_file","consent_acknowledged":true}'
```

### 参数说明

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| source | string | 是 | 数据来源，支持 `coros`、`garmin`、`generic`、`manual_file` |
| Authorization | header | 是 | 登录后返回的 Bearer token |
| consent_acknowledged | boolean | 启动导入时必填 | 用户是否已确认授权范围 |

### 返回示例

授权确认成功时返回 202。

```json
{
  "data": {
    "status": "authorized_precheck_only",
    "source": {"id": "manual_file", "name": "手动文件"},
    "import_started": false,
    "next_step": "frontend may request the real importer after showing the precheck panel"
  },
  "message": "已确认授权"
}
```

### 错误示例

未登录返回 401。

```json
{
  "detail": "missing bearer token"
}
```

未确认授权返回 403。

```json
{
  "detail": "running data import requires explicit consent precheck acknowledgement"
}
```

### 注意事项

- `start` 当前是安全占位实现，返回 `import_started=false`。
- 不要提示“已经导入成功”，应提示“已完成授权确认”。
- 403 的运营提示建议统一为：请先确认导入授权范围后再继续。
- 注册测试用户时使用 `member` 角色，避免触发提权保护。

## 2. 文件格式错误

### 概述

文件格式错误表示后端无法把上传内容
解析为跑步活动记录。

CSV（Comma-Separated Values，逗号分隔值）
必须包含表头。

JSON（JavaScript Object Notation，数据交换格式）
必须是活动对象、活动对象列表，
或包含 `activities` / `data` 的对象。

### 快速开始

CSV 示例：

```bash
curl -s -X POST "$BASE_URL/api/v1/running-data-imports/wizard" \
  -H "$AUTH_HEADER" \
  -H 'Content-Type: application/json' \
  -d '{"source":"coros","format":"csv","content":"活动名称,开始时间,距离(km)\n晨跑,2026-06-01 07:00:00,5.2\n"}'
```

坏 JSON 示例：

```bash
curl -i -X POST "$BASE_URL/api/v1/running-data-imports/wizard" \
  -H "$AUTH_HEADER" \
  -H 'Content-Type: application/json' \
  -d '{"source":"generic","format":"json","content":"{bad-json"}'
```

### 参数说明

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| source | string | 是 | 数据来源，必须属于支持清单 |
| format | string | 是 | 只能是 `csv` 或 `json` |
| content | string | 是 | 原始文件内容，最大 200000 字符 |

### 返回示例

CSV 可解析时返回字段映射和预览。

```json
{
  "data": {
    "source": "coros",
    "input_format": "csv",
    "field_mapping": {
      "title": "活动名称",
      "start_time": "开始时间",
      "distance_km": "距离(km)"
    },
    "missing_fields": ["duration_seconds"],
    "preview": [
      {
        "row_number": 1,
        "title": "晨跑",
        "start_time": "2026-06-01 07:00:00",
        "distance_km": 5.2,
        "duration_seconds": null,
        "location": null,
        "duplicate": false,
        "duplicate_reason": null
      }
    ],
    "errors": [],
    "duplicate_count": 0
  },
  "message": "识别完成"
}
```

### 错误示例

坏 JSON 返回 400。

```json
{
  "detail": "无法解析 JSON 内容"
}
```

CSV 没有表头返回 400。

```json
{
  "detail": "无法解析 CSV 表头"
}
```

### 注意事项

- CSV 表头由 `csv.DictReader` 解析。
- JSON 解析逻辑位于 `_parse_json`。
- 前端不要把 400 展示成“服务器错误”。
- 用户提示参考 `backend/import_error_copy.py` 的“格式错误”。

## 3. 字段缺失

### 概述

字段缺失表示文件可以解析，
但缺少生成活动需要的标准字段。

标准必填字段定义在 `REQUIRED_FIELDS`：

```text
title, start_time, distance_km, duration_seconds
```

字段别名定义在 `FIELD_ALIASES`。

### 快速开始

下面命令构造一个缺少运动时长的 CSV。

```bash
curl -s -X POST "$BASE_URL/api/v1/running-data-imports/wizard" \
  -H "$AUTH_HEADER" \
  -H 'Content-Type: application/json' \
  -d '{"source":"generic","format":"csv","content":"活动名称,开始时间,距离(km)\n晨跑,2026-06-01 07:00:00,5.2\n"}'
```

下面命令构造一行缺少开始时间的数据。

```bash
curl -s -X POST "$BASE_URL/api/v1/running-data-imports/wizard" \
  -H "$AUTH_HEADER" \
  -H 'Content-Type: application/json' \
  -d '{"source":"generic","format":"csv","content":"活动名称,开始时间,距离(km),用时(秒)\n晨跑,,5.2,1800\n"}'
```

### 参数说明

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 活动名称 / title / name | string | 是 | 活动标题，会映射到 `title` |
| 开始时间 / start_time / startTime | string | 是 | 活动开始时间，会映射到 `start_time` |
| 距离(km) / distance | number | 是 | 跑步距离，会映射到 `distance_km` |
| 用时(秒) / duration | number | 是 | 跑步用时，会映射到 `duration_seconds` |

### 返回示例

整份文件缺少 `duration_seconds` 映射时：

```json
{
  "missing_fields": ["duration_seconds"],
  "errors": []
}
```

某一行缺少开始时间时：

```json
{
  "errors": [
    {
      "row": 1,
      "fields": ["start_time"],
      "message": "缺少必填字段"
    }
  ]
}
```

### 注意事项

- `missing_fields` 表示文件没有对应表头。
- `errors` 表示某一行没有具体值。
- 当前行级错误只检查 `title` 和 `start_time`。
- 新增表头别名时要同步更新向导测试。

## 4. 重复导入

### 概述

重复导入表示系统判断待导入活动已经存在。

当前去重规则是：
活动名称 + 开始时间前 16 个字符。

这等价于按“活动名称 + 精确到分钟的开始时间”判断。

### 快速开始

先用管理员或领队账号创建活动。

```bash
curl -s -X POST "$BASE_URL/api/v1/activities" \
  -H "$AUTH_HEADER" \
  -H 'Content-Type: application/json' \
  -d '{"title":"周末长跑","start_time":"2026-06-07T07:30:00","location":"滨江公园","distance_km":10}'
```

再导入同名同分钟记录。

```bash
curl -s -X POST "$BASE_URL/api/v1/running-data-imports/wizard" \
  -H "$AUTH_HEADER" \
  -H 'Content-Type: application/json' \
  -d '{"source":"garmin","format":"json","content":"[{\"name\":\"周末长跑\",\"startTime\":\"2026-06-07T07:30:00\",\"distance\":10,\"duration\":3600}]"}'
```

### 参数说明

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| title / name | string | 是 | 参与重复判断的活动名称 |
| start_time / startTime | string | 是 | 参与重复判断的开始时间 |
| duplicate | boolean | 否 | 后端返回字段，表示是否重复 |
| duplicate_reason | string/null | 否 | 后端返回字段，说明重复原因 |

### 返回示例

```json
{
  "duplicate_count": 1,
  "preview": [
    {
      "row_number": 1,
      "title": "周末长跑",
      "start_time": "2026-06-07T07:30:00",
      "distance_km": 10.0,
      "duration_seconds": 3600,
      "location": null,
      "duplicate": true,
      "duplicate_reason": "活动已存在"
    }
  ]
}
```

### 注意事项

- 向导阶段只标记重复，不写入新活动。
- 当前真实导入写入尚未闭环，不能承诺“自动跳过”。
- 运营提示建议为：活动已存在，请确认是否跳过重复记录。
- 代码入口是 `_existing_activity_keys` 和 `_build_preview`。

## 5. 异常配速

### 概述

异常配速表示系统根据距离和用时计算出的
平均配速超出常见跑步范围。

阈值位于 `backend/running_data_anomaly_precheck.py`：

- 最小合理配速：150 秒/公里。
- 最大合理配速：900 秒/公里。
- 超过 100 公里的单次记录会提示“超长距离”。

GPS（Global Positioning System，全球定位系统）轨迹
还会用于检查空轨迹和重复轨迹。

### 快速开始

下面命令同时复现异常配速和空 GPS 点。

```bash
curl -s -X POST "$BASE_URL/api/v1/running-data-imports/anomaly-precheck" \
  -H "$AUTH_HEADER" \
  -H 'Content-Type: application/json' \
  -d '{"source":"generic","format":"csv","content":"活动名称,开始时间,距离(km),用时(秒),GPS轨迹\n异常配速,2026-06-01T07:00:00,10,1000,track-a\n空GPS,2026-06-05T07:00:00,6,2400,[]\n"}'
```

### 参数说明

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| distance_km | number | 是 | 距离，单位公里 |
| duration_seconds | number | 是 | 用时，单位秒 |
| gps_track | string | 否 | GPS 轨迹，用于空轨迹和重复轨迹检查 |
| start_time | string | 是 | 开始时间，缺失时会阻断导入 |

### 返回示例

```json
{
  "data": {
    "summary": {
      "total_rows": 2,
      "anomaly_count": 2,
      "blocking_count": 0,
      "can_import": true
    },
    "anomalies": [
      {
        "row": 1,
        "code": "异常配速",
        "severity": "警告",
        "message": "平均配速约为每公里 100 秒，超出常见跑步范围",
        "suggestion": "请核对距离和用时，必要时改为手动确认后再导入"
      },
      {
        "row": 2,
        "code": "空GPS点",
        "severity": "提示",
        "message": "GPS 轨迹为空",
        "suggestion": "可补充轨迹文件；若为室内跑，请在前端标记为无轨迹导入"
      }
    ]
  },
  "message": "异常预检完成"
}
```

### 注意事项

- 异常配速是“警告”，不是自动阻断。
- 缺失时间和重复轨迹是“阻断”。
- 空 GPS 点是“提示”。
- `can_import=false` 表示存在阻断级异常。
- 先运行 `tests/test_running_data_import_anomaly_precheck.py` 定位阈值问题。

## 最小复现检查清单

按顺序执行，能复现大多数导入失败。

1. 启动 FastAPI（Fast Application Programming Interface，快速接口框架）服务。
2. 设置 `BASE_URL`。
3. 注册 `member` 测试用户。
4. 从注册响应中提取 `access_token`。
5. 设置 `AUTH_HEADER`。
6. 调用 `GET /api/v1/running-data-imports/precheck?source=garmin`。
7. 如果返回 401，检查 `Authorization` 请求头。
8. 如果返回 422，检查 `source` 是否属于支持清单。
9. 调用 `POST /api/v1/running-data-imports/start`。
10. 如果返回 403，检查 `consent_acknowledged` 是否为 `true`。
11. 调用 `POST /api/v1/running-data-imports/wizard` 上传最小 CSV。
12. 如果返回 400，检查 CSV 表头或 JSON 内容。
13. 查看 `missing_fields`，补齐四个标准字段。
14. 查看 `errors`，定位具体行号和缺失字段。
15. 查看 `duplicate_count` 和 `duplicate_reason`。
16. 调用 `POST /api/v1/running-data-imports/anomaly-precheck`。
17. 查看 `blocking_count` 判断能否继续导入。
18. 复查中文提示是否符合 `backend/import_error_copy.py`。

## 运营提示文案建议

| 场景 | 推荐文案 | 用户下一步 |
|---|---|---|
| 未登录 | 请先登录后再导入跑步数据 | 返回登录页 |
| 未确认授权 | 请先确认导入授权范围后再继续 | 回到授权预检页 |
| 来源不支持 | 暂不支持该来源平台，请选择高驰、佳明或通用 CSV/JSON | 切换来源 |
| 文件格式错误 | 文件内容格式错误，请检查 CSV/JSON 后重试 | 检查文件格式 |
| 缺少字段 | 导入数据缺少必填字段，请补齐后重试 | 补齐字段 |
| 重复活动 | 活动已存在，请确认是否跳过重复记录 | 核对重复记录 |
| 异常配速 | 配速超出常见范围，请核对距离和用时 | 修改距离或用时 |
| 空 GPS 点 | GPS 轨迹为空，如为室内跑请标记为无轨迹导入 | 补充轨迹或确认室内跑 |
| 重复轨迹 | 轨迹重复，请删除重复记录或只保留一条 | 删除重复行 |

## 注意事项

- 不要把后端英文错误原文直接展示给用户。
- 不要在导入失败时写入部分活动记录。
