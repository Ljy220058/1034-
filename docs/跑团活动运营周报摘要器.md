# 跑团活动运营周报摘要器

## 概述

跑团活动运营周报摘要器是一份可复用的中文周报模板。
它帮助管理员汇总本周活动、成员参与、导入质量和异常数据。

本文档只新增文档，不修改后端或前端代码。
字段来源已按现有代码、迁移脚本和导入向导接口核对。

## 快速开始

在项目根目录查看周报模板：

```bash
cd /root/autodl-tmp/projects/hermes-swarm-lab
sed -n '1,260p' docs/跑团活动运营周报摘要器.md
```

复制“周报模板”一节到 kanban（看板，任务协作队列）评论、管理员页面或群公告。
把尖括号里的示例值替换成本周统计结果。

## 字段来源说明

周报只使用当前仓库已有或已设计的数据字段。
不要在周报里写没有来源的数据。

| 周报字段 | 推荐来源 | 复用字段 | 说明 |
|---|---|---|---|
| 新增活动数 | `activities` 表 | `created_at`、`start_time` | 按本周创建或本周发生统计，口径需固定 |
| 已结束活动数 | `activities` 表 | `start_time` | `start_time` 小于周报结束时间的活动 |
| 活跃成员 | `attendances` 表 | `member_id`、`status` | `status = 'signed_in'` 表示已签到 |
| 总跑量 | `activities` 表 + `attendances` 表 | `distance_km`、`status` | 只统计已签到活动对应距离 |
| 报名未签到 | `registrations` 表 + `attendances` 表 | `registration_status`、`attendance_status` | 有报名但没有已签到记录 |
| 导入缺失字段 | 导入向导返回 | `missing_fields`、`errors` | 用于统计失败原因 |
| 重复活动 | 导入向导返回 | `duplicate`、`duplicate_reason` | 通过标题和开始时间识别 |
| 异常波动 | 参与率异常模型 | `anomaly_level`、`rate_delta_pp` | 来自迁移 007 的指标设计 |

## 计算口径

### 新增活动数

一句话说明：统计本周创建或本周开始的活动数量。

推荐第一版使用活动开始时间作为口径：

```sql
SELECT COUNT(*) AS new_activity_count
FROM activities
WHERE date(start_time) BETWEEN :week_start AND :week_end;
```

注意事项：

- 如果运营更关心“本周录入了多少活动”，可改用 `created_at`。
- 周报中必须写清楚使用 `start_time` 还是 `created_at`。

### 活跃成员

一句话说明：活跃成员是本周至少完成 1 次签到的成员。

```sql
SELECT
    m.id AS member_id,
    m.name,
    COUNT(DISTINCT att.activity_id) AS signed_in_count
FROM attendances att
JOIN members m ON m.id = att.member_id
JOIN activities a ON a.id = att.activity_id
WHERE att.status = 'signed_in'
  AND date(a.start_time) BETWEEN :week_start AND :week_end
GROUP BY m.id, m.name
ORDER BY signed_in_count DESC, m.id ASC;
```

注意事项：

- `absent` 不算活跃成员。
- 同一成员同一活动只有一条签到记录。
- 如果只报名未签到，不计入活跃成员。

### 总跑量

一句话说明：总跑量是本周已签到活动距离的累计值。

```sql
SELECT
    COALESCE(SUM(COALESCE(a.distance_km, 0)), 0) AS total_distance_km
FROM attendances att
JOIN activities a ON a.id = att.activity_id
WHERE att.status = 'signed_in'
  AND date(a.start_time) BETWEEN :week_start AND :week_end;
```

注意事项：

- 活动距离为空时按 0 公里处理。
- 如果 10 人签到同一场 8 公里活动，总跑量按 80 公里计算。
- 如果要统计“路线里程”，则每场活动只算一次距离。

### 导入失败原因 Top 3

一句话说明：导入失败原因来自导入向导的 `errors` 和解析错误。

可复用的原因归类：

| 原始信号 | 周报原因 | 建议动作 |
|---|---|---|
| `missing_fields` 包含 `duration_seconds` | 缺少运动时长 | 补齐运动时长字段 |
| `missing_fields` 包含 `start_time` | 缺少开始时间 | 使用 ISO 8601 时间或可识别日期列 |
| `duplicate_reason = 活动已存在` | 活动已存在 | 人工确认是否跳过 |
| `detail = 无法解析 JSON 内容` | JSON 格式错误 | 修正 JSON 后重试 |
| `detail = 无法解析 CSV 表头` | CSV 表头错误 | 确认第一行是表头 |
| `source must be one of` | 数据来源不支持 | 改用支持的数据来源 |

### 异常数据提醒

一句话说明：异常数据提醒告诉管理员哪些数据需要人工确认。

建议第一版检查以下项目：

| 异常 | 判断条件 | 处理建议 |
|---|---|---|
| 报名未签到 | `registered` 但无 `signed_in` | 询问成员或补录缺席 |
| 签到缺少报名 | 有签到但无报名记录 | 标记为现场补录或补齐报名 |
| 距离为空 | `distance_km IS NULL` | 补齐活动距离 |
| 缺少运动时长 | 导入缺少 `duration_seconds` | 补齐后再导入 |
| 疑似重复活动 | `duplicate = true` | 确认是否跳过 |

## 注意事项

- 周报默认用活动开始时间 `start_time` 作为本周归属口径。
- 总跑量只统计已签到成员，不统计只报名未签到成员。
- 导入向导当前只返回预览、缺失字段、错误和重复数。
- 当前核心 schema 没有活动状态字段，无法自动排除已取消活动。
- 当前核心 schema 没有反馈表，周报不要编造成员满意度或评分。
- 如果同一活动多人签到，总跑量按“人数 × 活动距离”累计。
- 如果只想看路线规模，应另算“活动路线总里程”。
- 手机号属于敏感信息，不应出现在运营周报中。
- 管理员复制周报到公开位置前，应删除内部任务 ID 和调试路径。
