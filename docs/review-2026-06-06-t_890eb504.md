# 代码审查报告

任务：t_890eb504
范围：深技大风格活动瀑布流、空闲 worker 推荐/任务看板、任务导入相关前后端接口。

## 严重（必须修）
- [frontend/activity-waterfall.js:110] 活动瀑布流直接请求 `/api/v1/activities`，但后端 `backend/routes/activities.py:13` 该接口依赖 `get_current_user` 鉴权；当前请求没有带 `Authorization`，真实联调时会稳定 401 并落入本地示例数据，前端看似可用但永远不展示后端活动。→ 建议：复用 `createApiClient` 并从登录态注入 token，例如 `fetch(API_URL, { headers: { Accept: 'application/json', Authorization: \`Bearer ${token}\` } })`；如果活动瀑布流确实应公开展示，则后端拆出只读公开接口并明确返回字段契约。
- [frontend/app.js:204] 前端任务板调用 `/api/v1/task-queue/tasks`，但后端路由只注册了 `/api/v1/task-queue/workers`、`/api/v1/workspaces/tasks`、`/api/v1/workspaces/tasks/items`，仓库内没有任何 `/api/v1/task-queue/tasks` 实现；空闲 worker 推荐弹层 `frontend/worker-recommendation-modal.js:58` 也依赖同一不存在接口，联调时会全部进入本地 fallback。→ 建议：要么新增 `GET /api/v1/task-queue/tasks`，返回 `{data:[{id,title,assignee,status,priority,workspace,created_at,updated_at}]}`；要么把前端统一改为已存在的 `/api/v1/workspaces/tasks?workspace=current`，并同步 `frontend/api.js:575-576` 的客户端方法。
- [backend/task_import.py:169-171] 批量导入只执行 `SELECT 1`，没有把校验后的任务写入 `workspace_tasks` 或任何任务表；导入向导会收到 `count/items` 成功响应，但后续任务板、瀑布流创建任务入口无法查到导入结果。→ 建议：在循环校验后调用现有 `upsert_workspace_task_item(...)` 或等价 repository 写入，并把 `description` 放入 `metadata`；失败时返回 4xx，不要返回“导入成功”。

## 中等（应该修）
- [backend/task_import.py:14] 导入状态允许 `doing`，但 `backend/repository.py:155` 的 `workspace_tasks.status` 约束只允许 `todo/ready/running/blocked/done/archived`；一旦按建议真正落库，`doing` 会触发数据库约束错误，前端又在多处把 `doing` 映射为 `running`，字段语义不一致。→ 建议：导入阶段统一规范化：`normalized_status = 'running' if status == 'doing' else status`，并将允许集改为 `{'todo','running','done'}` 或直接复用工作区状态枚举。
- [backend/routes/workspaces.py:73] `GET /api/v1/workspaces/tasks` 只要求登录，未做 `admin_or_leader` 或角色判断；普通成员可以传 `workspace_path` 查看共享工作区任务列表，与任务要求的“导入接口/任务面板后续联调”权限边界不一致，也与其他 worker 接口只允许 admin/leader 的做法不一致。→ 建议：在读取工作区任务、任务项、worker board、推荐摘要前统一调用 `admin_or_leader(current_user)`；至少对 `workspace_path` 显式限制为当前项目根并拒绝普通成员。
- [backend/app.py:21] 模块加载时已经 `register_routes(app)`，启动事件 `backend/app.py:143-148` 又再次注册同一批 router；FastAPI 会出现重复路由/重复 OpenAPI operation，且当后续新增导入向导路由时可能被先注册的同路径处理函数遮蔽，导致联调命中旧逻辑。→ 建议：只保留一次路由注册；通常保留模块级注册，startup 只做 `initialize_database()`，或增加幂等标记 `if not getattr(app.state, 'routes_registered', False): ...`。
- [frontend/activity-waterfall.js:101-104] `bindEvents()` 对 `dom.search/dom.sort/dom.refresh` 直接调用 `addEventListener`，只要导入向导页面复用脚本但不包含活动瀑布流完整 DOM，脚本会在初始化阶段抛错，阻断后续导入向导脚本执行。→ 建议：和其他模块一样使用可选绑定：`dom.search?.addEventListener(...)`，并在 `initActivityWaterfall()` 中检测 `dom.list` 不存在时直接 return。

## 建议（可以修）
- [frontend/activity-waterfall.js:133] `distanceKm: Number(...)` 没有处理 `NaN`，后续 `frontend/activity-waterfall.js:280` 调 `item.distanceKm.toFixed(1)`；如果后端导入数据把距离字段传成空字符串、`"未知"` 或其他非数字文本，卡片渲染会直接抛错。→ 建议：增加安全转换函数：`const distance = Number(value); distanceKm: Number.isFinite(distance) ? distance : 0`，并对异常值显示“距离待补充”。
- [frontend/activity-waterfall.js:306] “创建任务”按钮跳转到 `/tasks/create?...`，当前后端没有页面路由或创建接口与这个路径对应；在静态部署或 FastAPI 部署下会 404，且不会把活动字段带入导入向导。→ 建议：改为已存在的导入/创建入口路径，或直接 POST 到任务创建 API；至少把目标路径集中成常量并在文档/路由中保持一致。

## 不需要修但值得注意
- `frontend/index.html:441-446` 文案声明字段兼容 `cover_url`，但 `frontend/activity-waterfall.js:126-142` 实际没有使用 `cover_url` 渲染封面，只使用渐变背景。若后续设计期望活动封面真实展示，需要补上 `coverImage` 映射和 CSS 变量赋值。
- `backend/models.py:6` 导入了 `field_validator` 但当前文件未使用；这不是联调阻塞问题，但容易误导后续读代码的人以为已有自定义校验。
