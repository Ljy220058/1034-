# 只读任务日志巡检脚本

## 目标

`scripts/readonly_task_log_inspector.sh` 用于快速巡检最近 Hermes Kanban worker 的失败原因。脚本只读取当前工作区、看板数据库中的任务记录、运行记录、最近事件和评论，不修改任务状态，不杀进程，不启动长驻服务。

## 一条命令运行

在项目根目录执行：

```bash
scripts/readonly_task_log_inspector.sh t_0f23ae55
```

如果当前 shell 已经设置 `HERMES_KANBAN_TASK`，可以不传任务编号：

```bash
scripts/readonly_task_log_inspector.sh
```

## 读取来源

脚本按以下顺序读取信息：

1. `HERMES_KANBAN_DB` 指向的 SQLite 看板数据库，使用 `mode=ro` 只读连接。
2. `tasks` 表：任务编号、负责人、状态、工作区、连续失败次数、最近失败摘要。
3. `task_runs` 表：最近运行记录、结果、错误、元数据。
4. `task_events` 表：最近事件，例如 `crashed`、`gave_up`、`protocol_violation`。
5. `task_comments` 表：最近评论。
6. 当前工作区中的 `logs/`、`.logs/`、`tmp/`、`var/log/` 以及根目录下的 `*.log`、`*.out`、`*.err` 文件，仅输出文件路径、大小、修改时间和末尾片段。

## 报告内容

输出报告为中文，包含：

- 任务编号
- 标题
- 负责人
- 状态
- 当前运行编号
- 连续失败次数
- 最近运行失败摘要
- 最近事件
- 最近错误片段
- 最近评论
- 工作区日志线索
- 建议下一步

## 常用参数

通过环境变量调整输出数量：

```bash
KANBAN_INSPECT_RUN_LIMIT=20 \
KANBAN_INSPECT_EVENT_LIMIT=50 \
KANBAN_INSPECT_LOG_LIMIT=10 \
scripts/readonly_task_log_inspector.sh t_0f23ae55
```

可显式指定数据库和工作区：

```bash
HERMES_KANBAN_DB=/root/.hermes/kanban.db \
HERMES_KANBAN_WORKSPACE=/root/autodl-tmp/projects/hermes-swarm-lab \
scripts/readonly_task_log_inspector.sh t_0f23ae55
```

## 缺少日志或命令时的处理

- 缺少任务编号：报告会提示传入 `scripts/readonly_task_log_inspector.sh <任务编号>` 或设置 `HERMES_KANBAN_TASK`。
- 缺少看板数据库：报告会提示设置 `HERMES_KANBAN_DB=/root/.hermes/kanban.db`。
- 数据库不是 Hermes Kanban 数据库：报告会提示确认表结构。
- 工作区没有日志文件：报告会提示到 Hermes 会话日志目录按 `run_id` 或任务编号检索，或让自定义 worker 将短生命周期日志输出到工作区 `logs/` 目录。

## 只读保证

脚本不会执行以下操作：

- 不调用 `kanban_complete`、`kanban_block`、`kanban_comment` 等状态写入命令。
- 不更新 SQLite 表。
- 不杀进程。
- 不启动 daemon、server、watcher 等长驻服务。

只读连接写法为：

```python
sqlite3.connect(f"file:{path}?mode=ro", uri=True)
```

## 验证命令

```bash
bash -n scripts/readonly_task_log_inspector.sh
scripts/readonly_task_log_inspector.sh t_0f23ae55
HERMES_KANBAN_DB=/tmp/不存在.db scripts/readonly_task_log_inspector.sh t_0f23ae55 || true
```

验收时重点确认：报告为中文、运行一次快速退出、数据库缺失时给出可执行提示。
