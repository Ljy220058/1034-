# 空闲工作者创意分配速查表

适用工作区：`/root/autodl-tmp/projects/hermes-swarm-lab`

用途：供中文创意生成 cron 在发现空闲 worker 时快速判断“该给谁生成什么类型的 kanban 任务”。本速查表只提供分配参考和任务模板，不修改线上调度配置，不启动长耗时实现。

## 一、总原则

1. 先判断 worker 的职责边界，再生成任务，不要因为某个 worker 空闲就把不匹配的实现任务塞给它。
2. 实现类任务优先给 `backend-dev`、`frontend-dev`、`test-engineer`、`data-modeler`；审查、验收、整理类任务分别给专门角色。
3. `quality-gate` 偏验收、抽检、冒烟、质量门禁，不应接收新功能实现任务。
4. `code-reviewer` 偏风险审查、代码评审、安全和可维护性判断，不应接收普通功能开发任务。
5. `default` 只接收轻量整理、模板、索引、速查表、低风险中文文档任务，不接收需要改核心代码、跑长测试或做线上配置的任务。
6. 每次生成前检查近期 kanban 与 `docs/`、`tests/`、`backend/`、`frontend/` 中是否已有同主题产物，避免重复。

## 二、角色分配速查表

| worker | 适配任务类型 | 不适合任务类型 | 推荐交付物 |
|---|---|---|---|
| `backend-dev` | 后端接口、路由、数据处理服务、权限与错误处理实现 | 纯 UI 设计、最终验收抽检、风险审查报告 | `backend/routes/*.py`、`backend/*.py`、`tests/test_*.py`、`docs/*接口*.md` |
| `frontend-dev` | 页面入口、交互状态、前端轻量实现、前端错误提示 | 后端数据建模、代码风险审查、质量门禁终审 | `frontend/*.html/js/css`、`docs/*前端*.md`、前端验收清单 |
| `test-engineer` | 自动化测试、冒烟脚本、回归用例、失败提示验证 | 产品方案撰写、功能实现主任务、风险审批 | `tests/test_*.py`、`docs/*测试*.md`、`docs/*冒烟*.md` |
| `docs-writer` | 用户文档、方案说明、规格整理、操作指南 | 直接改业务代码、深度安全审查、数据库迁移实现 | `docs/*.md` |
| `code-reviewer` | 风险审查、代码评审、安全边界、可维护性和阻塞问题判断 | 新功能实现、普通文案整理、验收抽检主任务 | `docs/*评审*.md`、`docs/*风险审查*.md`、评审结论 |
| `quality-gate` | 验收、抽检、质量门禁、发布前检查、复测记录 | 新功能实现、架构方案主笔、普通代码评审替代 | `docs/*质量门禁*.md`、`docs/*验收*.md`、抽检记录 |
| `data-modeler` | 数据结构、字段口径、迁移草案、指标模型、数据契约 | 页面视觉实现、最终验收、泛文档整理 | `docs/*数据契约*.md`、`migrations/*.sql`、`backend/*model*.py` |
| `idea-scout` | 创意挖掘、任务选题、去重筛选、候选任务池 | 具体实现、验收终审、代码安全审批 | `docs/*创意*.md`、候选任务 JSON/Markdown |
| `unblocker` | 阻塞任务梳理、缺口补充、依赖关系清点、人工决策问题归纳 | 越权替别人完成实现、无授权改线上配置 | `docs/*阻塞梳理*.md`、任务解阻建议 |
| `default` | 轻量整理、模板、速查表、索引、已有资料摘要 | 核心代码实现、长耗时测试、线上调度配置修改、风险终审 | `docs/*速查表*.md`、`docs/*模板*.md`、轻量 JSON |

## 三、各角色任务模板

### 1. backend-dev

适配任务类型：后端接口实现、业务服务补充、数据读取/写入逻辑、权限与错误处理。

中文任务标题模板：

- `中文创意：{功能名称}后端接口实现`
- `补充{业务对象}{处理动作}服务与错误处理`

描述必填字段：

- 业务场景：说明接口服务于谁、解决什么问题。
- 接口路径或服务入口：例如 `GET /api/...` 或 `backend/routes/...`。
- 请求字段：字段名、类型、是否必填、默认值。
- 返回字段：成功返回、失败返回、空状态返回。
- 权限边界：登录、角色、资源归属或匿名访问要求。
- 验收方式：最小测试命令、手动调用示例或文档检查点。
- 目标产物路径：代码文件、测试文件或接口说明文档。

避免重复检查点：

- 是否已有相同接口路径、同名路由或同主题后端任务。
- 是否只是补测试；如果是，应分配给 `test-engineer`。
- 是否与当前进行中的后端任务修改同一个文件，导致冲突。
- 是否缺少字段口径；若缺少，应先给 `data-modeler` 建数据契约任务。

### 2. frontend-dev

适配任务类型：页面入口、交互状态、前端轻量实现、用户可见错误提示、前端验收清单。

中文任务标题模板：

- `中文创意：{页面或模块}前端体验优化`
- `实现{用户动作}入口与状态提示`

描述必填字段：

- 页面或模块：具体到页面、卡片、按钮、列表或弹窗。
- 目标用户：管理员、普通成员、访客等。
- 入口位置：从哪里进入、哪个按钮触发。
- 交互状态：默认、加载中、成功、空状态、错误状态。
- 数据来源：接口、静态示例、已有文档或 mock 数据。
- 验收方式：打开路径、操作步骤、预期可见文案。
- 目标产物路径：`frontend/` 文件或 `docs/` 前端规范。

避免重复检查点：

- 是否已有同页面、同入口、同交互状态任务。
- 是否只是审查旧页面；如果是，应给 `code-reviewer` 或 `quality-gate`。
- 是否依赖尚不存在的后端接口；若依赖缺失，应先拆给 `backend-dev`。
- 是否与近期前端任务重复同一个主题词和产物路径。

### 3. test-engineer

适配任务类型：自动化测试、冒烟脚本、回归用例、失败提示校验、边界输入测试。

中文任务标题模板：

- `中文创意：{被测对象}自动化回归测试`
- `建立{功能名称}冒烟用例与复测命令`

描述必填字段：

- 被测对象：接口、页面、脚本、数据契约或文档流程。
- 测试范围：成功路径、失败路径、边界输入、权限场景。
- 前置条件：依赖数据、mock、环境变量或已有实现。
- 用例清单：至少列出 3 个最小用例。
- 失败提示要求：失败时应输出哪些中文定位信息。
- 复测命令：例如 `pytest tests/test_xxx.py`。
- 目标产物路径：测试文件或测试说明文档。

避免重复检查点：

- 是否已有同名 `tests/test_*.py` 或同对象验收清单。
- 是否上游实现尚不存在；若不存在，先不要创建测试实现任务。
- 是否把质量门禁抽检任务误写成完整测试开发任务。
- 是否与同批次其他测试任务覆盖完全相同场景。

### 4. docs-writer

适配任务类型：产品说明、用户指南、方案文档、规格整理、变更说明、操作流程。

中文任务标题模板：

- `中文创意：{主题}方案说明文档`
- `整理{功能名称}用户操作指南`

描述必填字段：

- 目标读者：开发者、测试者、管理员、普通用户或 reviewer。
- 文档目的：用于实现、验收、培训、交接还是决策。
- 必含章节：背景、目标、流程、字段、异常、验收等。
- 参考资料：已有文档、代码路径、任务卡或外部约束。
- 与已有文档关系：新增、补充、合并或替代。
- 目标产物路径：唯一的 `docs/*.md`。
- 最小验收步骤：如何确认章节完整且可执行。

避免重复检查点：

- 是否已有同主题文档，只是换标题重写。
- 是否目标产物路径已存在且内容相近。
- 是否文档其实需要先由实现或数据角色产出事实依据。
- 是否把评审、质量门禁结论伪装成普通说明文。

### 5. code-reviewer

适配任务类型：风险审查、代码评审、安全边界、权限检查、可维护性和回归风险判断。

中文任务标题模板：

- `风险审查：{审查对象}代码变更`
- `复核{功能名称}权限与可维护性风险`

描述必填字段：

- 审查对象：文件、目录、PR、任务产物或变更说明。
- 审查范围：安全、权限、数据一致性、错误处理、回归风险。
- 风险分级：高、中、低或阻塞/非阻塞。
- 证据格式：文件路径、行号、触发条件、影响说明。
- 整改建议格式：每条发现对应一个可执行修复建议。
- 不改代码声明：默认只审查；如需修复，应另建下游任务。
- 目标产物路径：评审报告或 kanban 评论。

避免重复检查点：

- 是否已有同对象评审报告或 reviewer 评论。
- 是否审查对象尚未完成；若未完成，应等待上游任务。
- 是否把“实现缺失”误分给 code-reviewer；实现应给开发角色。
- 是否与 `quality-gate` 的验收抽检重复；code-reviewer 关注风险，不替代验收。

### 6. quality-gate

适配任务类型：验收、抽检、发布前质量门禁、复测记录、质量标准一致性检查。

中文任务标题模板：

- `质量门禁：{功能名称}验收抽检`
- `复测{交付物名称}并输出质量结论`

描述必填字段：

- 验收对象：代码、文档、测试、接口、页面或任务交付物。
- 验收标准来源：任务卡、文档、测试文件、用户要求。
- 抽检范围：必须覆盖和可选覆盖的检查点。
- 复测命令或手动步骤：能在短时间内执行的验证方法。
- 通过/不通过判定：明确阻塞项和非阻塞建议。
- 证据格式：命令输出摘要、文件路径、截图描述或清单勾选。
- 目标产物路径：质量门禁报告。

避免重复检查点：

- 是否已有同交付物质量门禁或验收报告。
- 是否任务其实是新实现；新实现不得分给 `quality-gate`。
- 是否抽检对象没有明确验收标准；缺标准时应先给 `docs-writer` 或上游补充。
- 是否与 code-reviewer 重叠：`quality-gate` 看是否达标，`code-reviewer` 看风险与可维护性。

### 7. data-modeler

适配任务类型：字段口径、数据契约、指标定义、迁移草案、数据质量规则、实体关系说明。

中文任务标题模板：

- `中文创意：{数据对象}数据契约定义`
- `设计{指标名称}字段口径与样例数据`

描述必填字段：

- 数据对象：表、实体、事件、指标或导入记录。
- 字段列表：字段名、类型、必填性、默认值、枚举值。
- 数据来源：用户输入、接口、文件、第三方系统或派生计算。
- 约束规则：唯一性、范围、格式、缺失处理。
- 示例数据：至少包含正常、缺失、异常三类样例。
- 下游使用者：后端、前端、测试、分析或文档。
- 目标产物路径：数据契约文档、迁移草案或模型文件。

避免重复检查点：

- 是否已有同数据对象的数据契约或迁移脚本。
- 是否只是接口实现，不需要新增字段口径；若是，应给 `backend-dev`。
- 是否字段定义会影响现有迁移，需要明确是草案还是可执行 SQL。
- 是否缺少下游使用场景，导致模型过度设计。

### 8. idea-scout

适配任务类型：创意挖掘、候选任务池、主题去重、空闲 worker 选题建议、轻量竞品/历史任务扫描。

中文任务标题模板：

- `整理{主题范围}中文创意候选任务池`
- `扫描近期任务并提出{数量}个不重复创意选题`

描述必填字段：

- 扫描范围：近期 kanban、`docs/`、代码目录或指定主题。
- 输出数量：候选任务数量和优先级建议。
- 去重规则：同主题、同产物、同 worker、同批次限制。
- 目标 worker：每个候选任务建议分给谁。
- 候选卡格式：标题、assignee、body 摘要、产物路径、验收标准。
- 排除主题：明确近期已做或不希望重复的主题。
- 目标产物路径：候选任务池 Markdown 或 JSON。

避免重复检查点：

- 是否只是把已有任务标题改写一遍。
- 是否候选任务无法落到具体 worker。
- 是否给审查或质量角色生成了实现任务。
- 是否缺少产物路径，导致后续创建卡时冲突。

### 9. unblocker

适配任务类型：阻塞任务梳理、缺失信息归纳、依赖关系检查、需要人工决策的问题提炼。

中文任务标题模板：

- `梳理{任务组或功能}阻塞原因与解阻路径`
- `汇总{被阻塞对象}缺失信息和下一步决策`

描述必填字段：

- 被阻塞对象：任务 id、功能、交付物或依赖链。
- 当前状态：blocked、ready、running、待评审等。
- 阻塞原因：缺权限、缺需求、缺上游产物、测试失败、冲突等。
- 所需决策：给人类或上游 worker 的具体问题。
- 建议下一步：解阻后应分配给哪个 worker。
- 证据来源：任务评论、文件路径、测试输出或文档链接。
- 目标产物路径：阻塞梳理文档或 kanban 评论。

避免重复检查点：

- 是否已有 unblocker 对同一阻塞对象做过梳理。
- 是否可以直接由上游 worker 继续，而不需要单独解阻任务。
- 是否把 unblocker 变成“代替实现”的角色。
- 是否问题描述过宽，无法让人类快速回答。

### 10. default

适配任务类型：轻量整理、速查表、模板库、索引、摘要、已有材料归纳、低风险中文文档。

中文任务标题模板：

- `整理{主题}轻量速查表`
- `建立{用途}中文模板索引`

描述必填字段：

- 整理对象：已有文档、任务模式、模板、角色边界或示例集合。
- 输出形式：Markdown、JSON、表格或索引。
- 覆盖范围：必须包含哪些角色、文件、主题或字段。
- 不做事项：不改线上配置、不做长耗时实现、不修改核心业务代码。
- 示例要求：至少给出一组可复用示例。
- 目标产物路径：唯一的文档或轻量 JSON。
- 验收方式：中文完整性、路径清晰、可供下一轮 cron 参考。

避免重复检查点：

- 是否已有相同速查表、模板库或索引。
- 是否任务需要实际实现；如需要，应分配给专业开发或测试角色。
- 是否需要长耗时命令、联网调研或人工审批；如需要，不适合 `default`。
- 是否只是重复复制已有文档而没有新增结构化整理价值。

## 四、quality-gate、code-reviewer、default 的边界提醒

### quality-gate：验收与抽检优先

`quality-gate` 适合在上游已有交付物之后做短周期验收，例如检查文档是否满足任务要求、测试是否能跑通、接口返回是否符合约定。它不应承担新增接口、重构前端、设计数据模型等实现类任务。

可分配：`质量门禁：训练完成复盘卡片验收抽检`

不应分配：`实现训练完成复盘卡片后端接口`

### code-reviewer：风险审查优先

`code-reviewer` 关注变更是否安全、可维护、权限边界是否清楚、是否存在阻塞风险。它可以指出问题和建议下游修复，但不应替代 `backend-dev`、`frontend-dev` 或 `test-engineer` 做实现。

可分配：`风险审查：活动报名接口权限与错误处理`

不应分配：`新增活动报名接口并补齐数据库迁移`

### default：轻量整理或模板任务

`default` 适合接收低风险、短周期、中文整理类任务，例如速查表、模板索引、已有文档摘要。它不应接收核心代码改动、线上调度配置、长耗时测试或需要专业审查结论的任务。

可分配：`整理空闲工作者创意分配速查表`

不应分配：`实现中文创意生成 cron 的线上调度策略`

## 五、空闲 worker 到任务类型的快速选择规则

1. 空闲的是 `backend-dev`：优先生成后端接口、服务逻辑、错误处理任务；若缺字段，先生成 `data-modeler` 上游任务。
2. 空闲的是 `frontend-dev`：优先生成页面入口、状态展示、交互优化任务；若缺接口，先让 `backend-dev` 补接口。
3. 空闲的是 `test-engineer`：优先生成测试用例、复测命令、失败提示验证任务；不要让它写产品方案。
4. 空闲的是 `docs-writer`：优先生成方案、指南、规格整理任务；不要让它做最终质量裁决。
5. 空闲的是 `code-reviewer`：优先生成风险审查任务；必须有明确审查对象。
6. 空闲的是 `quality-gate`：优先生成验收抽检任务；必须有明确验收标准和交付物。
7. 空闲的是 `data-modeler`：优先生成字段、指标、数据契约任务；避免让它做纯页面文案。
8. 空闲的是 `idea-scout`：优先生成候选任务池和去重扫描；不要让它直接实现候选任务。
9. 空闲的是 `unblocker`：优先生成阻塞梳理和依赖清点；不要让它绕过人工决策。
10. 空闲的是 `default`：只生成轻量整理、模板、索引、速查表任务。

## 六、示例：quality-gate 与 default 较空闲时应生成什么任务

输入假设：


## 七、创建任务前最小检查清单

1. 检查目标 worker 是否真的适配该任务类型。
2. 检查标题是否能一眼看出任务性质，例如“实现”“验收”“评审”“整理”“梳理”。
3. 检查描述是否包含目标、具体要求、交付物、验收标准。
4. 检查目标产物路径是否唯一且清晰。
5. 检查 `quality-gate`、`code-reviewer`、`default` 没有被分配实现类任务。
6. 检查任务是否会重复近期已完成、进行中或阻塞的同主题卡片。
7. 检查是否需要上游事实依据；如果需要，先创建上游任务而不是让当前 worker 猜测。
