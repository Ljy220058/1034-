## 三、根因之间的依赖关系

```text
P0 后端导入链 / repository 漂移
  ├─ 阻断 pytest 收集
  │   ├─ 阻断 QA 通过
  │   ├─ 阻断代码审查闭环
  │   └─ 阻断前后端功能验证
  ├─ 派生大量重复修复任务
  │   ├─ todo 子任务依赖父任务，无法自然推进
  │   └─ backend-dev 队列拥塞
  └─ 掩盖真实业务缺陷
      ├─ auth 权限模型问题无法被稳定验证
      ├─ worker board / task board 接口无法稳定验证
      └─ 批量导入与任务持久化问题被反复重提
```

结论：当前不是单个任务阻塞，而是“后端基础导入链断裂 + 任务重复派生 + 质量门循环退回”的系统性阻塞。

## 七、解封建议

1. 不建议继续把所有 triage 任务机械重建为新任务；当前核心问题会导致重建后继续失败。
2. 最先应解的是 P0 主线：后端导入链、repository 符号对齐、pytest collection。
3. 所有依赖“补充看板空闲探测与分配规则”的 todo 子任务应等待父任务或主线修复完成后再执行，避免并行冲突。
4. 对已完成但 review-required 的文档类任务，可以由质量门直接复核并完成；不要继续派生泛化修复任务。
5. 对前端和数据模型任务，先保留现状，待后端 API 稳定后一次性验证，避免把后端失败误判为前端失败。

## 八、最终判断

当前看板最大根因是：后端基础导入链断裂造成全局测试无法收集，随后质量门与审查流程不断派生重复修复任务，导致 backend-dev 队列拥塞，并进一步拖累 worker board、task board、auth、安全、前端联调等模块。

最高收益动作是：集中修复 `backend.repository` 与 `backend/routes/*` 的接口漂移，让 `import backend` 和 pytest collection 先恢复；随后再逐层处理 QA、审查、权限、前端联调和 worker 协议治理。
