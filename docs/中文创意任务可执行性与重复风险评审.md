## 风险清单

### 1. 疑似重复或强相关任务
- `建立重复创意拦截评审规则`、`中文创意库去重与趋势标签器`、`建立中文创意任务验收模板库`、本任务都围绕“中文创意任务质量/去重/验收”。如果并行推进，容易产出多份互相覆盖的规则文档。建议：后续只保留一个主规则文档，其他任务必须在正文写明“评审/实现/模板化/复用”的上下游关系。
- `增加跑步数据导入授权预检面板` 与 `跑步数据导入隐私与授权审计` 同属导入授权隐私主题。建议：前者限定为预检接口/面板实现，后者限定为审计清单，不要都输出“隐私边界说明”。
- `设计活动数据异常趋势雷达图模型` 与 `设计跑步活动数据质量评分模型` 都涉及活动异常/质量评分。建议：雷达图任务只定义前端维度数组与趋势展示契约，质量评分任务负责底层评分输入与分值计算。
- `建立跑团功能路线图与任务入口文档` 与 `整理活动瀑布流与数据导入的联调手册` 都可能整理导入、瀑布流、质量门禁方向。建议：路线图只做优先级和依赖；联调手册只做字段、接口、错误码检查。
- `后端创意卡片批量路由器` 与 `实现任务分配优先级路由器` 都涉及任务路由/分配。建议：前者面向创意任务批量导入与去重，后者面向 worker 空闲度与优先级派发。

### 2. 范围过大的任务类型
- “路线图/入口文档”类任务容易同时覆盖会员数据、活动展示、导入向导、运营诊断和看板协作，若没有限定每组最多条目和验收口径，会变成大而全综述。
- “模板库/规则库/标签器”类任务容易同时要求扫描看板、提取标签、去重、输出 JSON/Markdown、指导下一轮生成，实际跨越数据分析、规则设计和实现。
- “前端面板/导航面板”类任务如果只写“支持筛选、排序、状态切换、空状态、加载态”，但不指定数据来源和最小页面，会导致实现范围膨胀。
- “安全/隐私/授权”类任务如果同时要求梳理接口、前端入口、模型、越权、token、文件校验和错误泄露，应该拆成审计任务和修复任务。

### 3. 验收标准不清的任务类型
- 只写“输出 Markdown 或 JSON 文件”的文档任务：缺少文件路径、章节数量、复用方式。
- 只写“不要阻塞正在运行任务”的调度任务：缺少如何证明未阻塞、是否只读、是否会创建/归档任务。
- 只写“提供最小验证方式”的实现任务：缺少具体命令、预期输出、失败样例。
- 只写“适合前端调用/可被后端复用”的接口/模型任务：缺少请求响应字段、错误码、示例 payload。

## 5 条中文创意任务创建检查规则

1. **先查 20 条近期任务再创建**：如果同一工作区内存在运行中/待办/阻塞的同主题任务，新任务必须改成明确的“评审、补充、实现、测试、修复”之一，并在正文引用上游任务或产物路径。
2. **正文必须写清三件事**：目标、交付物路径/接口/组件、验收方式；缺任一项时不要派发给 worker。
3. **同主题拆边界**：同一主题下“文档/规则”“后端实现”“前端面板”“测试/审计”必须分给不同任务，并写清不做的范围，避免两个 worker 同时改同一产物。
4. **验收标准必须可执行**：每个任务至少包含一个命令、一个接口调用、一个页面检查步骤或一个示例输出；不能只写“补充说明”“优化体验”。
5. **强制标明新增价值**：如果标题含“创意、去重、模板、路线图、联调、导入、瀑布流、质量评分”等近期高频词，正文必须说明它相对已有任务/文档新增什么，否则跳过创建或改为评论建议。
