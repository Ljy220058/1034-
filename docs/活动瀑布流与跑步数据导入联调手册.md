# 活动瀑布流与跑步数据导入联调手册

## 概述

本手册说明活动瀑布流页面如何消费活动列表，并说明跑步数据导入向导如何把 CSV（Comma-Separated Values，逗号分隔值文件）或 JSON（JavaScript Object Notation，数据交换格式）解析为活动预览。

适用对象：前端、后端、QA（Quality Assurance，质量保障）和移动端联调同学。

代码来源：

- 活动瀑布流前端：`frontend/activity-waterfall.js`
- 活动接口路由：`backend/routes/activities.py`
- 活动数据模型：`backend/models.py`
- 活动存储模型：`backend/activity_registration_risk.py`
- 导入接口路由：`backend/routes/running_data_imports.py`
- 数据质量预检模型：`backend/running_data_anomaly_precheck.py`
- 导入错误文案规则：`backend/import_error_copy.py`

## 快速开始

在本地服务启动后，先确认登录态，再按下面顺序联调。

```bash
# 准备身份令牌。把示例值替换为登录接口返回的 JWT。
AUTH_HEADER='Authorization: Bearer your-jwt-token'

# 1. 读取活动瀑布流数据源
curl -i -H "Accept: application/json" \
  -H "$AUTH_HEADER" \
  http://localhost:8000/api/v1/activities

# 2. 查看跑步数据导入预检
curl -i -H "Accept: application/json" \
  -H "$AUTH_HEADER" \
  "http://localhost:8000/api/v1/running-data-imports/precheck?source=generic"

# 3. 用 JSON 样例跑导入向导
curl -i -X POST http://localhost:8000/api/v1/running-data-imports/wizard \
  -H "Content-Type: application/json" \
  -H "$AUTH_HEADER" \
  -d '{"source":"generic","format":"json","content":"[{\"title\":\"校园夜跑接力\",\"start_time\":\"2026-06-01T20:00:00\",\"distance_km\":8.4,\"duration_seconds\":2671,\"location\":\"西丽湖\",\"gps_track\":\"22.59,113.99;22.60,114.00\"}]"}'

# 4. 跑数据质量异常预检
curl -i -X POST http://localhost:8000/api/v1/running-data-imports/anomaly-precheck \
  -H "Content-Type: application/json" \
  -H "$AUTH_HEADER" \
  -d '{"source":"generic","format":"json","content":"[{\"title\":\"校园夜跑接力\",\"start_time\":\"2026-06-01T20:00:00\",\"distance_km\":8.4,\"duration_seconds\":2671,\"location\":\"西丽湖\",\"gps_track\":\"22.59,113.99;22.60,114.00\"}]"}'
```

`AUTH_HEADER` 表示带 JWT（JSON Web Token，身份令牌）的 HTTP Authorization 请求头。未登录请求会被 `get_current_user` 拦截，前端应展示登录提示。

## 一、联调整体流程

### 1. 活动瀑布流读取活动

活动瀑布流通过 `GET /api/v1/activities` 拉取活动列表。

前端会调用 `normalizeActivities(payload)` 兼容三种返回形态：数组、`data` 数组、`items` 数组。

后端当前路由返回 `ApiResponse(data=[...])`，所以前端实际读取 `payload.data`。

### 2. 跑步数据导入向导生成预览

导入向导通过 `POST /api/v1/running-data-imports/wizard` 解析上传内容。

后端会识别字段映射、缺失字段、前 20 行预览、行级错误和重复数量。

当前向导只预览，不写入活动表。

### 3. 数据质量异常预检补充风险信息

异常预检通过 `POST /api/v1/running-data-imports/anomaly-precheck` 返回质量问题。

模型会检查缺失时间、超长距离、空 GPS 点、异常配速和重复轨迹。

前端应把阻断项展示为不可继续导入，把警告和提示展示为可人工确认。

### 4. 瀑布流展示导入结果

真实导入写入尚未闭环，`POST /api/v1/running-data-imports/start` 当前只返回授权确认占位。

后续接入真实写入后，应复用活动接口字段，让导入后的记录能进入活动瀑布流。

## 二、前端活动卡片字段

### 概述

活动卡片字段来自 `frontend/activity-waterfall.js` 的 `normalizeActivities` 和 `renderActivityCard`。

### 字段说明

| 前端字段 | 类型 | 必填 | 来源字段 | 用途 | 缺口 |
|---|---|---:|---|---|---|
| `id` | string/number | 是 | `id` | 点赞、评论按钮定位卡片 | 后端活动接口返回 integer，前端已转字符串比较 |
| `title` | string | 是 | `title`、`name` | 卡片标题和封面主标题 | 导入向导可提供 `title` |
| `type` | string | 否 | `type`、`category`、由 `pace` 推断 | 展示「校园感」「速度训练」「社交约跑」 | 后端活动模型没有 `type` 字段 |
| `coverLabel` | string | 否 | `coverLabel`、`cover_label` | 封面角标 | 后端活动模型没有该字段 |
| `distanceKm` | number | 否 | `distanceKm`、`distance_km`、`distance` | 距离徽章和距离排序 | 后端活动模型有 `distance_km` |
| `pace` | string | 否 | `pace`、`avg_pace` | 配速徽章和配速筛选 | 后端活动模型是 `pace_group`，不是实际配速 |
| `runner` | string | 否 | `runner`、`nickname`、`host` | 头像和发起人展示 | 后端活动模型没有发起人字段 |
| `completed` | number | 否 | `completed`、`completed_count`、`done_count` | 互动热度计算和「最近完成」 | 后端活动模型没有完成人数字段 |
| `reasoning` | string | 否 | `reasoning`、`reason`、`suggestion` | 卡片描述 | 后端可用 `description`，但前端当前未读取 `description` |
| `likes` | number | 否 | `likes`、`like_count` | 热度计算和点赞按钮 | 后端活动模型没有点赞字段 |
| `comments` | number | 否 | `comments`、`comment_count` | 热度计算和评论按钮 | 后端活动模型没有评论字段 |
| `tags` | string[] | 否 | `tags`、`labels` | 标签列表 | 后端活动模型没有标签字段 |
| `coverTone` | string | 否 | `coverTone`、`cover_tone`、`type` | 封面色调和徽章颜色 | 后端活动模型没有该字段 |
| `coverSize` | string | 否 | `coverSize`、`cover_size` | 瀑布流高低卡片 | 后端活动模型没有该字段 |
| `coverUrl` | string | 否 | `coverUrl`、`cover_url`、`cover` | 封面图 | 后端活动模型没有封面字段 |
| `campus` | string | 否 | `campus`、`campus_name`、`location`、`route_area`、`place` | 校区筛选和热力摘要 | 后端活动模型有 `location` |
| `month` | string | 否 | `month`、`activity_month`、`date`、`started_at`、`created_at` | 月份筛选和热力摘要 | 后端活动接口返回 `start_time`，前端当前没有读取 `start_time` |
| `distanceBucket` | string | 否 | 前端按 `distanceKm` 计算 | 距离筛选 | 小于 5K 为 `short`，5-10K 为 `middle`，10K+ 为 `long` |
| `paceBucket` | string | 否 | 前端按 `pace` 计算 | 配速筛选 | 无标准配速时进入 `unknown` |

### 返回示例

活动接口当前返回 `ApiResponse` 包装。

```json
{
  "data": [
    {
      "id": 1,
      "title": "校园夜跑接力",
      "start_time": "2026-06-01T20:00:00",
      "location": "西丽湖",
      "route": "操场外圈",
      "distance_km": 8.4,
      "pace_group": "5'18\"/km",
      "description": "夜间路线安全、补给清晰",
      "max_participants": 30,
      "created_at": "2026-06-01T10:00:00",
      "updated_at": "2026-06-01T10:00:00"
    }
  ],
  "message": "成功"
}
```

### 注意事项

- 前端 `reasoning` 不读取后端 `description`，联调时要确认是否新增兼容映射。
- 前端 `month` 不读取后端 `start_time`，活动月份可能显示「未标注」。
- 前端热度由 `likes + comments + completed` 计算，后端当前没有这些字段。
- 前端按 `pace` 解析 `5'18"/km` 这类字符串，`pace_group` 是否等价需要产品确认。
- 活动接口需要登录，移动端遇到 401 应提示用户重新登录。

## 三、导入状态字段

### 概述

导入状态字段来自预检、授权启动、向导预览和异常预检四个接口。

### 字段说明

| 字段 | 类型 | 必填 | 来源接口 | 说明 | 前端展示建议 |
|---|---|---:|---|---|---|
| `source.id` | string | 是 | `precheck`、`start`、`wizard`、`anomaly-precheck` | 来源平台标识 | 展示为来源平台内部值 |
| `source.name` | string | 是 | `precheck`、`start`、`anomaly-precheck` | 来源平台中文名 | 展示给用户 |
| `authorization_required` | boolean | 是 | `precheck` | 是否需要授权 | 为 true 时展示授权说明 |
| `can_start_import` | boolean | 是 | `precheck` | 当前是否可直接导入 | 当前返回 false |
| `consent_required` | boolean | 是 | `precheck` | 是否必须确认授权 | 为 true 时显示勾选框 |
| `read_fields` | string[] | 是 | `precheck` | 需要读取的第三方字段 | 展示授权范围 |
| `save_location.table` | string | 是 | `precheck` | 计划保存表 | 当前是 `running_data_imports` |
| `save_location.mode` | string | 是 | `precheck` | 保存模式 | 当前是确认前 dry run |
| `revocation.endpoint` | string | 是 | `precheck` | 撤销授权入口 | 当前只返回路径 |
| `privacy_boundary` | object | 是 | `precheck` | 隐私边界 | 强调不保存第三方账号密码 |
| `failure_handling.import_failure` | string | 是 | `precheck` | 失败处理 | 告知失败不写活动记录 |
| `status` | string | 是 | `start` | 启动状态 | 当前是 `authorized_precheck_only` |
| `import_started` | boolean | 是 | `start` | 是否已真实导入 | 当前为 false |
| `next_step` | string | 是 | `start` | 下一步说明 | 前端可作为灰度提示 |
| `input_format` | string | 是 | `wizard`、`anomaly-precheck` | 输入格式 | 值为 `csv` 或 `json` |
| `field_mapping` | object | 是 | `wizard`、`anomaly-precheck` | 标准字段到原始表头的映射 | 展示字段识别结果 |
| `missing_fields` | string[] | 是 | `wizard` | 缺失标准字段 | 有值时提示补齐 |
| `preview` | array | 是 | `wizard` | 预览行 | 最多返回前 20 行 |
| `duplicate_count` | number | 是 | `wizard` | 重复活动数量 | 大于 0 时显示重复提醒 |
| `summary.total_rows` | number | 是 | `anomaly-precheck` | 总行数 | 展示本次检查范围 |
| `summary.anomaly_count` | number | 是 | `anomaly-precheck` | 异常数量 | 展示风险数量 |
| `summary.blocking_count` | number | 是 | `anomaly-precheck` | 阻断数量 | 大于 0 禁止继续导入 |
| `summary.can_import` | boolean | 是 | `anomaly-precheck` | 是否可导入 | false 时展示阻断项 |
| `anomalies` | array | 是 | `anomaly-precheck` | 异常明细 | 按行号展示 |

```json
{
  "data": {
    "source": { "id": "generic", "name": "通用" },
    "input_format": "json",
    "field_mapping": {
      "title": "title",
      "start_time": "start_time",
      "distance_km": "distance_km",
      "duration_seconds": "duration_seconds",
      "location": "location",
      "gps_track": "gps_track"
    },
    "missing_fields": [],
    "preview": [
      {
        "row_number": 1,
        "title": "校园夜跑接力",
        "start_time": "2026-06-01T20:00:00",
        "distance_km": 8.4,
        "duration_seconds": 2671,
        "location": "西丽湖",
        "duplicate": false,
        "duplicate_reason": null
      }
    ],
```

### 注意事项

- `wizard` 的 `preview` 是导入预览，不代表活动已写入数据库。

- `anomaly-precheck` 的 `can_import=false` 表示存在阻断项。
- `duplicate_count` 只统计已有活动重复，不统计同一上传文件内的重复 GPS 轨迹。

## 四、错误提示字段

### 概述

错误提示字段来自接口异常、向导行级错误、异常预检和错误文案规则表。

### 字段说明

| 字段 | 类型 | 必填 | 来源 | 说明 | 推荐前端提示 |
|---|---|---:|---|---|---|
| `detail` | string/object | 否 | FastAPI 异常响应 | 400、403、422、404 等错误详情 | 按状态码转成中文可行动提示 |
| `errors[].row` | number | 是 | `wizard` | 出错行号 | 显示「第 N 行」 |
| `errors[].fields` | string[] | 是 | `wizard` | 缺失字段 | 显示缺失字段名 |
| `errors[].message` | string | 是 | `wizard` | 行级错误文案 | 当前为「缺少必填字段」 |
| `preview[].duplicate` | boolean | 是 | `wizard` | 是否重复活动 | true 时标记重复 |
| `preview[].duplicate_reason` | string/null | 否 | `wizard` | 重复原因 | 当前为「活动已存在」 |
| `anomalies[].row` | number | 是 | `anomaly-precheck` | 异常行号 | 定位到预览行 |
| `anomalies[].code` | string | 是 | `anomaly-precheck` | 异常类型 | 展示为风险标签 |
| `anomalies[].severity` | string | 是 | `anomaly-precheck` | 严重级别 | `阻断`、`警告`、`提示` |
| `anomalies[].message` | string | 是 | `anomaly-precheck` | 异常说明 | 展示给用户 |
| `anomalies[].suggestion` | string | 是 | `anomaly-precheck` | 修复建议 | 放在下一步操作中 |

### 错误码和状态码

| 场景 | HTTP 状态码 | 实际来源 | 建议展示 |
|---|---:|---|---|
| 未登录 | 401 | `get_current_user` | 请先登录后再继续导入 |
| 未确认授权 | 403 | `start` | 请先确认导入授权范围后再继续 |
| 来源平台不支持 | 422 | `precheck`、`start`、`wizard`、`anomaly-precheck` | 暂不支持该来源平台，请选择高驰、佳明或通用 CSV/JSON |
| CSV 表头缺失 | 400 | `_parse_csv` | 文件内容格式错误，请检查 CSV 表头后重试 |
| JSON 无法解析 | 400 | `_parse_json` | 文件内容格式错误，请检查 JSON 后重试 |
| JSON 无活动记录 | 400 | `_parse_json` | JSON 内容缺少活动记录，请上传活动对象或活动列表 |
| 行级缺少标题或时间 | 200 + `errors` | `_build_preview` | 导入数据缺少必填字段，请补齐后重试 |
| 活动重复 | 200 + `duplicate=true` | `_build_preview` | 活动已存在，请确认是否跳过重复记录 |
| 质量阻断 | 200 + `severity=阻断` | `precheck_running_data_anomalies` | 修复阻断项后再导入 |

### 返回示例

```json
{
  "data": {
    "field_mapping": {
      "start_time": "开始时间",
      "distance_km": "距离(km)"
    },
    "missing_fields": ["title", "duration_seconds"],
    "preview": [
      {
        "row_number": 1,
        "title": null,
        "start_time": "2026-06-01T20:00:00",
        "distance_km": 8.4,
        "duration_seconds": null,
        "location": "西丽湖",
        "duplicate": false,
        "duplicate_reason": null
      }
    ],
    "errors": [
      {
        "row": 1,
        "fields": ["title"],
        "message": "缺少必填字段"
      }
    ],
    "duplicate_count": 0
  },
  "message": "识别完成"
}
```

### 注意事项

- `backend/import_error_copy.py` 是推荐文案规则表，接口内仍有少量直接文案。
- 前端不应直接展示英文 `source must be one of...`，应转换成中文提示。
- 400 表示文件内容无法解析，200 + `errors` 表示文件可解析但行数据不完整。
- 阻断项和警告项都来自 200 响应，不能只按 HTTP 状态码判断成功。

## 五、导入字段与活动卡片字段对照

### 概述

本节把导入向导字段、数据质量字段和活动瀑布流字段连接起来。

### 字段来源和缺口

| 标准字段 | 导入别名 | 向导输出 | 异常预检使用 | 活动接口字段 | 瀑布流字段 | 缺口 |
|---|---|---|---|---|---|---|
| `title` | `title`、`name`、`activity_name`、`活动名称`、`名称` | `preview[].title` | 不直接检查 | `title` | `title` | 可闭环 |
| `start_time` | `start_time`、`started_at`、`startTime`、`开始时间`、`日期`、`时间` | `preview[].start_time` | 缺失时间阻断 | `start_time` | 未直接读取 | 前端应把 `start_time` 纳入月份解析 |
| `distance_km` | `distance_km`、`distance`、`distance_km_total`、`距离(km)`、`距离`、`里程` | `preview[].distance_km` | 超长距离、异常配速 | `distance_km` | `distanceKm` | 可闭环 |
| `duration_seconds` | `duration_seconds`、`duration`、`elapsed_time`、`用时(秒)`、`时长`、`运动时长` | `preview[].duration_seconds` | 异常配速 | 无 | 可推导 `pace` | 后端活动模型没有用时字段 |
| `location` | `location`、`地点`、`城市` | `preview[].location` | 不直接检查 | `location` | `campus` | 可通过校区归一化展示 |
| `pace` | `pace`、`配速`、`平均配速` | 只进 `field_mapping` | 不使用 | `pace_group` | `pace` | 命名不一致，需要联调约定 |
| `gps_track` | `gps_track`、`gps`、`gps_points`、`track`、`route_points`、`GPS轨迹`、`轨迹`、`GPS点` | 只进 `field_mapping` | 空 GPS 点、重复轨迹 | 无 | 无 | 只用于质量检查，不展示卡片 |
| `activity_id` | 预检读取字段 | 无 | 无 | `id` | `id` | 第三方活动 ID 当前不入库 |
| `heart_rate_summary` | 预检读取字段 | 无 | 无 | 无 | 无 | 当前无心率展示字段 |
| `gps_track_summary` | 预检读取字段 | 无 | 无 | 无 | 无 | 当前只返回隐私范围说明 |

### 注意事项

- 导入向导识别 `duration_seconds`，但活动表没有保存用时。
- 活动瀑布流展示配速需要 `pace`，活动表字段名是 `pace_group`。
- 数据质量评分依赖 `gps_track`，活动卡片当前不展示轨迹。
- 若真实导入后要进入瀑布流，需要定义 `duration_seconds`、`pace`、`tags`、`likes`、`comments` 和 `completed` 的来源。

## 六、数据质量评分模型

### 概述

数据质量预检返回异常清单和汇总结果，用于决定是否允许继续导入。

### 规则说明

| 规则 | 条件 | 严重级别 | 返回字段 | 说明 |
|---|---|---|---|---|
| 缺失时间 | `start_time` 为空 | 阻断 | `code=缺失时间` | 没有开始时间不能建立活动去重键 |
| 超长距离 | `distance_km > 100` | 警告 | `code=超长距离` | 可能是多段记录合并 |
| 空 GPS 点 | `gps_track` 为空、`[]`、`null`、`None` | 提示 | `code=空GPS点` | 室内跑可人工确认 |
| 异常配速 | `duration_seconds / distance_km < 150` 或 `> 900` | 警告 | `code=异常配速` | 单位是秒/公里 |
| 重复轨迹 | 多行 GPS 轨迹哈希相同 | 阻断 | `code=重复轨迹` | 需要删除重复记录或保留一条 |

### 返回示例

```json
{
  "data": {
    "summary": {
      "total_rows": 2,
      "anomaly_count": 2,
      "blocking_count": 1,
      "can_import": false
    },
    "anomalies": [
      {
        "row": 2,
        "code": "缺失时间",
        "severity": "阻断",
        "message": "跑步记录缺少开始时间",
        "suggestion": "补充开始时间后再导入"
      }
    ],
    "source": { "id": "generic", "name": "通用" },
    "input_format": "json",
    "field_mapping": { "title": "title" }
  },
  "message": "异常预检完成"
}
```

### 注意事项

- `blocking_count` 大于 0 时，前端应禁用继续导入按钮。
- `anomalies` 已按行号和错误码排序，前端可直接渲染。
- 重复轨迹使用 SHA-256（Secure Hash Algorithm 256-bit，安全哈希算法）摘要比较，不返回原始轨迹。
- 空 GPS 点是提示，不是阻断；室内跑可继续走人工确认。

## 七、联调检查项

### 概述

以下检查项覆盖成功导入、重复活动、缺失字段、权限不足和移动端展示。

### 检查清单

| 编号 | 场景 | 操作 | 预期结果 | 负责方 |
|---:|---|---|---|---|
| 1 | 成功预览 | 用完整 JSON 调 `POST /wizard` | `missing_fields=[]`、`errors=[]`、`preview[0].title` 有值 | 后端 + 前端 |
| 2 | 质量可导入 | 用完整 JSON 调 `POST /anomaly-precheck` | `summary.can_import=true` 或只有非阻断提示 | 后端 + QA |
| 3 | 重复活动 | 先创建同名同分钟活动，再调 `POST /wizard` | `duplicate=true`、`duplicate_reason=活动已存在`、`duplicate_count>0` | 后端 + QA |
| 4 | 缺失字段 | 上传缺少标题或开始时间的内容 | `errors[].row` 有行号，`errors[].fields` 指出字段 | 后端 + 前端 |
| 5 | 权限不足 | 不带 JWT 调导入接口或活动接口 | 返回 401，前端展示登录提示 | 前端 + 移动端 |
| 6 | 未确认授权 | `POST /start` 且 `consent_acknowledged=false` | 返回 403，提示先确认授权范围 | 后端 + 前端 |
| 7 | 非法来源 | `source=strava` 调任意导入接口 | 返回 422，前端展示支持平台 | 后端 + 前端 |
| 8 | 移动端展示 | 在窄屏展示 `preview`、`errors`、`anomalies` | 行号、字段、建议不被截断，按钮状态清晰 | 移动端 |
| 9 | 瀑布流兼容 | 导入后活动进入 `GET /activities` | 卡片标题、距离、校区、月份和配速可展示 | 前端 + 后端 |
| 10 | 错误文案一致 | 对照 `backend/import_error_copy.py` | 缺少字段、格式错误、重复活动、权限不足、来源不支持都有中文提示 | QA |

### 注意事项

## 八、当前缺口和建议

### 缺口列表

| 缺口 | 影响 | 建议 |
|---|---|---|
| 真实导入写入尚未闭环 | `start` 不会创建活动，瀑布流看不到导入结果 | 后续新增真实写入接口前先定义重复策略 |
| 活动模型缺少社交热度字段 | 瀑布流热度排序只能使用默认 0 | 后端补齐 `likes`、`comments`、`completed` 或前端隐藏热度排序 |
| 活动模型缺少封面字段 | 深技大风格封面只能使用默认渐变 | 后端补齐 `cover_label`、`cover_tone`、`cover_url` 或前端按类型推导 |
| `description` 与 `reasoning` 不一致 | 活动描述可能展示默认文案 | 前端兼容读取 `description` |
| `start_time` 与 `month` 不一致 | 月份筛选可能显示「未标注」 | 前端兼容读取 `start_time` |
| `pace_group` 与 `pace` 不一致 | 配速筛选可能进入 `unknown` | 约定 `pace_group` 是否直接作为配速字符串 |
| 移动端导入页未定位到实现 | 字段绑定缺少可见验收点 | 先补 mock 页面或契约测试 |

### 注意事项

- 缺口不等于接口错误，是当前联调需要显式确认的字段契约。
- 文档以当前代码为准，不描述尚未实现的真实写入能力。
- 新增字段时要同时更新后端模型、接口测试、瀑布流字段映射和移动端展示。
