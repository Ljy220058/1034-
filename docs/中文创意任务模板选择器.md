# 中文创意任务模板选择器

## 一、目标

本文件定义一个轻量的中文创意任务模板选择器，用于帮助 cron 创意生成器根据当前空闲 worker 自动选择不同任务模板，避免连续生成同类型、同负责人、同产物或同工作区的重复任务。

适用工作区：`dir:/root/autodl-tmp/projects/hermes-swarm-lab`

使用原则：

1. 先读取当前空闲 worker，再按 worker 能力选择模板。
2. 每个空闲 worker 最多生成一张任务卡。
3. 同一批次内不得生成相同模板、相同产物路径或相同主题的任务。
4. 若近期已有相似任务，应跳过或改为评审、补充、测试类下游任务。
5. 本选择器只提供模板和示例，不修改线上调度配置。

## 二、现有中文任务模式归纳

根据当前项目 `docs/` 下的中文看板交付物，可以归纳出以下高频标题与描述模式：

| 模式 | 常见标题词 | 常见描述结构 | 典型产物 |
|---|---|---|---|
| 前端体验 | 界面、入口、筛选、瀑布流、交互、说明页 | 明确页面、用户角色、入口位置、交互状态和验收截图/清单 | `docs/*界面规范*.md`、前端脚本 |
| 后端接口 | 接口、摘要、导出、导入、统计、聚合 | 明确接口路径、请求字段、返回字段、权限和错误处理 | `backend/routes/*.py`、接口文档 |
| 测试与质量门禁 | 验收、冒烟、质量门禁、联调、清单 | 明确测试范围、最小用例、失败提示和复测步骤 | `tests/*.py`、`docs/*清单*.md` |
| 文档方案 | 方案、路线图、用户故事、说明、规格 | 明确目标读者、章节结构、可执行步骤和产物路径 | `docs/*.md` |
| 审查与安全 | 审查、评审、风险、权限、安全、合规 | 明确审查对象、风险等级、证据、结论和整改建议 | `docs/review-*.md`、`docs/security-audit-*.md` |
| 数据与运营分析 | 指标、留存、周报、异常、摘要 | 明确数据来源、指标口径、输出格式和使用场景 | `docs/*指标*.md`、`docs/*摘要*.md` |

## 三、模板定义

### 模板一：前端体验任务

模板编号：`frontend_experience`

适合 worker：

- `frontend-dev`
- `ui-reviewer`
- 具备能力标签：`前端`、`界面`、`交互`、`HTML`、`JavaScript`

必填字段：

- 页面或模块名称
- 目标用户角色
- 入口位置
- 核心交互状态
- 目标产物路径
- 验收方式

标题模板：

```text
中文创意：{页面或模块名称}前端体验优化
```

正文模板：

```text
目标：为{目标用户角色}优化{页面或模块名称}的前端体验，明确入口、状态展示和异常提示。

具体要求：
1. 说明入口位置：{入口位置}。
2. 覆盖至少三种交互状态：默认、加载中、异常或空状态。
3. 若需要改代码，优先修改 frontend/ 下的轻量文件；若只做方案，输出到 {目标产物路径}。
4. 给出最小验收步骤，说明如何打开页面或检查文档。

验收标准：中文说明清晰；入口、状态和失败提示可执行；产物路径明确；不重复已有同主题前端任务。
```

避免重复检查点：

- 是否已有同页面、同入口的前端任务。
- 是否已有同名 `docs/*界面*` 或 `docs/*入口*` 文档。
- 同一批次内是否已有前端模板任务。
- 若只是评审旧前端方案，标题必须包含“评审”或“复核”。

### 模板二：后端接口任务

模板编号：`backend_api`

适合 worker：

- `backend-dev`
- `api-engineer`
- 具备能力标签：`后端`、`接口`、`FastAPI`、`SQLite`、`数据模型`

必填字段：

- 接口名称
- 接口路径
- 请求字段
- 返回字段
- 权限要求
- 目标产物路径

标题模板：

```text
中文创意：{接口名称}后端接口
```

正文模板：

```text
目标：实现或设计{接口名称}后端接口，服务于{业务场景}。

具体要求：
1. 接口路径：{接口路径}。
2. 请求字段：{请求字段}。
3. 返回字段：{返回字段}。
4. 权限要求：{权限要求}。
5. 若实现代码，补充最小测试；若仅做方案，输出接口说明到 {目标产物路径}。

验收标准：字段定义完整；错误处理有中文说明；权限边界清楚；至少包含一个成功示例和一个失败示例。
```

避免重复检查点：

- 是否已有相同接口路径或同名路由。
- 是否已有同主题后端任务处于 `todo`、`ready`、`running` 或 `blocked`。
- 是否与当前批次其他任务争用同一个 `backend/routes/*.py` 文件。
- 若只是补充测试，不要创建后端实现模板，应选择测试模板。

### 模板三：测试与质量门禁任务

模板编号：`quality_gate`

适合 worker：

- `qa-tester`
- `quality-gate`
- `test-engineer`
- 具备能力标签：`测试`、`验收`、`质量门禁`、`pytest`、`冒烟`

必填字段：

- 被测对象
- 测试范围
- 最小用例列表
- 失败提示要求
- 复测命令
- 目标产物路径

标题模板：

```text
中文创意：{被测对象}验收冒烟清单
```

正文模板：

```text
目标：为{被测对象}建立测试与质量门禁，确保后续 worker 能按同一标准验收。

具体要求：
1. 覆盖测试范围：{测试范围}。
2. 至少列出三个最小用例：成功路径、失败路径、边界输入。
3. 写清失败提示应包含哪些中文字段。
4. 提供复测命令：{复测命令}。
5. 产物输出到 {目标产物路径}；如新增测试，放在 tests/ 下。

验收标准：用例可执行；失败信息可定位；复测命令清楚；不与已有验收清单重复。
```

避免重复检查点：

- 是否已有同对象的 `docs/*验收*`、`docs/*冒烟*` 或 `tests/test_*`。
- 是否只是重复已有测试名或清单章节。
- 同一批次内是否已给同 worker 分配另一个测试门禁任务。
- 若被测对象尚无上游实现或方案，应先创建后端、前端或文档任务。

### 模板四：文档方案任务

模板编号：`documentation_plan`

适合 worker：

- `docs-writer`
- `product-planner`
- `creative-writer`
- 具备能力标签：`文档`、`方案`、`产品`、`中文写作`、`用户故事`

必填字段：

- 方案主题
- 目标读者
- 必含章节
- 目标产物路径
- 复用或区别于已有文档的说明
- 最小验收步骤

标题模板：

```text
中文创意：{方案主题}方案文档
```

正文模板：

```text
目标：为{目标读者}整理{方案主题}的中文方案文档，作为后续实现、测试或评审的依据。

具体要求：
1. 输出到 {目标产物路径}。
2. 必含章节：{必含章节}。
3. 明确它与已有文档的关系：{复用或区别于已有文档的说明}。
4. 每个关键建议都要给出可执行下一步。
5. 附最小验收步骤，说明如何检查文档是否完整。

验收标准：全文中文；章节完整；下一步可执行；产物路径不与近期任务重复。
```

避免重复检查点：

- 是否已有相同主题的 `docs/*.md`。
- 是否只是把“方案、路线图、用户故事、说明”互换标题。
- 目标产物路径是否已存在且内容相近。
- 若新任务是补充旧文档，标题和正文必须写清“补充范围”。

必填字段：

- 审查对象
- 审查范围
- 风险分级标准
- 证据格式
- 整改建议格式
- 目标产物路径

标题模板：

```text
中文创意：{审查对象}风险审查
```

正文模板：

```text
目标：审查{审查对象}在{审查范围}内的风险，并输出中文结论和整改建议。

具体要求：
1. 风险分级：高、中、低。
2. 每条发现必须包含证据位置、影响、建议和是否阻塞。
3. 产物输出到 {目标产物路径}。
4. 不直接修改线上调度配置；如需修复，另建下游任务。
5. 给出最小复核步骤。
```

避免重复检查点：

- 是否已有同对象的 `review-*` 或 `security-audit-*` 文档。
- 是否与进行中的实现任务没有上下游关系。
- 是否把“合规清单、审查报告、评分器”重复创建为同一目标。
- 若发现需要修复，应创建下游修复任务，而不是在本任务中扩大范围。

## 四、选择规则

### 1. worker 到模板的优先匹配

| worker 或能力关键词 | 首选模板 | 备选模板 |
|---|---|---|
| `frontend`、`前端`、`ui`、`界面` | 前端体验任务 | 文档方案任务 |
| `backend`、`api`、`后端`、`接口` | 后端接口任务 | 数据与运营分析任务 |
| `qa`、`test`、`quality`、`测试`、`验收` | 测试与质量门禁任务 | 审查与安全任务 |
| `docs`、`writer`、`文档`、`方案` | 文档方案任务 | 前端体验任务 |
| `review`、`security`、`audit`、`审查`、`安全` | 审查与安全任务 | 测试与质量门禁任务 |
| `data`、`ops`、`运营`、`指标` | 数据与运营分析任务 | 后端接口任务 |

### 2. 批次内去重规则

1. 同一批次中，同一个模板最多使用一次；如果空闲 worker 数量超过模板数量，才允许第二轮使用。
2. 同一批次中，目标产物路径必须唯一。
3. 同一批次中，标题核心词重叠超过六成时，只保留优先级更高的任务。
4. 若 worker 能力无法识别，不强行创建任务，输出“无法识别 worker 能力”。
5. 若 worker 同时匹配多个模板，优先选择当前批次尚未使用的模板。

### 3. 与历史任务去重规则

创建真实 kanban 卡之前，应按 `docs/创意任务去重策略.md` 执行创建前检查：

1. 检查同工作区同产物路径。
2. 检查同负责人二十四小时内同主题任务。
3. 检查待办、进行中、阻塞状态的相似任务。
4. 检查七十二小时内已完成的相似任务。
5. 对三十天内历史相似任务输出弱提醒。

## 五、输出任务卡字段

每张生成卡片至少包含以下字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | 是 | 中文标题，来自模板并填充主题 |
| `assignee` | 是 | 目标 worker 或对应 profile |
| `body` | 是 | 中文任务正文，包含目标、具体要求、验收标准 |
| `workspace_kind` | 是 | 固定为 `dir` |
| `workspace_path` | 是 | 固定为 `/root/autodl-tmp/projects/hermes-swarm-lab` |
| `priority` | 否 | 建议 0 到 10 |
| `template_id` | 是 | 使用的模板编号 |
| `artifact_path` | 是 | 目标产物路径 |
| `dedupe_checks` | 是 | 创建前必须执行的去重检查点 |

## 七、最小验证步骤

1. 打开本文件，确认至少包含五类模板；本文件实际包含六类模板。
2. 检查每类模板是否包含适合 worker、必填字段、验收标准和避免重复检查点。
3. 运行示例脚本：

```bash
python scripts/creative_task_template_selector.py --example
```

4. 确认脚本输出两张中文任务卡，且两张卡的 `assignee` 分别为 `frontend-dev` 和 `docs-writer`。
5. 确认未修改线上调度配置；本任务只新增文档和轻量示例脚本。
