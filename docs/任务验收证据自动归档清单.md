# 任务验收证据自动归档清单

## 目标

本清单用于规范看板 worker 在标记任务完成前提交可复核的验收证据，避免“已完成”评论只有结论、没有测试命令、没有关键输出、没有制品路径或没有回滚说明。它可直接复制到 `kanban_comment` 或任务完成评论中，供 QA Gate、reviewer 和后续 worker 快速复核。

## 常见缺失证据类型

1. 缺少测试命令：只写“测试通过”，未说明实际运行了哪些命令、在哪个目录运行、是否只跑了部分测试。
2. 缺少关键输出：未保留 `passed/failed` 数量、截图路径、构建摘要、接口响应或错误栈关键行。
3. 缺少变更文件：未列出新增、修改、删除的文件路径，QA 无法定位制品或差异入口。
4. 缺少制品路径：文档、截图、报告、导出文件、生成脚本输出等没有给出可打开路径。
5. 缺少风险说明：未说明未覆盖的测试范围、依赖外部服务的假设、兼容性风险或安全边界。
6. 缺少回滚方式：功能变更后没有说明如何撤回配置、恢复文件、关闭开关或回退迁移。
7. 缺少人工验收依据：涉及 UI、内容、图片、音频、运营文案时，未给出截图、样例或人工检查点。
8. 缺少失败证据：测试失败或部分跳过时，只写“环境问题”，未保留 traceback、跳过原因和后续修复责任人。

## 中文验收清单字段

| 字段 | 必填 | 填写要求 | 示例 |
|---|---|---|---|
| 任务摘要 | 是 | 一句话说明本次交付内容和验收对象 | 新增活动签到 API，并补充 8 个接口测试 |
| 变更文件 | 是 | 列出相对项目根目录路径；文档或截图也要列出 | `backend/routes/checkins.py`, `tests/test_checkin.py` |
| 制品路径 | 是 | 列出可复核文件路径；文件应存在且非空 | `docs/任务验收证据自动归档清单.md` |
| 测试命令 | 是 | 写明完整命令、工作目录和是否为全量/局部测试 | `cd /root/autodl-tmp/projects/hermes-swarm-lab && pytest tests/test_checkin.py -q` |
| 关键输出 | 是 | 粘贴最小但足够复核的结果摘要 | `8 passed in 0.42s` |
| 截图或日志 | 条件必填 | UI/视觉/异步任务需给出截图或日志路径；无则写“不适用” | `artifacts/checkin-success.png` |
| 风险说明 | 是 | 说明未覆盖范围、依赖假设、潜在兼容/安全风险 | 未覆盖真实短信服务，仅使用 mock client |
| 回滚方式 | 是 | 说明撤回变更或禁用功能的具体方法 | 回滚 `backend/routes/checkins.py` 与路由注册；删除新增测试 |
| 安全自查 | 是 | 说明是否检查硬编码密钥、注入风险、敏感日志 | 未新增密钥；SQL 使用参数化查询 |
| 后续任务 | 条件必填 | 如仍有未完成项，写明任务 id、负责人或建议创建的修复任务 | 需由 frontend-dev 补充签到按钮入口 |

## 可直接嵌入任务完成评论的模板

```markdown
## 验收证据归档

- 任务摘要：<一句话说明交付内容>
- 变更文件：
  - `<相对路径 1>`
  - `<相对路径 2>`
- 制品路径：
  - `<可复核制品路径>`
- 测试命令：
  - 工作目录：`/root/autodl-tmp/projects/hermes-swarm-lab`
  - 命令：`<pytest / npm test / python -m compileall 等完整命令>`
  - 范围：<全量 / 局部 / 冒烟>
- 关键输出：
  ```text
  <粘贴 passed/failed 数量、构建摘要、接口响应关键行或 traceback 关键行>
  ```
- 截图或日志：<路径；不适用则写“不适用”>
- 风险说明：<未覆盖范围、外部依赖、兼容性或安全风险>
- 回滚方式：<恢复文件、关闭开关、回退迁移或撤销配置的具体步骤>
- 安全自查：<硬编码密钥、SQL 注入、敏感日志等检查结论>
- 后续任务：<无 / task id + assignee + 目标>
```

## 前端任务示例

```markdown
## 验收证据归档

- 任务摘要：新增活动详情页“立即报名”按钮的空状态与成功提示。
- 变更文件：
  - `frontend/src/pages/ActivityDetail.tsx`
  - `frontend/src/components/RegistrationToast.tsx`
  - `frontend/tests/activity-detail.spec.ts`
- 制品路径：
  - `frontend/src/pages/ActivityDetail.tsx`
  - `artifacts/activity-registration-success.png`
- 测试命令：
  - 工作目录：`/root/autodl-tmp/projects/hermes-swarm-lab`
  - 命令：`npm test -- activity-detail.spec.ts --runInBand`
  - 范围：局部前端组件与交互测试
- 关键输出：
  ```text
  PASS frontend/tests/activity-detail.spec.ts
  Tests: 6 passed, 6 total
  ```
- 截图或日志：`artifacts/activity-registration-success.png`
- 风险说明：仅覆盖桌面宽度和基础成功态，未覆盖移动端断点与真实后端超时重试。
- 回滚方式：回滚 `ActivityDetail.tsx`、`RegistrationToast.tsx` 和对应测试；如已发布，隐藏报名按钮开关 `registrationButtonEnabled=false`。
- 安全自查：未新增 token、api_key、password 等硬编码密钥；未新增用户输入拼接 HTML。
- 后续任务：无。
```

## 后端任务示例

```markdown
## 验收证据归档

- 任务摘要：新增活动签到 API，支持按活动 id 和用户 id 创建签到记录。
- 变更文件：
  - `backend/routes/checkins.py`
  - `backend/app.py`
  - `tests/test_checkin.py`
- 制品路径：
  - `backend/routes/checkins.py`
  - `tests/test_checkin.py`
- 测试命令：
  - 工作目录：`/root/autodl-tmp/projects/hermes-swarm-lab`
  - 命令：`pytest tests/test_checkin.py -q`
  - 范围：局部后端接口测试
- 关键输出：
  ```text
  8 passed in 0.51s
  ```
- 截图或日志：不适用；接口响应由 pytest 断言覆盖。
- 风险说明：当前示例只覆盖内存测试库，未覆盖生产数据库迁移和并发重复签到冲突。
- 回滚方式：移除 `backend/routes/checkins.py`，撤回 `backend/app.py` 中的路由注册，删除 `tests/test_checkin.py`；如已有迁移需执行对应 down migration。
- 安全自查：未写入硬编码密码或 API Key；数据库查询应使用 ORM/参数化条件，禁止字符串拼接 SQL。
- 后续任务：如需并发防重，创建 backend-dev 修复/增强任务补充唯一约束与冲突测试。
```

## 使用建议

1. worker 在完成任务前先填写模板，再执行 `kanban_complete` 或在需要 review 时写入 `kanban_comment`。
2. QA Gate 抽查时优先读取“制品路径”“测试命令”“关键输出”“安全自查”四项。
3. 如果任务没有制品路径或测试命令，应视为验收证据不足；除纯调研任务外，不应直接通过。
4. 如果测试失败但任务已标记完成，应保留失败输出并创建明确的修复任务，不能只写“环境问题”。
5. 对截图、报告、日志等制品，路径应使用项目内相对路径或明确绝对路径，避免只贴聊天截图或临时不可访问链接。
