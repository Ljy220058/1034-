# 代码审查报告
## 严重（必须修）
- [backend/routes/workspaces.py:77-80] `workspace_path` 允许直接传入任意路径，`current` 之外的 `workspace:` 选择器只做前缀截断后就交给 `_normalize_workspace_path`，没有任何白名单/归属校验；同时返回 `list_workspace_tasks(effective_workspace, ...)`，会把同一数据库里的任意工作区任务暴露给持有任意有效 token 的用户 → 建议：把 workspace selector 限定为当前租户/当前项目根目录，至少校验路径必须落在允许的工作区根下，并在返回前做权限检查；若确实需要跨工作区浏览，新增显式授权参数和后端鉴权。
- [backend/routes/announcements.py:32-39] `PATCH /announcements/{id}` 使用 `get_optional_current_user`，未登录请求只要传有效 body 就能进入更新流程；`admin_or_leader(current_user)` 会在未登录时直接抛 401，但该路由的认证不是强制依赖，FastAPI 允许匿名到达逻辑层，容易在后续改动中遗漏授权门禁 → 建议：把依赖改成 `Depends(get_current_user)`，保持写接口统一强制认证，避免匿名访问误开。
- [backend/routes/workspaces.py:191-203] `read_workspace_worker_summary` 固定读取 `Path.cwd()`，与同文件其它接口接受 `workspace_path`/`workspace` 参数的契约不一致；如果服务运行目录不是目标 workspace，返回的统计会错配，前端/测试可能读到别的目录的 board 数据 → 建议：统一以显式 `workspace_path` 为输入，或至少从同一配置源解析 workspace 根，避免“当前目录”隐式耦合。

## 中等（应该修）
- [backend/routes/tasks.py:156-185] `batch_create_task_items` 允许任意客户端把 `workspace_path` 设为仓库根目录之外的任意绝对路径，只做了硬编码等值判断后再写库；一旦未来部署路径变化，这个校验会失效或误拒，且路径值未复用统一的 workspace 解析器，行为分裂 → 建议：提取统一的 workspace 归一化/白名单函数，只接受明确允许的 workspace roots，并在这里和 `workspaces.py` 共用。
- [backend/task_board_models.py:343-359] `list_workspace_task_items_for_recommendation` 把 `status_filter`、`assignee` 做了参数化，但 `query` 的 `workspace` 条件字符串是通过 f-string 直接拼接，虽然当前条件仅来自固定片段，仍属于 SQL 组装风险点；后续一旦加新条件很容易引入注入 → 建议：改成固定 SQL 模板配合参数数组，避免动态拼接 where 子句。
- [backend/routes/common.py:77-80] `get_current_user` 仅解析 `Authorization: Bearer <token>` 的明文字符串，token 内包含 `member_id:role:expires_at`，完全可预测且未签名；任意知道成员 id 和角色的人都能伪造 token，属于认证绕过风险 → 建议：改为 HMAC/JWT 签名 token，并把服务端密钥放入环境变量；至少加入签名和过期校验，不要把角色明文放在客户端可伪造的载荷里。
- [backend/routes/tasks.py:175-177] `batch_create_task_items` 把 workspace 路径硬编码为 `/root/autodl-tmp/projects/hermes-swarm-lab`，这会导致测试/多环境部署不可移植，且在容器或 CI 上直接 422，属于环境耦合缺陷 → 建议：改用配置化的项目根目录或调用统一 workspace 解析方法，不要把宿主机绝对路径写死。

## 建议（可以修）
- [backend/routes/activities.py:18-24] `create_activity_endpoint` 里先调用 `admin_or_leader(current_user)`，随后又重复判断 `current_user.role`，属于冗余授权逻辑；虽然不影响安全，但增加维护成本 → 建议：保留一层鉴权即可。
- [backend/routes/announcements.py:18-21,42-48] 公告创建/删除接口直接返回 503，路由仍然暴露在公共 API 中，前端或自动化会把它当成可用能力；如果这是临时关闭，缺少显式特性开关与说明 → 建议：在文档或 OpenAPI 中标记未启用，或直接移除未实现端点，避免调用方误用。
- [backend/models.py:68,80,231,239] 多个模型显式开启 `extra='allow'`，会把未声明字段悄悄吞进请求体；这会降低输入契约的可预测性，也让前端多传字段时难以及时发现 → 建议：对写接口尽量收紧为默认 `extra='forbid'`，只在确有兼容需要时开放。
- [backend/routes/workspaces.py:231-236] 推荐逻辑从 `metadata['capabilities']` 直接采样，未限制元素类型和长度，极端情况下会把异常结构传入推荐器 → 建议：先标准化成长度受限的字符串列表，再传给推荐函数。
