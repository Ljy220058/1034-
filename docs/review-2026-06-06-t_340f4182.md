# 代码审查报告
## 严重（必须修）
- [backend/routes/announcements.py:19-21] 公告创建接口被直接改成 `raise HTTPException(status_code=503)`，原本可用的创建功能现在对所有管理员/负责人永久不可用 → 建议：恢复对 `create_announcement` 的调用；如果只是临时下线，至少要在路由层保留明确的 feature flag/开关，并给出可恢复的降级逻辑。
- [backend/routes/announcements.py:43-45] 公告删除接口同样被硬编码为 503，并且后续 `deleted` 分支已不可达，导致删除能力彻底失效 → 建议：恢复 `delete_announcement` 路径；若需要禁用，改为受控开关而不是永久 unreachable 代码。
- [backend/routes/common.py:36-49] `sanitize_member_payload()` 新增“首个 `UserRegister` 可任意角色”的 bootstrap 逻辑，直接通过 `SELECT COUNT(*) FROM members` 判断是否放行管理员/领导角色，等于把首次注册提升权限放宽到请求体可控，存在越权创建高权限账号的风险 → 建议：把 bootstrap 授权收敛到只在离线初始化/显式环境开关下启用，且首次管理员创建应验证不可被普通注册流程触发。
- [backend/routes/workspaces.py:84-84] `_normalize_workspace_path()` 仅允许位于 `PROJECT_ROOT` 或当前工作目录下的路径，但没有做目录存在性/类型校验，也没有对符号链接回跳做更强约束；结合后续直接把该路径传给仓储查询，容易出现越权访问或错误路径绕过问题 → 建议：显式校验 `is_dir()`、`exists()`，并在授权前后都使用规范化后的绝对路径做白名单比对，必要时禁止符号链接穿越。
- [backend/repository.py:340-356] `list_workspace_task_items()` 直接把 `status_filter`、`limit` 交给查询拼接逻辑，虽然参数化了 SQL，但调用方可传入任意状态字符串，仓储层没有二次校验；一旦路由层校验缺失或被复用，会把非法状态带入业务数据面 → 建议：在仓储层再做一次状态白名单校验，避免单点验证失效。
## 中等（应该修）
- [backend/routes/workspaces.py:124-152] `import_workspace_task_items()`/`read_task_queue_tasks()` 接口仍使用宽泛的 `dict[str, Any]` 入参或路径型查询参数，缺少结构化模型约束，错误会晚到仓储层才抛出，调试和可维护性较差 → 建议：为请求体定义 Pydantic 模型，显式约束 `workspace_path`、`items`、`status` 字段类型和取值范围。
- [backend/routes/tasks.py:87-96] `_build_timeline()` 用整除 `100 // (steps - 1)` 生成百分比，`steps > 2` 时会产生重复/跳跃的进度点（例如 3、4、5 步都有可能出现不均匀刻度），接口返回的“模拟进度”与实际预期不稳定 → 建议：改为按浮点线性插值再四舍五入，或明确文档说明这是离散近似值。
- [backend/app.py:61-66] 全局异常处理把所有未处理异常统一吞成中文 `服务器内部错误`，但没有记录日志或关联 request id，线上排障会丢失关键信息 → 建议：在返回统一错误体的同时记录结构化日志，至少包含路径、方法和异常堆栈摘要。
- [backend/routes/activities.py:68-79] 报名创建接口只依赖 `registration_member_guard()` 和下游仓储返回码，未在路由层明确检查 `activity_id`、`member_id` 的业务合法性边界（如负值、越界、活动报名窗口），如果仓储层没兜底会出现错误状态码混淆 → 建议：在路由层补充最小输入验证，并确保仓储层对业务规则有单独校验。
## 建议（可以修）
- [backend/routes/__init__.py:25-45] `router_modules` 里 `workers_router` 重复注册了两次，容易造成维护者误判路由集合，也可能在某些场景下引入重复挂载问题 → 建议：去重列表并补一个路由注册测试。
- [backend/routes/tasks.py:99-124] 进度接口返回的任务数据是静态硬编码样本，且 `simulate_task_progress()` 只是基于固定列表回放，并不连接真实任务状态 → 建议：如果这是演示接口，明确命名/文档标注为 mock；如果是正式能力，接入真实数据源。
- [backend/app.py:69-80] `/healthz` 与 `/health/ready` 返回了版本、数据库路径和工作区路径等运维信息，虽然便于排查，但在对外暴露场景下会泄露部署环境细节 → 建议：仅在内部网络或带鉴权的运维端点暴露这些字段，公网端点精简返回。
