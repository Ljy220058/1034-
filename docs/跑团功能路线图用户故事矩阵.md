# 跑团功能路线图用户故事矩阵

## 概述

本文档把 1034 跑团管理系统的功能路线图整理成用户故事矩阵，便于后端、前端和测试任务执行者继续拆分实现任务。

矩阵围绕跑步数据导入、活动瀑布流、训练计划、里程徽章、隐私授权五个模块展开。
每条故事都说明用户目标、优先级、依赖角色和建议验收方式。



## 参数说明

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| source_file | 文件 | 是 | 待导入的跑步记录文件，建议第一版支持 CSV（逗号分隔值文件） |
| dry_run | 布尔值 | 是 | 是否只预检不写入数据，第一版建议固定为 `true` |

| import_batch_id | 字符串 | 否 | 导入批次编号，用于追踪同一批数据 |

```json
    "invalid_count": 2,
    "errors": [
      {
        "row": 3,
        "field": "distance_km",
        "message": "活动距离必须是大于或等于 0 的数字"
```

## 注意事项

- 导入报告必须说明错误行号和错误原因，不能只写“格式错误”。
- 手机号属于敏感信息，报告中只展示脱敏后的手机号。
- 第一版导入应优先做预检，确认字段映射稳定后再支持正式写入。
