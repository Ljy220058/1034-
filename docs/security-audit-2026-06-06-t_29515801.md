# 安全审计报告

## 严重 (CVSS >= 7)
### [backend/routes/workspaces.py:127-152] 任务与工作器枚举接口缺少角色授权控制 (CVSS: 8.6)
- 攻击向量：任意已登录普通成员只要携带有效 JWT，就能直接访问 `/api/v1/workspaces/task-queue/workers` 和 `/api/v1/workspaces/tasks`，枚举内部 worker 列表、任务状态、工作区路径与元数据；攻击者可以据此建立内部拓扑、筛选高价值任务、定位活跃工作区，进一步辅助横向移动与定向破坏。
- 影响：泄露内部任务队列、工作器身份、工作区路径和任务元数据，暴露系统运行细节与操作情报，违反最小权限原则。
- 修复：```python
from fastapi import HTTPException

# 在路由函数开头加入统一授权检查
if current_user.role not in {'admin', 'leader'}:
    raise HTTPException(status_code=403, detail='forbidden')
```

## 中等 (CVSS 4-6)
### [backend/models.py:116-173] 安全敏感请求模型未统一拒绝未知字段 (CVSS: 5.9)
- 攻击向量：攻击者可在创建活动或公告请求中附带额外 JSON 字段；如果后续代码或存储层对这些字段做了隐式透传、日志拼接或条件分支，攻击者可借由“多余字段”注入未预期语义，绕过接口契约并污染下游处理逻辑。
- 影响：请求面扩大、输入契约不一致、后续维护时容易形成隐式信任边界，增加权限绕过、数据污染和逻辑混淆风险。
- 修复：```python
from pydantic import BaseModel

class ActivityBase(BaseModel):
    ...
    model_config = {'extra': 'forbid'}

class ActivityCreate(BaseModel):
    ...
    model_config = {'extra': 'forbid'}

class AnnouncementBase(BaseModel):
    ...
    model_config = {'extra': 'forbid'}

class AnnouncementCreate(BaseModel):
    ...
    model_config = {'extra': 'forbid'}
```

### [backend/routes/workspaces.py:134-152] 任务查询接口未按角色分级，导致内部数据面过宽 (CVSS: 5.8)
- 攻击向量：任何登录用户都可通过 `workspace`、`workspace_path`、`status` 和 `limit` 参数反复调用任务列表接口，批量获取工作区任务摘要；即便没有直接修改权限，仍可对组织内任务进行持续侦察、画像和优先级推断。
- 影响：泄露任务进度、状态分布、路径信息与元数据，增加针对特定项目或 workspace 的社工和供应链攻击成功率。
- 修复：```python
from fastapi import HTTPException

if current_user.role not in {'admin', 'leader'}:
    raise HTTPException(status_code=403, detail='forbidden')
```

## 低危 (CVSS < 4)
### [backend/models.py:58-78] Activity 基础/创建模型输入边界可进一步收紧为显式安全契约 (CVSS: 3.7)
- 攻击向量：攻击者可以在活动创建请求中追加非标准字段来探测后端字段接收行为；虽然当前未见直接利用点，但这种宽松契约会让未来变更更容易出现“额外字段被误用”的逻辑回归。
- 影响：增加接口行为不确定性，提升后续引入参数污染漏洞的概率。
- 修复：```python
class ActivityBase(BaseModel):
    ...
    model_config = {'extra': 'forbid'}

class ActivityCreate(BaseModel):
    ...
    model_config = {'extra': 'forbid'}
```
