# 任务重复风险审查报告

## 1. 报告目的

本报告用于中文创意任务创建前的重复风险审查，目标是帮助后续 idea-scout、dispatcher、docs-writer、code-reviewer 等 worker 在创建新卡片前判断：是否允许创建、是否建议合并到已有任务、是否应拒绝创建。

适用范围：当前项目 `/root/autodl-tmp/projects/hermes-swarm-lab` 中面向 1034 跑团管理系统的中文创意任务、方案文档任务、任务入口任务、去重/验收/调度规则任务、前后端功能创意拆分任务。

本报告只提供创建前审查规则，不要求修改线上配置，不自动阻塞、归档或删除已有任务。

## 3. 5 类最容易重复的创意模式

### 3.1 同主题规则文档反复生成

典型标题：

- 建立重复创意拦截评审规则
- 中文创意库去重与趋势标签器
- 建立中文创意任务验收模板库
- 审查中文创意任务的可执行性与重复风险
- 补齐创意任务重复预警和去重规则

风险：这些任务都围绕“创意任务质量、去重、验收、规则、模板”，即使标题动词不同，最终也容易产出相同章节：标题相似度、负责人、工作区、创建时间、验收标准。

审查重点：必须说明新任务是“规则主文档、评审报告、实现标签器、模板库、接入验证”中的哪一种，并引用已有文档路径。

### 3.2 同一功能被拆成多个无边界面板/接口任务

典型标题：

- 前端创意卡片导航面板
- 后端创意卡片批量路由器
- 空闲 worker 推荐
- 调度前快照摘要
- 任务健康度筛选修复

风险：这些任务都服务看板协作流程，若正文只写“支持筛选、排序、推荐、摘要、状态提示”，worker 会同时修改相同路由或相同页面，导致交付物重叠。

审查重点：必须明确接口路径、组件路径、输入输出字段，以及本任务不做的相邻能力。

### 3.3 方案文档与实现任务互相覆盖

典型标题：

- 活动模板智能推荐器功能方案
- 为活动创建新增模板推荐接口
- 在活动创建区域增加模板推荐卡片
- 更新活动模板推荐 API 说明
- 补全活动模板推荐用户指南

风险：方案、后端实现、前端实现、API 文档、用户指南都属于同一功能链路。如果每个任务都重新描述全部背景、接口、前端状态和验收，会出现多份不一致方案。

审查重点：新任务必须定位为“实现方案中的第 N 步”，并只交付一个层级：后端接口、前端入口、文档更新或测试补齐。

### 3.4 同一数据口径的指标/诊断任务重复

典型标题：

- 活动留存分层指标方案
- 活动参与异常模型
- 活动报名异常诊断
- 设计活动数据异常趋势雷达图模型
- 设计跑步活动数据质量评分模型

风险：这些任务都依赖成员、活动、报名、签到和 `activity_participation_facts`。标题可能分别叫“留存、异常、趋势、质量评分”，但都可能重复定义统计窗口、异常标签和分层原因。

审查重点：必须说明统计对象、窗口、输出字段、与已有指标的差异；禁止只换图表名称就创建新任务。

### 3.5 同产物清单/模板任务重复

典型标题：

- 任务验收证据自动归档清单
- 创意任务验收冒烟清单
- 建立中文创意任务验收模板库
- 任务验收证据归档结构统一
- 中文创意任务合规规则评审

风险：都可能输出到 `docs/`，内容重复覆盖“变更文件、测试命令、关键输出、风险说明、安全自查、中文标题、负责人、工作区”。如果没有指定复用方式，就会产生多个相似清单。

审查重点：如果已有清单能覆盖，新任务应改为“接入到某接口/某 worker 流程”或“评审某文档缺口”，而不是新建同类总览文档。

## 4. 四维轻量审查规则

后续 worker 创建任务前，至少按以下四个维度打分。建议输出“允许创建 / 建议合并 / 拒绝创建”三档结论。

### 4.1 标题相似度

规则 1：标题规范化后再比对。

- 去掉“中文创意：”“功能创意：”“建立/整理/补齐/设计/审查”等泛化前缀。
- 合并同义词：审核/审查/复核，规则/清单/模板，推荐/分流/路由，预检/审计/授权。
- 抽取核心词：模块名、目标对象、交付物名、动作。

判断建议：

- 核心词重叠 ≥ 70%，且功能方向相同：至少“建议合并”。
- 标题几乎同名，且已有任务仍在 todo/ready/running/blocked：直接“拒绝创建”。
- 只有泛化词相同，目标模块不同：进入其他维度继续判断。

### 4.2 目标对象

规则 2：同一业务对象或代码区域必须说明上下游边界。

目标对象包括：

- 业务对象：活动、成员、报名、签到、任务、worker、工作区。
- 技术对象：`backend/routes/workspaces.py`、`backend/routes/task_imports.py`、`frontend/activity-waterfall.js`、`docs/api.md` 等。
- 数据对象：`activity_participation_facts`、成员资料字段、活动模板字段。

判断建议：

- 同一对象 + 同一负责人 + 旧任务未完成：默认拒绝创建。
- 同一对象 + 不同负责人，但分别是后端/前端/文档/测试：允许创建，但正文必须写清依赖关系。
- 同一对象 + 只是“再整理一份方案”：建议合并到已有文档或旧任务评论。

### 4.3 交付物

规则 3：交付物路径或接口相同优先判重。

审查时必须要求候选任务写出至少一种交付物：

- Markdown 路径，例如 `docs/创意任务去重策略.md`
- API 路径，例如 `GET /api/v1/activities/templates/recommendations`
- 组件/脚本路径，例如 `frontend/activity-waterfall.js`
- 测试文件路径，例如 `tests/test_activity_template_recommendations.py`

判断建议：

- 交付物路径完全相同：拒绝创建，除非标题明确是“评审/更新/补充”且引用上游。
- 同一目录下同主题 Markdown：建议合并，避免多份规则文档。
- 一个任务交付后端代码、另一个交付前端代码：可允许创建，但必须有父子依赖或明确接口契约。

### 4.4 验收标准

规则 4：验收标准相同或不可执行时，不应创建新任务。

必须检查候选任务是否包含可执行验收：

- 命令：例如 `pytest tests/test_xxx.py`
- 接口调用：例如 `curl GET /api/v1/...`
- 页面验证：例如访问 `frontend/index.html` 并检查加载/空/错误态
- 文档检查：例如章节数量、示例数量、引用路径

判断建议：

- 两个候选任务验收都写“输出 Markdown，至少 5 条规则、3 个示例”：建议合并。
- 验收只写“优化体验、补充说明、提供建议”：拒绝创建，要求补全验收。
- 验收可执行且新增价值明确：允许创建。

## 5. 最小判定矩阵

| 标题相似度 | 目标对象 | 交付物 | 验收标准 | 建议结论 |
|---|---|---|---|---|
| 高 | 相同 | 相同 | 相同或相近 | 拒绝创建 |
| 高 | 相同 | 不同 | 明确上下游 | 建议合并或改为子任务 |
| 中 | 相同 | 不同 | 可执行且新增价值明确 | 允许创建，但正文必须引用已有任务/文档 |
| 中 | 不同 | 不同 | 可执行 | 允许创建 |
| 低 | 相同 | 相同 | 不清晰 | 拒绝创建，先补正文 |
| 低 | 不同 | 不同 | 不清晰 | 建议暂缓创建，补验收后再审 |

## 6. 具体审查规则清单

1. 先查近期任务和 `docs/` 已有产物；未做检索不得创建中文创意任务。
2. 标题规范化后核心词重叠 ≥ 70% 时，必须列出命中的已有任务或文档。
3. 同一工作区、同一负责人、同一主题，只要已有任务未完成，默认拒绝创建。
4. 新任务与已有任务目标对象相同，但交付物不同，必须写清“上游/下游/评审/实现/测试/文档”的关系。
5. 交付物路径完全相同，除非是显式更新或评审，否则拒绝创建。
6. 只输出泛化 Markdown 的任务，必须说明章节、示例数量、后续接入方式和复用入口，否则拒绝创建。
7. 涉及同一 API 或同一前端组件的任务，必须指定接口路径或组件路径，不能只写“优化页面/补充接口”。
8. 同一批候选任务内部也要互相比对，命中同主题时只保留目标最具体的一张。
9. 已完成任务 72 小时内仍处于强去重窗口；新任务必须说明旧产物不能复用的原因。
10. 不同负责人不能抵消重复风险；若工作区、目标对象或交付物相同，仍按疑似重复处理。
11. 验收标准必须包含可执行检查方式；无法验证的任务不应创建。
12. 如果只是补充已有文档中的一节，优先在旧任务评论中提出补充建议，不新建平级任务。

## 7. 判断示例

### 7.1 允许创建

已有任务：`活动模板智能推荐器功能方案`，产物为 `docs/活动模板智能推荐器方案.md`，状态为完成。

候选任务：`为活动创建新增模板推荐接口`，负责人 `backend-dev`，交付物为 `backend/activity_templates.py`、`backend/routes/activities.py`、`tests/test_activity_template_recommendations.py`。

判断：允许创建。

原因：标题同属“活动模板推荐”，但候选任务是方案下游后端实现，交付物从文档转为代码和测试，验收可通过接口和 pytest 验证。

候选任务正文必须补充：

```text
基于 docs/活动模板智能推荐器方案.md 的第 6、10、11 节，本任务只实现后端推荐接口，不做前端卡片、不更新用户指南。
验收：pytest tests/test_activity_template_recommendations.py 通过；普通成员访问返回 403；缺少 activity_type 返回 422。
```

### 7.2 建议合并

已有任务：`创意任务去重策略.md` 已输出标题相似度、负责人、工作区、创建时间四类规则。

候选任务：`建立重复创意拦截评审规则`，负责人 `code-reviewer`，正文要求输出标题相似度、目标对象、交付物、验收标准四个维度规则。

判断：建议合并。

原因：候选任务与已有去重策略同主题、同工作区、同为规则文档；虽然维度名称略有变化，但交付目标仍是“创建前去重规则”。

建议改写：

```text
标题改为：补充创意任务去重策略的目标对象与验收维度
交付物固定为：更新 docs/创意任务去重策略.md 的新增小节，或输出评审报告引用该文档。
验收：新增至少 3 个目标对象维度示例，不重新生成完整策略。
```

### 7.3 拒绝创建

已有任务：`建立中文创意任务验收模板库`，状态为 running，目标是输出中文创意任务验收模板。

候选任务：`补齐中文创意任务验收规则清单`，负责人相同或相近，交付物仍是 `docs/` 下新的验收清单，验收也是“至少 5 条规则、3 个示例”。

判断：拒绝创建。

原因：旧任务仍未完成，新任务与旧任务目标对象、交付物类型、验收标准高度重叠；继续创建只会让两个 worker 同时写相似 Markdown。

建议处理：

```text
不创建新卡片。等待已有任务完成后，再根据产物缺口创建“评审中文创意任务验收模板库的可执行性”或“把验收模板接入调度器诊断输出”。
```

### 7.4 允许创建但需人工确认

已有任务：`跑步数据导入隐私与授权审计`，负责人 `security-auditor`，产物是审计报告。

候选任务：`增加跑步数据导入授权预检面板`，负责人 `frontend-dev` 或 `security-auditor`，产物是前端预检面板或预检规则说明。

判断：允许创建但需人工确认边界。

原因：两者同属导入授权主题，但一个是审计，一个是预检入口。若候选任务只重复输出隐私边界清单，应合并；若实现面板或接口，则可创建。

正文必须写清：

```text
本任务只做导入前授权预检入口，不重新做隐私审计；隐私边界复用已有审计报告。
验收：未授权用户看到 403 或中文提示；dry_run 不写库；预检结果包含失败行号和失败原因。
```

## 8. 后续接入建议

建议在后续创意生成或 kanban 创建前增加一个只读“重复风险诊断”步骤，不直接修改旧任务状态，只返回诊断结果。

建议输出字段：

```json
{
  "decision": "allow | merge | reject",
  "risk_level": "low | medium | high",
  "matched_existing_items": [
    {
      "title": "创意任务去重策略",
      "artifact": "docs/创意任务去重策略.md",
      "match_reasons": ["同主题规则文档", "验收标准相近"]
    }
  ],
  "triggered_rules": ["标题核心词重叠", "同工作区同产物"],
  "required_rewrite": "说明与已有文档的上下游关系，并固定交付物路径",
  "safe_to_create": false
}
```

接入位置建议：

1. 在 idea-scout 生成候选任务后、调用 `kanban_create` 前运行诊断。
2. 诊断只读取近期任务、当前工作区文档和候选任务正文，不阻塞已有任务。
3. `decision=reject` 时跳过创建并记录中文原因。
4. `decision=merge` 时把候选改写为“补充/评审/实现已有产物”的下游任务，或只写评论建议。
5. `decision=allow` 时仍要求任务正文包含交付物和可执行验收。

## 10. 不需要立即处理但值得注意

- 当前项目已经有多份创意质量、去重、验收相关文档，后续不宜再创建“总览型规则文档”，应优先创建接入、实现、评审或补充型任务。
- `docs/跑团功能路线图与任务入口.md` 已经提供任务种子库；后续创意生成应复用其“后续可执行入口”，而不是从零生成同类路线图。
- 文档类任务完成时必须给出绝对路径；否则后续 worker 很难判断是否与已有产物重复。
- 安全/授权/隐私任务应区分“审计报告”和“修复实现”，避免两个安全任务重复输出同一风险清单。
- 前端面板类任务必须指定页面和组件路径；否则容易重复生成“筛选、排序、空状态、加载态”的泛化任务。
