# 训练异常提醒规则配置样例

日期：2026-06-06
状态：可复用配置样例
配置版本：训练异常提醒规则.v1
交付物：`examples/training_anomaly_alert_rules.v1.json`

## 一、目标

本文为跑团训练复盘与活动导入模块提供一份可直接复用的“训练异常提醒规则配置”样例，帮助后续后端与前端实现提醒逻辑时使用同一份稳定契约。本文只提供配置样例和验收口径，不修改线上配置，不新增数据库表，不替代后端仓储、接口或前端实现。

## 二、已梳理的现有依据

| 依据 | 当前口径 | 本配置如何复用 |
|---|---|---|
| `backend/models.py` | 成员包含常用配速、常跑距离、训练目标；活动包含开始时间、距离、配速组；签到包含状态与GPS校验 | 作为训练复盘与未完成判断的基础字段 |
| `backend/database.py` | 当前核心表为成员、活动、报名、签到、公告；没有正式训练计划表和跑步记录表 | 本配置不要求立即落库，可由后端在导入预览或复盘计算阶段读取 |
| `backend/running_data_anomaly_precheck.py` | 已有缺失时间、异常配速、重复轨迹、超长距离、空GPS点等预检口径 | 规则沿用既有中文异常语义，并补充复盘与展示动作 |
| `docs/训练计划日历导出联调样例.md` | 训练计划当前以活动字段和前端训练模板为主要联调口径 | 计划距离、训练类型和活动时间可作为触发条件输入 |
| `docs/跑步数据导入失败原因排查手册.md` | 导入向导已有来源、字段缺失、重复识别和中文文案要求 | 重复上传、来源异常和GPS点过少优先服务导入向导 |
| `docs/activity_anomaly_radar_contract.md` | 雷达图已有配速突变、距离异常、重复上传、GPS点过少、来源平台异常维度 | 本配置的规则ID可映射到雷达图维度风险 |
| `docs/训练完成智能复盘卡片数据契约.md` | 复盘卡片已有完成率、异常标签、数据质量和建议文案字段 | 命中结果可复用为异常标签、用户提示文案和建议处理动作 |

## 四、后端计算复用方式

1. 后端在导入预览、活动结束复盘或运营趋势计算阶段，组装规则需要的输入字段。
2. 每条规则按“触发条件.命中口径”进行判断，输出规则ID、严重级别、用户提示文案、建议处理动作和适用模块。
3. 对于“阻断”级规则，导入向导默认不写入记录，必须由用户跳过、修正或人工确认。
4. 对于“警告”级规则，允许继续生成复盘卡片，但需要在异常提醒或数据质量区域展示。
5. 对于“提示”级规则，不阻止流程，只作为弱提示、雷达维度或运营关怀信号。

## 五、前端展示复用方式

1. 前端不重新推导规则，只消费后端返回的命中结果。
2. 智能复盘卡片优先展示严重级别最高的一到两条提醒，避免信息过载。
3. 活动导入向导按行展示“阻断”和“警告”命中结果，并保留建议处理动作。
4. 异常趋势雷达图可把规则ID映射到既有维度：配速突变、距离异常、重复上传、GPS点过少、来源平台异常。
5. 连续缺席属于个人敏感提醒，只对本人、领队或管理员展示，不进入公开活动页。

## 六、最小人工验证步骤

1. 打开 `examples/training_anomaly_alert_rules.v1.json`，确认“规则”数组共有8条。
2. 确认每条规则都包含：规则ID、中文名称、触发条件、严重级别、用户提示文案、建议处理动作、适用模块。
3. 确认8条规则分别覆盖：配速突变、距离异常、心率缺失、GPS点过少、重复上传、训练未完成、连续缺席、导入来源异常。
4. 确认“样例输入与命中结果”共有3组，并且每组都包含输入和命中结果。
5. 执行本文“最小机器验证命令”，确认JSON可解析且规则数量、样例数量满足约定。
