# 代码审查报告
## 严重（必须修）
- [backend/routes/announcements.py:18-21] 公告创建接口被硬编码为直接返回 503，等于把原有写接口永久禁用，导致功能整体不可用 → 建议：恢复实际创建逻辑，或如果是临时下线，至少加 feature flag / 配置开关并保留可回退路径，不要在生产路径里直接 `raise HTTPException(503)`。
- [backend/routes/announcements.py:42-47] 删除接口同样直接返回 503，且后续删除逻辑被遗留代码遮蔽，说明当前删除能力不可用 → 建议：恢复 `delete_announcement` 的真正调用与结果校验，若必须临时禁用则改为受控开关并删除死代码，避免误导维护者。
- [backend/routes/common.py:37-49] `sanitize_member_payload()` 对注册时的首个用户开放任意角色，但仅用 `SELECT COUNT(*) FROM members` 判断，存在并发竞态：两个并发注册都可能看到 0，从而同时获得非 member 角色 → 建议：把“首个用户升级”放进事务里做原子检查/插入，或在数据库层加唯一性/初始化锁，避免越权注册。
- [backend/routes/workspaces.py:87-95] 工作区路径只做 `resolve()` 后的祖先目录判断，`workspace_path` 可由外部直接指定；一旦项目根或当前目录下存在符号链接/子目录逃逸，可能把可访问范围扩展到不期望路径 → 建议：对允许的 workspace 根做白名单校验，并拒绝通过符号链接跳出边界的路径，至少在解析后再次校验最终 `realpath` 是否仍位于允许根内。
## 中等（应该修）
- [backend/routes/workspaces.py:154-162] `read_workspace_tasks()` 只允许 `admin_or_leader`，但其路径参数校验只检查了字符串前缀/解析结果，没有结合用户可见工作区列表做授权过滤，容易把“路径合法”和“用户有权看”混为一谈 → 建议：把路径校验与授权校验分离，增加基于用户/成员关系的工作区访问控制。
- [backend/routes/members.py:29-40] 创建成员接口虽然检查了角色白名单，但 `current_user.role != ROLE_ADMIN` 时只允许创建 `member`，却没有对 `payload` 里其它敏感字段做额外审计；同时导入了未使用的 `hashlib, secrets`，表明密码/随机数逻辑可能被遗漏 → 建议：明确成员创建的字段白名单，补齐密码哈希与敏感字段处理，并删除无用导入避免误导安全审查。
- [backend/routes/common.py:133-141] `announcement_payload()` 会把 `content` 与 `body` 强制互拷贝并把 `is_pinned` 固定为 `True`，这会覆盖调用方显式传入的状态，造成接口语义与数据层不一致 → 建议：仅做字段兼容映射，不要无条件改写业务字段；若 pin 是服务端强制规则，应在模型/校验层显式说明。
- [backend/app.py:43-58] `HTTPException` 处理器对 `detail` 是字典时直接原样返回，没有统一错误结构；不同接口可能泄露内部错误格式并让前端难以稳定解析 → 建议：统一把错误包装成固定 schema（code/message/details），并仅对白名单字段透出 `details`。
## 建议（可以修）
- [backend/routes/announcements.py:32-39] `patch_announcement()` 里先 `payload.model_dump(exclude_unset=True)` 再 `AnnouncementUpdate(**data)`，如果模型后续增加必填字段或默认转换逻辑，这种二次构造容易引入行为漂移 → 建议：直接传原 payload 给 repository 层，或显式构造仅允许更新字段的 DTO。
- [backend/routes/common.py:63-74] `parse_token()` 只校验 token 里的 member_id/role/过期时间，并未加入签名或随机 nonce，格式上可伪造；虽然最终依赖数据库里的角色回查，但 token 本身仍然是可预测明文 → 建议：改成 HMAC/JWT 签名令牌，并在服务端保存可撤销的 session 标识。
- [backend/routes/__init__.py:25-45] `router_modules` 中 `workers_router` 被重复注册了一次，重复 include 一般不会立即报错，但会增加维护复杂度并可能导致重复路由检查开销 → 建议：去重路由列表，保持注册集合单一来源。
