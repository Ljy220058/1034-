# 任务变更影响范围审查清单

## 适用范围

本清单用于 1034 跑团管理系统的看板任务完成后复核变更影响范围。审查者应先看 `git diff --name-only` 与 `git diff`，再按变更触达的模块勾选检查项。重点覆盖活动、成员、公告、签到、工作区任务、认证授权、前端渲染、测试与文档契约。

## 依据与高风险影响范围

已参考现有审查报告、权限风险审计清单、`backend/app.py`、`backend/routes/` 路由和 `tests/` 结构，归纳出以下高风险范围：

1. 认证与授权：`backend/routes/common.py`、`auth.py`、`members.py`、`workspaces.py`、`checkins.py` 中的 Bearer token、角色校验、首用户引导、管理员或领队边界。
2. 活动与报名：`backend/routes/activities.py`、`backend/repository.py` 中的活动创建、更新、删除、报名、取消报名、人数上限和活动状态过滤。
3. 成员数据：成员注册、创建、更新、删除会影响权限、手机号唯一性、密码字段、个人资料和后续活动报名归属。
4. 公告：公告读取、发布、更新、删除会影响草稿泄露、存储型跨站脚本、旧字段兼容和前端展示。
5. 签到：`backend/routes/checkins.py`、`backend/attendance.py` 中的活动归属、成员归属、补签时间、定位标记和重复签到逻辑。
6. 工作区任务与 worker 看板：`backend/routes/workspaces.py`、`backend/routes/tasks.py`、`backend/repository.py` 中的 `workspace_path`、任务批量写入、状态筛选、worker 信息泄露和路径越权。
7. 错误处理：`backend/app.py` 的 `RequestValidationError`、`HTTPException`、通用异常处理会影响所有接口的前端错误解析与测试断言。
8. SQL 与数据库一致性：`backend/repository.py`、`backend/db.py`、`backend/database.py` 中的参数化查询、事务边界、唯一约束和并发回读。
9. 前端渲染与接口契约：`frontend/api.js`、`frontend/app.js`、`frontend/index.html` 中的响应结构、文本转义、鉴权头和错误提示。
10. 测试覆盖：`tests/test_api.py`、`tests/test_auth.py`、`tests/test_checkin.py`、`tests/test_workspaces.py`、`tests/test_task_*` 等测试是否覆盖新增或改动路径。

## 审查清单

| 序号 | 检查对象 | 风险说明 | 验证方法 | 通过标准 |
|---|---|---|---|---|
| 1 | 公开 API 端点的认证依赖 | 新增或改动路由如果缺少 `Depends(get_current_user)`、`admin_or_leader` 或等价校验，普通用户或匿名用户可能访问成员、签到、任务、公告管理数据。 | 对每个新增或改动的 `@router.get/post/patch/delete` 检查函数签名和首段逻辑；用 member token 和无 token 分别请求高权限接口。 | 匿名请求返回 401；普通成员访问管理接口返回 403；仅 admin/leader 可执行管理动作。 |
| 2 | 角色升级与成员写入 | `role`、`phone`、`password_hash`、成员 ID 归属处理不当会导致越权、账号接管或脏数据。 | 审查 `UserRegister`、`MemberCreate`、`MemberUpdate`、`sanitize_member_payload` 和成员路由；测试普通成员提交 `role=admin`、修改他人资料、重复手机号。 | 角色升级被拒绝或被明确限制；重复手机号返回 409 或 422；成员只能改自己允许字段。 |
| 3 | Token 签发与解析 | token 未签名、密钥缺失回退、只信任 token 中 role，会导致伪造管理员身份。 | 检查 `token_for_member`、`parse_token`、`_jwt_secret`；构造篡改 role、过期时间、签名的 token 访问 `/api/v1/members`。 | 篡改、过期、缺少密钥均失败；role 以数据库实时成员为准；错误响应不泄露密钥或内部栈。 |
| 4 | 活动创建、更新与删除 | 活动时间、名额、状态、删除会影响报名、签到和摘要面板；缺少验证会造成过期活动报名或名额异常。 | 审查 `ActivityCreate`、`ActivityUpdate`、`create_activity_endpoint`、`patch_activity`、`remove_activity`；测试负距离、零名额、缺失地点、删除已有报名活动。 | 非法字段返回 422；有业务约束的活动删除或修改不会破坏报名和签到一致性；活动详情 404 正确。 |
| 5 | 报名与候补逻辑 | 报名成员归属、名额上限、重复报名和取消报名错误会影响活动参与人数与后续签到。 | 审查 `create_registration_endpoint`、`cancel_registration_endpoint`、仓储层唯一约束；用 member 替他人报名、重复报名、满员报名、取消不存在报名。 | 普通成员只能操作自己；满员返回 409；重复报名不产生重复行；取消不存在报名返回 404。 |
| 6 | 签到真实性与活动归属 | 普通成员可自报 `checked_in_at` 或 `gps_checked`，以及 `attendance_id` 未校验活动归属，会造成补签伪造或跨活动读取删除。 | 审查 `backend/routes/checkins.py` 和 `backend/attendance.py`；测试普通成员提交未来时间、替他人签到、用活动 A 路径访问活动 B 的签到 ID。 | 成员归属被强制校验；跨活动签到 ID 返回 404；补签时间和定位标记有明确权限或可信来源限制。 |
| 7 | 公告状态与正文渲染 | 普通成员读取 draft、正文未转义或旧字段冲突会导致草稿泄露、存储型跨站脚本或公告内容被静默覆盖。 | 审查 `announcements.py`、`AnnouncementCreate/Update`、前端公告渲染；提交 `<img onerror=alert(1)>`、同时提交 `content/body`、普通成员查询 `status=draft`。 | 普通成员不可读草稿；正文在前端按文本渲染或后端限制标记；冲突字段返回 400/422 而非静默覆盖。 |
| 8 | 工作区路径与任务读取 | `workspace_path` 允许任意绝对路径或符号链接会泄露其他工作区任务、worker 状态和内部调度数据。 | 审查 `_resolve_workspace_selector`、`_normalize_workspace_path`、所有读取 `workspace_path` 的接口；尝试 `/`、`/root`、URL 编码路径、符号链接路径。 | 路径必须落在配置白名单根；未授权路径返回 403；响应不回显未授权绝对路径；所有工作区接口至少要求 admin/leader。 |
| 9 | 工作区任务批量写入 | 批量接口如果只验证部分字段或不规范化 `workspace_path`，会写入非法状态、越权工作区或产生不一致任务项。 | 审查 `batch_create_task_items`、`TaskItemCreate`、`upsert_workspace_task_item`；提交空列表、英文标题、非法状态、跨根目录 `workspace_path`。 | 非法 item 返回 422 且指出索引；写入前复用统一路径校验；状态集合与数据库约束一致。 |
| 10 | SQL 查询与事务边界 | 字符串拼接 SQL、动态排序字段、写后再查未放入事务，会造成注入、数据竞争或读到旧状态。 | 搜索 `execute(`、`SELECT`、`INSERT`、`UPDATE`、`DELETE`；检查每个变量是否使用参数绑定；检查 `ON CONFLICT` 后回读是否在同一事务。 | 所有用户输入均通过 `?` 参数绑定；动态列名来自白名单；写入和回读在同一连接或事务内完成。 |
| 11 | 全局错误响应契约 | `backend/app.py` 统一异常处理改动会影响所有接口与前端错误提示；过度吞异常会隐藏真实 500。 | 审查 `validation_exception_handler`、`http_exception_handler`、`unhandled_exception_handler`；触发 Pydantic 多字段错误、业务 403、未捕获异常。 | 422 保留足够字段路径；业务错误结构稳定；500 不泄露栈和 SQL，但日志侧可定位。 |
| 12 | 前端接口鉴权与错误处理 | 前端漏带 Authorization、错误结构分支处理不一致，会让功能在真实登录态失败或吞掉后端错误。 | 审查 `frontend/api.js` 和调用处；模拟 401、403、422、409、500；检查是否展示后端中文 detail。 | 所有需登录接口带 token；不同错误码有可读提示；不把未转义后端文本写入 `innerHTML`。 |
| 13 | 前端文本渲染和跨站脚本 | 活动标题、公告正文、任务描述、成员名来自用户输入，直接作为 HTML 渲染会产生存储型或反射型跨站脚本。 | 搜索 `innerHTML`、模板字符串拼接 DOM、`insertAdjacentHTML`；用包含 HTML 的标题、公告、任务描述做端到端渲染。 | 用户输入使用 `textContent` 或安全模板；确需 HTML 时先白名单清洗；测试覆盖恶意字符串不执行脚本。 |
| 14 | 测试与变更范围匹配 | 只改实现不改测试会遗漏权限、验证和错误契约回归，尤其是 routes 与 repository 的组合行为。 | 对照 `git diff --name-only`：后端路由改动对应 `tests/test_api.py`、`test_auth.py`、`test_checkin.py`、`test_workspaces.py`；前端改动对应前端测试或冒烟清单。 | 每个新增端点至少有成功、未认证、未授权、非法输入、缺失资源测试；文档类任务说明无需新增业务测试。 |
| 15 | 文档与 API 契约同步 | 文档更新如果未同步真实路由、字段、状态码，会误导前端或审查者，造成错误调用。 | 比对 `docs/api.md`、`docs/user-guide.md` 与真实 `backend/routes/`、模型字段、测试断言。 | 文档中的路径、方法、请求字段、响应字段、状态码与代码一致；废弃接口标注清楚。 |

## 快速执行顺序

1. 运行 `git diff --name-only`，按前端、后端、文档分类。
2. 如果有后端路由或模型改动，优先检查认证授权、输入验证、SQL、错误响应。
3. 如果触达活动、成员、公告、签到、工作区任务任一模块，至少执行对应模块的越权和非法输入用例。
4. 如果触达前端展示，至少检查一次恶意文本不会作为 HTML 执行。
5. 如果只改文档，按文档模板核对真实代码路径和字段，不要求业务测试。
6. 最终审查报告必须写明文件路径、行号、风险、验证方法和可执行修复建议。
